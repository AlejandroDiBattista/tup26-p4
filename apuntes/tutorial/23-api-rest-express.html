express.static

Ruta absoluta con import.meta.dirname: 'public' solo buscaría donde ejecutás node.

Lo que agrega express.static

  • cientos de tipos de archivo
  • envía de a trozos: no carga un video entero en memoria
  • ETag y Last-Modified: el navegador pregunta si cambió
  • maxAge: durante ese tiempo, ni pregunta
  • pedidos parciales, para adelantar un video
  • no sirve archivos ocultos

El caché del navegador

304: no cambió, el servidor no la envía de nuevo.

El lugar en la cadena

  • antes de registrarPedidos: las imágenes no llenan el registro
  • antes de las rutas: si el archivo no existe, pasa enseguida
  • antes de exigir una sesión: la página de inicio de sesión se puede pedir

Un frontend de una sola página

Si recargan en /contactos/7, no hay archivo: llega index.html y el JavaScript de la página resuelve la ruta.

Una imagen no pide HTML: sigue siendo 404. La API pasa a /api para no pisarse.

En producción

  • los archivos estáticos los suele servir nginx o una CDN, y Express queda para la API
  • las imágenes que suben los usuarios son otro tema: recibirlas con multer, validarlas y decidir dónde guardarlas
  • en Express 5, app.get('*') ya no funciona: el comodín es '/{*ruta}'

Otro puerto es otro origen

Páginalocalhost:5173

Origen = protocolo + dominio + puerto. Una página no lee respuestas de otro origen si la API no lo permite.

curl y Node no aplican esta regla. Por eso funciona en la terminal y falla en el navegador.

La sesión viaja en una cookie

El servidor verifica la contraseña una vez y pide guardar un identificador. Después, el navegador lo envía solo.

Las opciones de la cookie

HttpOnlyJavaScript no puede leerla: un script inyectado no roba la sesión
SameSite=Laxotros sitios no la usan en pedidos de segundo plano
Securesolo viaja por HTTPS; la activamos en producción
Max-Agecuántos segundos dura

Por qué cookies y no JWT

  • un JWT se guarda donde JavaScript lo lea: un script inyectado también lo lee
  • vale hasta que vence: cerrar sesión antes requiere guardar una lista en el servidor
  • con una sesión guardada y una cookie HttpOnly, cerrar sesión es borrar una fila

Cookies desde otro origen

Con credenciales, el origen tiene que ser exacto. El puerto no cuenta para SameSite: la cookie viaja.

Lo que falta para producción

  • HTTPS siempre; con NODE_ENV=production la cookie es Secure
  • un límite de intentos de inicio de sesión
  • guardar un hash del identificador de sesión
  • una base de datos: los accesos simultáneos al archivo se pisan
