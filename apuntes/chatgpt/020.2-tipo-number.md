# El tipo `number` en JavaScript

En JavaScript, `number` es el tipo numérico principal. Una
particularidad importante es que **no hay tipos separados como `int`,
`float` o `double`** al nivel del lenguaje: tanto los enteros como los
números con decimales son valores de tipo `number`.

``` js
let edad = 25;
let temperatura = 36.5;
let negativo = -10;

console.log(typeof edad);         // "number"
console.log(typeof temperatura);  // "number"
```

Internamente, los valores `number` se representan normalmente mediante
el formato de punto flotante **IEEE 754 de 64 bits**.

Esto explica algunas particularidades famosas:

``` js
0.1 + 0.2
// 0.30000000000000004
```

No es un problema específico de JavaScript: es consecuencia de
representar en binario números reales con una cantidad finita de bits.

------------------------------------------------------------------------

## 1. Literales numéricos

Un **literal** es una forma de escribir directamente un valor dentro del
código.

### Decimal

``` js
let a = 123;
let b = 3.1416;
let c = -45;
```

También existe notación científica:

``` js
let a = 1e3;     // 1000
let b = 2.5e2;   // 250
let c = 3e-3;    // 0.003
```

### Binario

Se utiliza el prefijo `0b`:

``` js
let n = 0b1010;
console.log(n); // 10
```

### Octal

Se utiliza `0o`:

``` js
let n = 0o17;
console.log(n); // 15
```

### Hexadecimal

Se utiliza `0x`:

``` js
let n = 0xFF;
console.log(n); // 255
```

Por ejemplo:

``` js
let a = 42;
let b = 0b101010;
let c = 0o52;
let d = 0x2A;

console.log(a, b, c, d);
// 42 42 42 42
```

Los cuatro contienen **el mismo valor**. Lo único que cambia es cómo se
escribió ese valor en el programa.

------------------------------------------------------------------------

## 2. Conversión a `number`

JavaScript tiene **tipado dinámico**: una variable no queda asociada
permanentemente con un tipo.

``` js
let x = 10;

x = "hola";
x = true;
```

Además, JavaScript realiza muchas **conversiones implícitas**, también
llamadas coerciones.

### Conversión implícita

``` js
"10" * 2
// 20
```

JavaScript necesita realizar una multiplicación y convierte `"10"` a
número.

``` js
"10" - 2   // 8
"10" / 2   // 5
"10" * 2   // 20
```

Pero `+` tiene una particularidad: también sirve para concatenar
strings.

``` js
"10" + 2
// "102"
```

Por eso:

``` js
10 + 20       // 30
"10" + 20     // "1020"

10 * 2        // 20
"10" * 2      // 20
```

Esta coerción automática es una de las características que hacen que
JavaScript sea considerado un lenguaje de **tipado débil**.

------------------------------------------------------------------------

## 3. Conversión explícita

La forma general para convertir algo a número es:

``` js
Number(valor)
```

Por ejemplo:

``` js
Number("123")       // 123
Number("3.14")      // 3.14
Number(true)        // 1
Number(false)       // 0
Number("")          // 0
```

Si la conversión no tiene sentido:

``` js
Number("hola")
// NaN
```

`NaN` significa **Not a Number**, aunque:

``` js
typeof NaN
// "number"
```

Para verificarlo conviene:

``` js
Number.isNaN(x)
```

### `parseInt()` y `parseFloat()`

``` js
parseInt("123")       // 123
parseFloat("12.34")   // 12.34
```

`parseInt()` puede recibir una base:

``` js
parseInt("1010", 2)   // 10
parseInt("FF", 16)    // 255
parseInt("100", 8)    // 64
```

Hay una diferencia conceptual importante:

``` js
Number("123px")     // NaN
parseInt("123px")   // 123
```

`Number()` intenta convertir **todo el valor**.

`parseInt()` intenta leer una parte inicial que pueda interpretar como
entero.

------------------------------------------------------------------------

## 4. Operadores aritméticos

  Operador   Operación        Ejemplo
  ---------- ---------------- -----------------------
  `+`        suma             `10 + 3` → `13`
  `-`        resta            `10 - 3` → `7`
  `*`        multiplicación   `10 * 3` → `30`
  `/`        división         `10 / 3` → `3.333...`
  `%`        resto            `10 % 3` → `1`
  `**`       potencia         `10 ** 3` → `1000`

El operador `%` es especialmente útil para divisibilidad:

``` js
n % 2 === 0
```

indica que `n` es par.

También tenemos incremento y decremento:

``` js
x++;
x--;

++x;
--x;
```

La diferencia entre prefijo y sufijo aparece cuando utilizamos el
resultado:

``` js
let x = 10;
let a = x++;   // a = 10, después x = 11
```

frente a:

``` js
let x = 10;
let a = ++x;   // primero x = 11, después a = 11
```

------------------------------------------------------------------------

## 5. Precedencia

Los operadores no se evalúan simplemente de izquierda a derecha.

``` js
2 + 3 * 4
// 14
```

porque `*` tiene mayor precedencia que `+`.

Una simplificación útil del orden es:

``` text
()
**
* / %
+ -
comparaciones
igualdades
operadores lógicos
```

Ejemplos:

``` js
2 + 3 * 4        // 14
(2 + 3) * 4      // 20
10 % 4 + 2       // 4
2 ** 3 * 4       // 32
```

Cuando una expresión comienza a ser difícil de leer, es preferible usar
paréntesis aunque no sean estrictamente necesarios.

------------------------------------------------------------------------

## 6. Operadores de comparación

Las comparaciones producen valores booleanos:

``` js
10 > 5
// true
```

  Operador   Significado
  ---------- --------------------------
  `<`        menor
  `>`        mayor
  `<=`       menor o igual
  `>=`       mayor o igual
  `===`      igualdad estricta
  `!==`      desigualdad estricta
  `==`       igualdad con coerción
  `!=`       desigualdad con coerción

JavaScript distingue entre igualdad estricta y no estricta:

``` js
10 == "10"    // true
10 === "10"   // false
```

Con `==`, JavaScript intenta convertir tipos antes de comparar.

Con `===`, compara valor **y tipo**.

Por eso, en código moderno generalmente se prefiere `===` y `!==`.

------------------------------------------------------------------------

## 7. Operaciones bit a bit --- bitwise

Los operadores **bitwise** permiten trabajar con los bits individuales
de un entero.

  Operador   Operación
  ---------- ------------------------------------------
  `&`        AND bit a bit
  `|`        OR bit a bit
  `^`        XOR bit a bit
  `~`        NOT bit a bit
  `<<`       desplazamiento izquierda
  `>>`       desplazamiento derecha conservando signo
  `>>>`      desplazamiento derecha sin signo

Por ejemplo:

``` js
let a = 0b1100;
let b = 0b1010;

a & b
```

Bit por bit:

``` text
  1100
& 1010
------
  1000
```

Resultado: `8`.

### OR bit a bit

``` text
  1100
| 1010
------
  1110
```

``` js
0b1100 | 0b1010
// 14
```

### XOR bit a bit

``` text
  1100
^ 1010
------
  0110
```

``` js
0b1100 ^ 0b1010
// 6
```

------------------------------------------------------------------------

## 8. ¿Qué pasa con los `number` al usar bitwise?

Aunque normalmente `number` trabaja con números IEEE 754 de 64 bits,
**la mayoría de las operaciones bitwise convierten sus operandos a
enteros de 32 bits** antes de realizar la operación.

``` js
5.8 | 0
// 5
```

Conceptualmente:

``` text
5.8
 ↓
entero de 32 bits
 ↓
00000000 00000000 00000000 00000101
```

De ahí viene el viejo truco:

``` js
x | 0
```

para forzar un valor al dominio de enteros de 32 bits:

``` js
12.9 | 0    // 12
-12.9 | 0   // -12
```

Pero **no debe confundirse con `Math.floor()`**:

``` js
Math.floor(-12.9)   // -13
-12.9 | 0           // -12
```

Además, la conversión bitwise está limitada al rango de 32 bits.

Para truncar explícitamente es más claro:

``` js
Math.trunc(12.9)   // 12
```

------------------------------------------------------------------------

## 9. Desplazamientos

`<<` mueve los bits hacia la izquierda.

``` js
let x = 0b00000101;
x << 1
```

produce:

``` text
00000101     5
     ↓
00001010    10
```

Para valores donde no hay overflow:

``` js
5 << 1    // 10
5 << 2    // 20
```

Desplazar `n` posiciones hacia la izquierda equivale conceptualmente a
multiplicar por `2^n`, dentro de las limitaciones de 32 bits.

### Desplazamiento hacia la derecha

``` js
20 >> 1   // 10
20 >> 2   // 5
```

Conceptualmente:

``` text
10100     20
01010     10
00101      5
```

`>>` conserva el signo.

`>>>` realiza desplazamiento hacia la derecha rellenando con ceros.

------------------------------------------------------------------------

## 10. Bits como conjunto de opciones

Una aplicación clásica consiste en representar **varias opciones
simultáneas dentro de un único número**.

Supongamos permisos de usuario:

``` js
const LEER     = 1 << 0;  // 0001
const ESCRIBIR = 1 << 1;  // 0010
const BORRAR   = 1 << 2;  // 0100
const ADMIN    = 1 << 3;  // 1000
```

Cada bit representa una opción independiente.

``` text
LEER       0001
ESCRIBIR   0010
BORRAR     0100
ADMIN      1000
```

### Activar opciones: OR

``` js
let permisos = LEER | ESCRIBIR;
```

``` text
  0001    LEER
| 0010    ESCRIBIR
------
  0011
```

Podemos agregar otra opción:

``` js
permisos |= BORRAR;
```

Ahora `permisos` vale `0111`: tiene tres opciones simultáneamente.

### Consultar una opción: AND

``` js
if ((permisos & ESCRIBIR) !== 0) {
    console.log("Puede escribir");
}
```

AND funciona como una máscara que deja pasar únicamente el bit que
queremos consultar.

### Apagar una opción

Para apagar un bit usamos AND con la máscara negada:

``` js
permisos &= ~BORRAR;
```

Por ejemplo:

``` text
  0111
& 1011
------
  0011
```

Quedan activos `LEER` y `ESCRIBIR`.

### Alternar una opción con XOR

``` js
permisos ^= ADMIN;
```

Si `ADMIN` estaba apagado, se enciende. Si estaba encendido, se apaga.

------------------------------------------------------------------------

## 11. El patrón completo

``` js
const LEER     = 1 << 0;
const ESCRIBIR = 1 << 1;
const BORRAR   = 1 << 2;
const ADMIN    = 1 << 3;

let permisos = 0;

// prender
permisos |= LEER;
permisos |= ESCRIBIR;

// preguntar
if ((permisos & LEER) !== 0) {
    console.log("Puede leer");
}

// apagar
permisos &= ~ESCRIBIR;

// alternar
permisos ^= ADMIN;
```

Un solo entero puede representar muchas opciones simultáneas:

``` text
0000   ninguna
0001   LEER
0011   LEER + ESCRIBIR
0101   LEER + BORRAR
1011   LEER + ESCRIBIR + ADMIN
1111   todas
```

Una forma práctica de recordar los operadores es:

``` text
|       prender bits
&       consultar/filtrar bits
& ~     apagar bits
^       alternar bits
<<      colocar un bit en una posición
>>      desplazar bits
```

La idea fundamental es que dejamos de pensar el número solamente como
una cantidad y empezamos a utilizar **cada uno de sus bits como
información independiente**.
