# Programación IV — El tipo booleano en JavaScript

Los booleanos son uno de los tipos de datos primitivos de JavaScript. Representan una idea extremadamente simple: una condición puede ser verdadera o falsa.

```js
true;
false;
```

Aunque sólo existen esos dos valores booleanos, JavaScript permite utilizar prácticamente cualquier valor como si fuera una condición. Para comprender correctamente este comportamiento hay que distinguir entre:

- valores booleanos;
- valores *truthy* y *falsy*;
- conversión explícita e implícita a booleano;
- operadores lógicos `!`, `&&` y `||`;
- evaluación por cortocircuito.

---

## 1. El tipo `boolean`

JavaScript tiene dos valores booleanos: `true` y `false`. Podemos almacenarlos directamente en variables:

```js
let activo = true;
let terminado = false;

console.log(typeof activo);
// "boolean"
```

También suelen aparecer como resultado de comparaciones:

```js
let edad = 20;
let mayor = edad >= 18;

console.log(mayor);
// true
```

Las expresiones relacionales y de igualdad producen valores booleanos:

```js
10 > 5;      // true
10 < 5;      // false
10 === 10;   // true
10 !== 10;   // false
```

Por eso los booleanos son fundamentales para controlar el flujo de ejecución:

```js
if (edad >= 18) {
  console.log("Es mayor de edad");
}
```

---

## 2. Una condición no necesita ser un booleano

En muchos lenguajes, la condición de un `if` debe ser estrictamente un valor booleano. JavaScript es más flexible.

```js
let nombre = "Ana";

if (nombre) {
  console.log("Hay un nombre");
}
```

`nombre` no contiene un booleano, sino un `string`. Sin embargo, JavaScript permite utilizarlo como condición porque, cuando necesita decidir entre verdadero y falso, convierte implícitamente el valor a booleano.

Conceptualmente podemos imaginar que ocurre algo parecido a esto:

```js
if (Boolean(nombre)) {
  console.log("Hay un nombre");
}
```

La conversión de una cadena no vacía produce `true`:

```js
Boolean("Ana");
// true
```

Por lo tanto, el cuerpo del `if` se ejecuta. Esta conversión automática es una manifestación del sistema de tipos dinámico y de las coerciones implícitas de JavaScript.

---

## 3. Valores *truthy* y *falsy*

Cuando JavaScript convierte un valor a booleano, el resultado sólo puede ser `true` o `false`.

- Los valores que se convierten en `false` se denominan ***falsy***.
- Los valores que se convierten en `true` se denominan ***truthy***.

Es importante notar que un valor *truthy* no necesariamente es el booleano `true`:

```js
"Hola" === true;
// false

Boolean("Hola");
// true
```

Por eso decimos que `"Hola"` es *truthy*, no que sea el booleano `true`.

---

## 4. Valores *falsy*

JavaScript tiene un conjunto pequeño de valores que se consideran falsos al convertirse a booleano:

```js
false;
0;
-0;
0n;
"";
null;
undefined;
NaN;
```

Podemos comprobarlo con la función `Boolean`:

```js
Boolean(false);       // false
Boolean(0);           // false
Boolean("");          // false
Boolean(null);        // false
Boolean(undefined);   // false
Boolean(NaN);         // false
```

Esto permite escribir:

```js
let nombre = "";

if (nombre) {
  console.log("Hay un nombre");
}
```

Como la cadena vacía `""` es *falsy*, el cuerpo del `if` no se ejecutará.

---

## 5. Valores *truthy*

Prácticamente todo lo que no es *falsy* es *truthy*:

```js
Boolean(1);         // true
Boolean(-1);        // true
Boolean(3.14);      // true
Boolean("Hola");    // true
Boolean("false");   // true
Boolean([]);        // true
Boolean({});        // true
```

Hay algunos casos que inicialmente pueden resultar sorprendentes. Una cadena que contiene `"false"` es *truthy*:

```js
Boolean("false");
// true
```

No importa lo que diga el texto: lo importante es que se trata de una cadena no vacía. Por el mismo motivo, `"0"` también es *truthy*:

```js
Boolean("0");
// true
```

Los arrays y los objetos también son *truthy*, incluso cuando están vacíos:

```js
Boolean([]);   // true
Boolean({});   // true
```

---

## 6. Conversión explícita a booleano

Podemos pedir explícitamente la conversión mediante la función `Boolean`:

```js
Boolean(valor);
```

Por ejemplo:

```js
Boolean(10);          // true
Boolean(0);           // false
Boolean("Hola");      // true
Boolean("");          // false
Boolean(null);        // false
Boolean(undefined);   // false
```

Esto resulta especialmente útil para experimentar y comprender las reglas de conversión de JavaScript.

---

## 7. Conversión mediante `!!`

Existe otra forma muy habitual de convertir un valor a booleano:

```js
!!valor;
```

Para entenderla conviene recordar que `!` es el operador de negación lógica:

```js
!true;    // false
!false;   // true
```

El operador `!` convierte primero su operando a booleano y luego niega el resultado. Por ejemplo:

```js
!"Hola";
```

Conceptualmente ocurre lo siguiente:

```js
!Boolean("Hola");
```

Como `"Hola"` es *truthy*, se convierte en `true` y luego se niega:

```js
!true;
// false
```

Si volvemos a negar el resultado, obtenemos el valor booleano original:

```js
!!"Hola";
// true
```

Por eso, `!!valor` es una forma abreviada de escribir `Boolean(valor)`:

```js
!!"Hola";   // true
!!"";       // false
!!42;       // true
!!0;        // false
!!null;     // false
```

---

## 8. Conversión implícita

Muchas conversiones ocurren automáticamente en JavaScript:

```js
let cantidad = 10;

if (cantidad) {
  console.log("Hay elementos");
}
```

`cantidad` contiene un número, no un booleano. Sin embargo, el `if` necesita tomar una decisión lógica y JavaScript realiza implícitamente esta conversión:

```js
Boolean(cantidad);
```

Como `Boolean(10)` es `true`, la condición se considera verdadera.

Lo mismo ocurre en otras estructuras de control:

```js
while (valor) {
  // Repetir mientras valor sea truthy.
}
```

También sucede con los operadores lógicos `!`, `&&` y `||`.

> Esta capacidad se denomina **coerción de tipos**: JavaScript convierte automáticamente un valor de un tipo en otro cuando el contexto lo requiere.

---

## 9. El operador AND: `&&`

El operador lógico AND se escribe `&&`. Su tabla de verdad es la siguiente:

| A       | B       | A `&&` B |
| ------- | ------- | -------- |
| `false` | `false` | `false`  |
| `false` | `true`  | `false`  |
| `true`  | `false` | `false`  |
| `true`  | `true`  | `true`   |

Por ejemplo:

```js
let edad = 25;
let tieneEntrada = true;

if (edad >= 18 && tieneEntrada) {
  console.log("Puede ingresar");
}
```

Las dos condiciones deben ser verdaderas. Sin embargo, en JavaScript `&&` tiene una característica adicional muy importante: **no necesariamente devuelve `true` o `false`; puede devolver directamente uno de sus operandos**.

---

## 10. Cortocircuito en `&&`

Consideremos la expresión:

```js
A && B;
```

Para que la expresión completa sea verdadera, `A` debe ser *truthy*. Si `A` es *falsy*, ya conocemos el resultado lógico y no hace falta evaluar `B`.

```js
false && algo();
```

En este caso, `algo()` ni siquiera se ejecuta. A este comportamiento se lo denomina **evaluación por cortocircuito**.

Podemos comprobarlo con una función:

```js
function prueba() {
  console.log("Se ejecutó");
  return true;
}

false && prueba();
```

No se imprime nada. JavaScript encontró un valor *falsy* y ya sabe que un AND no puede resultar verdadero.

---

## 11. `&&` devuelve el primer valor *falsy*

En JavaScript, `&&` devuelve el primer valor *falsy* que encuentra:

```js
10 && 20;
// 20
```

`10` es *truthy*, por lo que todavía no se puede determinar el resultado. Entonces se evalúa `20`. Como no quedan más operandos, `20` es el resultado.

Veamos una expresión más larga:

```js
10 && 0 && 30;
// 0
```

La evaluación ocurre de izquierda a derecha:

1. `10` es *truthy*: continuar.
2. `0` es *falsy*: detenerse.
3. `30` nunca se evalúa.

Otro ejemplo:

```js
"Juan" && 25 && "Hola";
// "Hola"
```

Todos los operandos son *truthy*, por lo que la evaluación llega hasta el último.

> `A && B && C && D` busca el primer valor *falsy*. Si no encuentra ninguno, devuelve el último operando.

---

## 12. El operador OR: `||`

El operador lógico OR se escribe `||`. Su tabla de verdad es la siguiente:

| A       | B       | A `\|\|` B |
| ------- | ------- | ----------- |
| `false` | `false` | `false`     |
| `false` | `true`  | `true`      |
| `true`  | `false` | `true`      |
| `true`  | `true`  | `true`      |

Nuevamente, JavaScript no necesariamente devuelve un booleano: puede devolver uno de los operandos.

---

## 13. Cortocircuito en `||`

Consideremos esta expresión:

```js
A || B;
```

Para que un OR sea verdadero alcanza con que `A` sea *truthy*. Por lo tanto, si `A` es *truthy*, no existe ninguna necesidad de evaluar `B`.

```js
true || algo();
```

En este caso, `algo()` no se ejecuta. Esto también es evaluación por cortocircuito.

---

## 14. `||` devuelve el primer valor *truthy*

Podemos pensar el comportamiento de `||` de esta manera:

> `||` devuelve el primer valor *truthy* que encuentra.

Por ejemplo:

```js
0 || 20;
// 20
```

`0` es *falsy*, por lo que JavaScript continúa. `20` es *truthy* y se convierte en el resultado.

Otro ejemplo:

```js
"" || null || "Juan" || "Pedro";
// "Juan"
```

La evaluación ocurre de izquierda a derecha:

1. `""` es *falsy*: continuar.
2. `null` es *falsy*: continuar.
3. `"Juan"` es *truthy*: detenerse.
4. `"Pedro"` nunca se evalúa.

Si ninguno de los primeros operandos es *truthy*, se devuelve el último:

```js
0 || "" || null;
// null
```

---

## 15. La simetría entre `&&` y `||`

Una forma sencilla de recordar ambos operadores es:

- `&&` busca algo que haga **falsa** la expresión;
- `||` busca algo que haga **verdadera** la expresión.

Por eso:

- `&&` devuelve el primer valor *falsy*;
- `||` devuelve el primer valor *truthy*.

Si no encuentran un valor que determine anticipadamente el resultado, devuelven el último operando.

```js
10 && 20 && 30;
// 30, porque ninguno fue falsy

0 || "" || 30;
// 30, porque los anteriores fueron falsy
```

---

## 16. ¿Por qué devuelven el valor y no `true` o `false`?

Esta particularidad resulta muy útil en JavaScript. Supongamos que queremos acceder a una propiedad sólo cuando existe un usuario:

```js
let nombre = usuario && usuario.nombre;
```

Si `usuario` es *falsy*, JavaScript se detiene y devuelve ese valor. Si es *truthy*, continúa y devuelve `usuario.nombre`.

Otro patrón tradicional permite elegir un valor alternativo:

```js
let nombre = nombreIngresado || "Anónimo";
```

Si el usuario ingresó un nombre:

```js
let nombreIngresado = "Ana";

"Ana" || "Anónimo";
// "Ana"
```

Si ingresó una cadena vacía:

```js
let nombreIngresado = "";

"" || "Anónimo";
// "Anónimo"
```

Los operadores lógicos pueden utilizarse no sólo para construir expresiones booleanas, sino también para seleccionar valores.

---

## 17. Un modelo mental sencillo

Cuando JavaScript encuentra `A && B`, podemos imaginar el siguiente comportamiento:

```js
if (!A) {
  return A;
} else {
  return B;
}
```

Cuando encuentra `A || B`, podemos imaginar esto:

```js
if (A) {
  return A;
} else {
  return B;
}
```

No es literalmente la implementación interna del lenguaje, pero es un excelente modelo mental:

```js
0 && 100;
// 0

0 || 100;
// 100
```

---

## 18. Lo fundamental

Un booleano sólo puede contener `true` o `false`. Sin embargo, JavaScript permite utilizar otros tipos de valores en contextos lógicos gracias a la conversión implícita a booleano.

Los valores se clasifican en:

- ***falsy***: al convertirse producen `false`;
- ***truthy***: al convertirse producen `true`.

La conversión explícita puede realizarse mediante cualquiera de estas formas:

```js
Boolean(valor);
!!valor;
```

Los operadores `&&` y `||` utilizan cortocircuito:

- `A && B` busca el primer valor *falsy*;
- `A || B` busca el primer valor *truthy*.

La idea más importante es que estos operadores no convierten necesariamente el resultado a `true` o `false`. Devuelven directamente el valor que permite determinar el resultado de la expresión.

```js
"Hola" && 42;   // 42
0 && 42;        // 0
"Hola" || 42;   // "Hola"
0 || 42;        // 42
```

Esta combinación de valores *truthy* y *falsy*, coerción implícita, cortocircuito y retorno del operando explica buena parte de la expresividad —y también algunas de las rarezas— de las expresiones lógicas en JavaScript.
