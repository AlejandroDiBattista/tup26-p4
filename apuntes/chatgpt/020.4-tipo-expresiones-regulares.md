# Expresiones regulares en JavaScript, desde primeros principios

Una **expresión regular** —*regular expression*, o **regex**— es una forma de describir **patrones de texto**.

La idea fundamental es esta:

> En lugar de preguntar «¿este texto es exactamente `"gato"`?», podemos preguntar «¿este texto tiene la forma que estoy buscando?».

Por ejemplo, queremos reconocer cualquiera de estos textos:

```text
gato
gata
gatos
gatas
```

Podríamos escribir muchas comparaciones:

```js
texto === "gato" ||
texto === "gata" ||
texto === "gatos" ||
texto === "gatas"
```

Pero también podemos describir el patrón:

```js
/gat[oa]s?/
```

Eso ya es una expresión regular.

---

## 1. Antes de las regex: buscar texto literalmente

Supongamos:

```js
const texto = "El gato duerme";
```

JavaScript ya puede buscar cadenas:

```js
texto.includes("gato");
```

Resultado:

```js
true
```

También podemos encontrar la posición:

```js
texto.indexOf("gato");
```

Resultado:

```js
3
```

Esto funciona perfectamente cuando conocemos **exactamente** lo que queremos buscar.

El problema aparece cuando queremos buscar una **forma**, no una cadena concreta.

Por ejemplo:

```text
381-555-1234
381-421-8877
351-555-9999
```

Queremos reconocer:

```text
tres dígitos
un guion
tres dígitos
un guion
cuatro dígitos
```

Ahí aparece la utilidad de las expresiones regulares.

---

## 2. Una regex es un objeto que describe un patrón

En JavaScript podemos escribir una expresión regular entre barras `/`.

```js
const patron = /gato/;
```

Podemos probarla sobre un texto:

```js
const patron = /gato/;

console.log(patron.test("Tengo un gato"));
```

Resultado:

```js
true
```

Pero:

```js
patron.test("Tengo un perro");
```

da:

```js
false
```

`test()` responde simplemente:

> ¿Existe alguna parte del texto que coincida con este patrón?

---

## 3. El caso más sencillo: caracteres literales

La regex:

```js
/gato/
```

significa:

```text
g
seguido de a
seguido de t
seguido de o
```

Por eso encuentra:

```js
/gato/.test("un gato negro");
```

pero no:

```js
/gato/.test("una gata negra");
```

Hasta aquí no hemos ganado demasiado respecto de:

```js
texto.includes("gato");
```

La potencia comienza cuando algunos caracteres dejan de significar literalmente lo que representan.

---

## 4. Los metacaracteres

En una expresión regular existen caracteres especiales llamados **metacaracteres**.

Algunos de los más importantes son:

```text
.   cualquier carácter
[]  conjunto de caracteres
^   comienzo
$   final
*   cero o más
+   uno o más
?   cero o uno
{}  cantidad
()  grupo
|   alternativa
\   escape
```

Vamos a construirlos uno por uno.

---

## 5. El punto `.`: cualquier carácter

La expresión:

```js
/g.to/
```

significa:

```text
g
cualquier carácter
t
o
```

Entonces coincide con:

```text
gato
geto
gito
goto
guto
g1to
g-to
```

Por ejemplo:

```js
/g.to/.test("gato");
```

da:

```js
true
```

y:

```js
/g.to/.test("g1to");
```

también:

```js
true
```

Pero:

```js
/g.to/.test("gto");
```

da:

```js
false
```

porque el punto representa **exactamente un carácter**.

---

## 6. Conjuntos con `[]`

Muchas veces no queremos «cualquier carácter», sino uno dentro de ciertas posibilidades.

Por ejemplo:

```js
/gat[oa]/
```

significa:

```text
gat
seguido de o o a
```

Entonces reconoce:

```text
gato
gata
```

Ejemplo:

```js
/gat[oa]/.test("gata");
```

```js
true
```

---

## 7. Rangos

Dentro de `[]` podemos especificar rangos.

Por ejemplo:

```js
/[0-9]/
```

significa:

> cualquier dígito entre 0 y 9.

Entonces:

```js
/[0-9]/.test("abc7xyz");
```

da:

```js
true
```

Podemos hacer lo mismo con letras:

```js
/[a-z]/
```

una letra minúscula.

```js
/[A-Z]/
```

una letra mayúscula.

Y podemos combinar:

```js
/[a-zA-Z0-9]/
```

que significa:

```text
una letra minúscula
o una letra mayúscula
o un número
```

---

## 8. Negar un conjunto

Dentro de `[]`, el símbolo `^` tiene un significado especial si aparece primero.

```js
/[^0-9]/
```

significa:

> cualquier carácter que **no sea un dígito**.

Por ejemplo:

```js
/[^0-9]/.test("123A456");
```

da:

```js
true
```

porque aparece `A`.

---

## 9. Clases abreviadas

Como ciertos patrones son extremadamente frecuentes, regex tiene abreviaturas.

### Dígitos

```js
\d
```

aproximadamente:

```js
[0-9]
```

Ejemplo:

```js
/\d/.test("Tengo 57 años");
```

```js
true
```

### No dígito

```js
\D
```

significa:

> cualquier carácter que no sea un dígito.

### Caracteres de palabra

```js
\w
```

tradicionalmente equivale aproximadamente a:

```text
letras inglesas
dígitos
_
```

es decir:

```text
A-Z
a-z
0-9
_
```

Ojo: para trabajar seriamente con Unicode, acentos, `ñ`, alfabetos no latinos, etc., conviene no asumir que `\w` significa «cualquier letra humana».

### No carácter de palabra

```js
\W
```

### Espacios

```js
\s
```

reconoce caracteres de espacio en blanco:

```text
espacio
tabulación
salto de línea
...
```

Por ejemplo:

```js
/\s/.test("Hola mundo");
```

da:

```js
true
```

### No espacio

```js
\S
```

---

## 10. El problema de la cantidad

Hasta ahora:

```js
/\d/
```

significa:

> un dígito.

Pero un número como:

```text
12345
```

tiene muchos dígitos.

Necesitamos poder decir:

> repita este patrón cierta cantidad de veces.

Para eso existen los **cuantificadores**.

---

## 11. `+`: una o más veces

```js
/\d+/
```

significa:

> uno o más dígitos consecutivos.

Entonces encuentra:

```text
1
42
123
987654321
```

Por ejemplo:

```js
/\d+/.test("Tengo 57 años");
```

da:

```js
true
```

Podemos extraer la coincidencia:

```js
"Tengo 57 años".match(/\d+/);
```

obtendremos una coincidencia cuyo contenido principal es:

```text
57
```

---

## 12. `*`: cero o más veces

```js
/a*/
```

significa:

> cero o más letras `a`.

Reconoce:

```text
""
"a"
"aa"
"aaa"
"aaaaaaaa"
```

La diferencia es importante:

```text
a+    una o más
a*    cero o más
```

Por eso `*` puede coincidir incluso sin consumir ningún carácter.

---

## 13. `?`: cero o una vez

```js
/a?/
```

significa:

> la `a` puede aparecer o no.

Esto permite expresar elementos opcionales.

Por ejemplo:

```js
/gatos?/
```

Hay que leerlo cuidadosamente.

El `?` afecta solamente a la `s`.

Por tanto significa:

```text
gato
seguido opcionalmente por s
```

Reconoce:

```text
gato
gatos
```

No reconoce `gata`.

Para eso podríamos escribir:

```js
/gat[oa]s?/
```

que reconoce:

```text
gato
gata
gatos
gatas
```

---

## 14. `{n}`: exactamente cierta cantidad

Podemos indicar una cantidad precisa.

```js
/\d{3}/
```

significa:

> exactamente tres dígitos consecutivos.

Reconoce:

```text
123
381
999
```

Entonces podemos empezar a describir nuestro teléfono:

```js
/\d{3}-\d{3}-\d{4}/
```

Esto significa:

```text
3 dígitos
-
3 dígitos
-
4 dígitos
```

Ejemplo:

```js
const telefono = /\d{3}-\d{3}-\d{4}/;

telefono.test("381-555-1234");
```

Resultado:

```js
true
```

---

## 15. `{mínimo,máximo}`

También podemos escribir:

```js
/\d{2,4}/
```

significa:

> entre 2 y 4 dígitos.

Por ejemplo:

```text
12
123
1234
```

También:

```js
/\d{2,}/
```

significa:

> al menos dos dígitos.

---

## 16. Hasta ahora buscamos «dentro» del texto

Consideremos:

```js
/\d{3}/.test("abc123xyz");
```

Da:

```js
true
```

Pero observá esto:

```js
/\d{3}/.test("123456");
```

También da:

```js
true
```

aunque quizás queríamos comprobar que **todo el texto** tuviera exactamente tres dígitos.

Para eso necesitamos los **anclajes**.

---

## 17. `^`: comienzo del texto

```js
/^Hola/
```

significa:

> `Hola` debe aparecer al comienzo.

Entonces:

```js
/^Hola/.test("Hola mundo");
```

da:

```js
true
```

pero:

```js
/^Hola/.test("Te digo Hola");
```

da:

```js
false
```

---

## 18. `$`: final del texto

```js
/mundo$/
```

significa:

> `mundo` debe estar al final.

```js
/mundo$/.test("Hola mundo");
```

```js
true
```

pero:

```js
/mundo$/.test("mundo cruel");
```

```js
false
```

---

## 19. Validar un texto completo

Combinando ambos:

```js
/^\d{3}$/
```

significa:

```text
comienzo
exactamente tres dígitos
final
```

Por tanto:

```js
/^\d{3}$/.test("123");
```

da:

```js
true
```

pero:

```js
/^\d{3}$/.test("1234");
```

da:

```js
false
```

Y:

```js
/^\d{3}$/.test("abc123");
```

también:

```js
false
```

Esta diferencia es fundamental:

```js
/\d{3}/
```

busca tres dígitos **en alguna parte**.

Mientras que:

```js
/^\d{3}$/
```

exige que **todo el texto** consista exactamente en tres dígitos.

---

## 20. Agrupar con `()`

Supongamos que queremos reconocer:

```text
ja
jaja
jajaja
jajajaja
```

Podemos agrupar:

```js
/(ja)+/
```

El cuantificador `+` ahora afecta al grupo completo:

```text
(ja)
```

no solamente a la `a`.

Así:

```js
/^(ja)+$/.test("jajaja");
```

da:

```js
true
```

---

## 21. Alternativas con `|`

El símbolo:

```text
|
```

significa **o**.

Por ejemplo:

```js
/gato|perro/
```

significa:

```text
gato
o
perro
```

Entonces:

```js
/gato|perro/.test("Tengo un perro");
```

da:

```js
true
```

Con grupos se vuelve mucho más útil:

```js
/(gato|perro)s?/
```

reconoce:

```text
gato
gatos
perro
perros
```

---

## 22. Escapar caracteres especiales

El punto:

```text
.
```

significa «cualquier carácter».

Si realmente queremos buscar un punto debemos **escaparlo**:

```js
/\./
```

Por ejemplo:

```js
/\./.test("Hola.");
```

da:

```js
true
```

El `\` dice:

> interpretá el siguiente carácter literalmente.

Para buscar:

```text
3.14
```

podemos usar:

```js
/3\.14/
```

Sin el escape:

```js
/3.14/
```

también coincidiría con:

```text
3X14
3-14
3a14
```

porque `.` significa cualquier carácter.

---

## 23. Las expresiones regulares en JavaScript son objetos

Cuando escribimos:

```js
const patron = /\d+/;
```

estamos creando un objeto de tipo:

```js
RegExp
```

Podemos verificarlo:

```js
console.log(typeof patron);
```

Resultado:

```text
object
```

y:

```js
patron instanceof RegExp;
```

da:

```js
true
```

También podemos crearlo explícitamente:

```js
const patron = new RegExp("\\d+");
```

Esto equivale aproximadamente a:

```js
const patron = /\d+/;
```

Pero aparece una molestia: dentro de un string de JavaScript también debemos escapar `\`.

Por eso:

```js
/\d+/
```

se convierte en:

```js
new RegExp("\\d+")
```

Cuando el patrón es conocido de antemano, normalmente es más cómodo usar:

```js
/.../
```

`new RegExp()` es especialmente útil cuando construimos el patrón dinámicamente.

Por ejemplo:

```js
const palabra = "gato";

const regex = new RegExp(palabra);
```

---

## 24. Flags: modificar cómo trabaja la regex

Después de la `/` final podemos colocar opciones llamadas **flags**.

Por ejemplo:

```js
/gato/i
```

La `i` significa:

> ignorar diferencias entre mayúsculas y minúsculas.

Entonces:

```js
/gato/i.test("GATO");
```

da:

```js
true
```

También reconoce:

```text
Gato
gato
GaTo
```

---

## 25. El flag `g`: búsqueda global

Normalmente una regex encuentra la primera coincidencia.

Por ejemplo:

```js
"1 gato, 2 perros y 3 peces".match(/\d/);
```

encuentra inicialmente:

```text
1
```

Pero con:

```js
/\d/g
```

pedimos todas las coincidencias:

```js
"1 gato, 2 perros y 3 peces".match(/\d/g);
```

Resultado:

```js
["1", "2", "3"]
```

`g` significa **global**.

---

## 26. Métodos principales

En JavaScript, las regex aparecen principalmente mediante métodos de `RegExp` y de `String`.

Los más importantes son:

```text
test()
match()
matchAll()
search()
replace()
split()
```

---

## 27. `test()`: ¿existe una coincidencia?

```js
const texto = "Tengo 42 años";

console.log(/\d+/.test(texto));
```

Resultado:

```js
true
```

Es ideal para validaciones sencillas.

---

## 28. `match()`: encontrar coincidencias

```js
const texto = "Tengo 42 años";

const resultado = texto.match(/\d+/);

console.log(resultado);
```

La parte principal encontrada será:

```text
42
```

Con `g`:

```js
const texto = "Compré 3 panes, 2 leches y 10 huevos";

console.log(texto.match(/\d+/g));
```

Resultado:

```js
["3", "2", "10"]
```

---

## 29. `replace()`: buscar y reemplazar

Las regex son extremadamente útiles para transformar texto.

Por ejemplo:

```js
const texto = "Juan     Pérez";

const limpio = texto.replace(/\s+/g, " ");

console.log(limpio);
```

Resultado:

```text
Juan Pérez
```

La expresión:

```js
/\s+/g
```

significa:

```text
uno o más espacios
en todas las posiciones
```

Y los sustituimos por un único espacio.

---

## 30. `split()`: separar utilizando un patrón

Normalmente hacemos:

```js
"a,b,c".split(",");
```

Pero podemos separar utilizando una regex.

Por ejemplo, queremos aceptar espacios variables:

```text
Juan,Pedro,Ana
Juan, Pedro, Ana
Juan , Pedro ,Ana
```

Podemos hacer:

```js
const texto = "Juan , Pedro,   Ana";

const nombres = texto.split(/\s*,\s*/);

console.log(nombres);
```

Resultado:

```js
["Juan", "Pedro", "Ana"]
```

La expresión:

```js
\s*,\s*
```

significa:

```text
cero o más espacios
,
cero o más espacios
```

---

## 31. Capturas

Los paréntesis no solamente agrupan. También **capturan** la parte del texto que coincidió.

Supongamos una fecha:

```text
24/08/2026
```

Podemos describirla así:

```js
/(\d{2})\/(\d{2})\/(\d{4})/
```

Tenemos tres grupos:

```text
(\d{2})    día
(\d{2})    mes
(\d{4})    año
```

Ejemplo:

```js
const fecha = "24/08/2026";

const resultado = fecha.match(/(\d{2})\/(\d{2})\/(\d{4})/);

console.log(resultado[0]);
console.log(resultado[1]);
console.log(resultado[2]);
console.log(resultado[3]);
```

Resultado:

```text
24/08/2026
24
08
2026
```

Es decir:

```text
resultado[0] = coincidencia completa
resultado[1] = primer grupo
resultado[2] = segundo grupo
resultado[3] = tercer grupo
```

---

## 32. Grupos con nombre

JavaScript moderno permite dar nombres a las capturas.

```js
const regex =
  /(?<dia>\d{2})\/(?<mes>\d{2})\/(?<anio>\d{4})/;
```

Entonces:

```js
const resultado = "24/08/2026".match(regex);

console.log(resultado.groups.dia);
console.log(resultado.groups.mes);
console.log(resultado.groups.anio);
```

Resultado:

```text
24
08
2026
```

Esto suele ser mucho más legible que trabajar con posiciones numéricas.

---

## 33. Un ejemplo completo: extraer información

Tenemos:

```js
const texto = "Alumno: Juan Pérez - Legajo: 12345";
```

Queremos obtener el legajo.

Podemos buscar:

```js
/Legajo:\s*(\d+)/
```

Descompongámoslo:

```text
Legajo:     texto literal

\s*         cero o más espacios

(\d+)       uno o más dígitos,
            y además los capturamos
```

Entonces:

```js
const texto = "Alumno: Juan Pérez - Legajo: 12345";

const resultado = texto.match(/Legajo:\s*(\d+)/);

console.log(resultado[1]);
```

Resultado:

```text
12345
```

Eso muestra el uso conceptual más importante de regex:

> convertir texto aparentemente desestructurado en datos estructurados.

---

## 34. Límites de palabra `\b`

Consideremos:

```js
/gato/
```

También encuentra `gato` dentro de:

```text
gatopardo
```

porque ahí aparecen esos cuatro caracteres.

Si queremos la palabra `gato`, podemos usar:

```js
/\bgato\b/
```

`\b` significa aproximadamente:

> límite de palabra.

Entonces:

```js
/\bgato\b/.test("El gato duerme");
```

da:

```js
true
```

mientras:

```js
/\bgato\b/.test("El gatopardo duerme");
```

da:

```js
false
```

---

## 35. Greedy: los cuantificadores son «codiciosos»

Supongamos:

```js
const texto = "<b>hola</b><b>mundo</b>";
```

Queremos obtener el contenido entre `<b>` y `</b>`.

Podríamos intentar:

```js
/<b>.*<\/b>/
```

Pero `.*` es **greedy**: intenta consumir todo lo posible.

Por eso puede capturar:

```text
<b>hola</b><b>mundo</b>
```

en lugar de solamente:

```text
<b>hola</b>
```

---

## 36. Cuantificadores no codiciosos

Podemos agregar `?` después del cuantificador:

```js
.*?
```

Entonces:

```js
/<b>.*?<\/b>/
```

busca la coincidencia más corta posible.

Conceptualmente:

```text
.*     todo lo posible
.*?    lo mínimo posible
```

También existen:

```text
+?
*?
{n,m}?
```

---

## 37. Unicode

JavaScript trabaja con Unicode, y las expresiones regulares modernas tienen soporte específico mediante el flag:

```js
u
```

Por ejemplo:

```js
/./u
```

maneja correctamente los puntos de código Unicode en situaciones donde una regex tradicional puede comportarse de forma inesperada con caracteres representados mediante pares sustitutos UTF-16.

Además existen las **Unicode Property Escapes**.

Por ejemplo:

```js
/\p{Letter}/u
```

significa:

> cualquier carácter Unicode cuya propiedad sea «letra».

Esto es mucho más apropiado para texto internacional que:

```js
/[A-Za-z]/
```

Por ejemplo:

```js
/\p{Letter}+/u.test("José");
```

```js
true
```

Y podemos combinarlo con `g`:

```js
const palabras = "José, María y Ñandú".match(/\p{Letter}+/gu);

console.log(palabras);
```

---

## 38. Una regex se puede pensar como un pequeño lenguaje

Llegados a este punto, conviene cambiar la forma de pensar.

No hay que memorizar regex completas.

Hay que aprender a leerlas como un lenguaje.

Por ejemplo:

```js
/^[A-Z][a-z]+$/
```

podemos traducirla paso por paso:

```text
^
comienzo

[A-Z]
una mayúscula

[a-z]+
una o más minúsculas

$
final
```

Por tanto describe textos como:

```text
Juan
Pedro
Maria
```

pero no:

```text
juan
JUAN
Juan123
```

---

## 39. Construir una regex en lugar de adivinarla

Supongamos que necesitamos validar un código con esta forma:

```text
ABC-1234
```

No intentemos escribir la regex completa mentalmente.

Partimos de la especificación.

Tres letras mayúsculas:

```js
[A-Z]{3}
```

Después un guion:

```js
[A-Z]{3}-
```

Después cuatro números:

```js
[A-Z]{3}-\d{4}
```

Y queremos validar el texto completo:

```js
/^[A-Z]{3}-\d{4}$/
```

Probamos:

```js
const codigo = /^[A-Z]{3}-\d{4}$/;

console.log(codigo.test("ABC-1234")); // true
console.log(codigo.test("AB-1234"));  // false
console.log(codigo.test("abc-1234")); // false
```

Esta es la manera correcta de trabajar:

> problema → componentes → regex.

No al revés.

---

## 40. Un ejemplo más real: nombre y número

Supongamos que recibimos líneas:

```text
Juan Perez,123
Ana Gomez,456
Pedro López,789
```

Queremos separar nombre y número.

Podemos usar:

```js
/^(.+),(\d+)$/
```

Traducimos:

```text
^

(.+)
uno o más caracteres
capturados

,
coma literal

(\d+)
uno o más números
capturados

$
```

Entonces:

```js
const linea = "Juan Perez,123";

const match = linea.match(/^(.+),(\d+)$/);

console.log(match[1]);
console.log(match[2]);
```

Resultado:

```text
Juan Perez
123
```

---

## 41. Pero regex no reemplaza a un parser

Esto es importante.

Las expresiones regulares son excelentes para estructuras relativamente simples:

```text
números
fechas
códigos
líneas
identificadores
fragmentos de texto
separadores
normalización
```

No son necesariamente la herramienta adecuada para analizar estructuras complejas como:

```text
HTML completo
JavaScript
JSON
SQL
lenguajes de programación
```

Por ejemplo, para JSON:

```js
JSON.parse(texto);
```

es muchísimo mejor que intentar construir una regex monstruosa.

Cuando una expresión regular comienza a parecer un conjuro para invocar a Cthulhu, probablemente sea momento de usar un parser.

---

## 42. La idea teórica detrás de una expresión regular

En términos conceptuales, una regex describe un **lenguaje**.

Por ejemplo:

```js
/\d{3}/
```

describe el conjunto:

```text
000
001
002
...
998
999
```

No enumera esas 1000 posibilidades.

Describe una **regla generadora** para todas ellas.

Podemos decir:

```text
L = { todos los strings formados por exactamente tres dígitos }
```

La regex:

```text
\d{3}
```

es una representación compacta de ese conjunto.

---

## 43. Regex y autómatas

Esta idea conecta con teoría de la computación.

Una expresión regular puede convertirse conceptualmente en una máquina que lee caracteres uno por uno.

Para:

```js
/ab+c/
```

la máquina tendría estados similares a:

```text
inicio
  |
  a
  v
estado 1
  |
  b
  v
estado 2
  |\
  | b
  |/
  |
  c
  v
aceptado
```

Reconoce:

```text
abc
abbc
abbbc
abbbbbc
```

pero no:

```text
ac
ab
bac
```

Esta máquina es un **autómata finito**.

De ahí viene el nombre «expresiones regulares»: originalmente describen precisamente los **lenguajes regulares**.

Los motores modernos de regex han agregado características que van más allá de las expresiones regulares matemáticas puras, pero la intuición sigue siendo excelente.

---

## 44. Resumen mental

No conviene aprender regex como una colección de jeroglíficos. Conviene recordar unas pocas ideas.

```text
texto literal
gato
```

```text
cualquier carácter
.
```

```text
uno de estos caracteres
[abc]
```

```text
un dígito
\d
```

```text
un espacio
\s
```

```text
repetición
*   cero o más
+   uno o más
?   cero o uno
```

```text
cantidad
{3}
{2,5}
{2,}
```

```text
posición
^   comienzo
$   final
\b  límite de palabra
```

```text
estructura
()  grupo
|   alternativa
```

Y en JavaScript:

```js
regex.test(texto)
texto.match(regex)
texto.matchAll(regex)
texto.replace(regex, reemplazo)
texto.split(regex)
```

La habilidad importante no es memorizar una expresión monstruosa.

La habilidad importante es poder mirar una necesidad como:

> «tres letras, después un guion, después cuatro números»

y construir tranquilamente:

```js
/^[A-Z]{3}-\d{4}$/
```

Una regex no es más que eso: **una descripción compacta de qué secuencia de caracteres consideramos válida o interesante**.
