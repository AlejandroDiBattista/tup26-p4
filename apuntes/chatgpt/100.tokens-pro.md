# BPE desde primeros principios en JavaScript con Node.js

> **BPE** significa **Byte Pair Encoding**, es decir, **codificación por pares de bytes**. En tokenizadores modernos, la idea se generaliza: después de las primeras fusiones ya no se combinan necesariamente dos bytes aislados, sino dos **tokens**, cada uno de los cuales puede representar varios bytes.

## Objetivo

Vamos a construir, sin librerías externas, una clase `BPE` con tres operaciones principales:

```js
bpe.aprender(textoBase);       // aprende las fusiones frecuentes
bpe.codificar(texto);          // string -> lista de tokens
bpe.decodificar(tokens);       // lista de tokens -> string
```

El propósito no es reproducir todos los detalles de un tokenizador industrial, sino aislar el algoritmo esencial para entenderlo por completo.

---

## 1. Antes de BPE: ¿cómo representa una computadora un texto?

Una computadora almacena números, no letras. Para guardar un texto necesitamos una regla que convierta caracteres en bytes. En Node.js podemos usar UTF-8 mediante `Buffer`:

```js
console.log([...Buffer.from("A", "utf8")]);
console.log([...Buffer.from("ñ", "utf8")]);
console.log([...Buffer.from("☕", "utf8")]);
```

Resultado:

```txt
[65]
[195, 177]
[226, 152, 149]
```

La letra `A` necesita un byte en UTF-8. La `ñ` necesita dos y `☕` necesita tres.

Esto nos da una primera forma de tokenizar cualquier texto:

```js
const tokens = [...Buffer.from(texto, "utf8")];
```

Cada número entre `0` y `255` puede considerarse un token básico.

### Ventaja

El vocabulario inicial tiene solamente 256 tokens y puede representar cualquier texto codificado en UTF-8. Nunca aparece un carácter desconocido.

### Problema

La secuencia puede resultar larga. Una palabra frecuente como `banana` ocupa seis tokens si cada byte se trata por separado:

```txt
b  a  n  a  n  a
98 97 110 97 110 97
```

BPE intenta reducir esa longitud aprendiendo fragmentos frecuentes.

---

## 2. ¿Qué es un token?

Un token será simplemente un número entero que representa una secuencia de bytes.

Al comenzar:

```txt
Token 97  -> [97]      -> "a"
Token 98  -> [98]      -> "b"
Token 110 -> [110]     -> "n"
```

Los tokens `0` a `255` representan los 256 bytes posibles. BPE crea tokens nuevos a partir del identificador `256`:

```txt
Token 256 -> [97, 110] -> "an"
Token 257 -> [98, 97, 110] -> "ban"
```

El número `256` no significa universalmente `"an"`. Ese significado pertenece al vocabulario aprendido por un modelo concreto.

---

## 3. ¿Por qué necesitamos BPE?

Existen varias estrategias posibles:

| Estrategia | Ventaja | Problema |
|---|---|---|
| Un token por byte | Vocabulario pequeño, completo y reversible | Produce muchas unidades |
| Un token por palabra | Las frases pueden usar pocos tokens | Vocabulario enorme y palabras desconocidas |
| BPE | Aprende fragmentos frecuentes y conserva los bytes como respaldo | Requiere entrenar y guardar un vocabulario |

BPE adopta un compromiso:

- Los textos raros pueden representarse mediante bytes individuales.
- Las secuencias frecuentes se agrupan en tokens más grandes.
- No es necesario conocer de antemano todas las palabras posibles.

BPE no aprende significados. Aprende **repeticiones estadísticas**.

---

## 4. La idea central del algoritmo

El entrenamiento sigue este procedimiento:

1. Convertir el texto base en bytes.
2. Contar todos los pares de tokens adyacentes.
3. Elegir el par más frecuente.
4. Crear un token nuevo que represente su concatenación.
5. Reemplazar todas sus apariciones no superpuestas.
6. Repetir hasta alcanzar el tamaño de vocabulario solicitado o hasta que ningún par aparezca al menos dos veces.

En pseudocódigo:

```txt
tokens = bytes UTF-8 del texto

mientras queden tokens por aprender:
    par = par adyacente más frecuente

    si el par aparece menos de dos veces:
        terminar

    nuevoToken = concatenación de los dos tokens del par
    guardar la regla de fusión
    reemplazar el par por nuevoToken
```

### Una precisión importante

En la primera iteración se fusionan dos bytes. Luego pueden fusionarse tokens mayores:

```txt
"a" + "n"   -> "an"
"b" + "an"  -> "ban"
"ban" + "an" -> "banan"
```

Por eso, en la práctica, BPE termina aprendiendo fragmentos de longitud variable.

---

## 5. Ejemplo manual: `banana banana`

Para facilitar la lectura mostraremos caracteres, aunque internamente usamos sus bytes.

Secuencia inicial:

```txt
b a n a n a ␠ b a n a n a
```

Los pares más importantes son:

```txt
b + a : 2 veces
a + n : 4 veces
n + a : 4 veces
```

Hay un empate entre `a+n` y `n+a`. Nuestra implementación conserva el primero que encontró entre los de frecuencia máxima, por lo que elige `a+n`.

### Primera fusión

```txt
256 = "a" + "n" = "an"
```

La secuencia queda:

```txt
b 256 256 a ␠ b 256 256 a
```

### Segunda fusión

```txt
257 = "b" + 256 = "ban"
```

Resultado:

```txt
257 256 a ␠ 257 256 a
```

### Tercera fusión

```txt
258 = 257 + 256 = "banan"
```

Resultado:

```txt
258 a ␠ 258 a
```

### Cuarta fusión

```txt
259 = 258 + "a" = "banana"
```

Resultado final:

```txt
259 32 259
```

El `32` es el byte UTF-8 del espacio. La frase pasó de 13 tokens básicos a 3 tokens usando cuatro fusiones aprendidas.

## 6. Estado que debe guardar la clase

La clase necesita dos estructuras:

```js
this.vocabulario // token -> secuencia de bytes
this.fusiones    // reglas aprendidas, en orden
```

El vocabulario comienza así:

```js
for (let byte = 0; byte < 256; byte++) {
  this.vocabulario.set(byte, [byte]);
}
```

Cada token básico representa exactamente un byte.

Las fusiones tendrán esta forma:

```js
{
  izquierdo: 97,
  derecho: 110,
  nuevo: 256
}
```

Esto significa:

```txt
[97, 110] -> 256
```

El orden de las reglas es parte del modelo. Una regla posterior puede depender de un token creado por una regla anterior.

---

## 7. Primer auxiliar: encontrar el par más frecuente

Recorremos la secuencia y contamos cada pareja adyacente:

```js
buscarParMasFrecuente(tokens) {
  const conteos = new Map();

  for (let i = 0; i < tokens.length - 1; i++) {
    const izquierdo = tokens[i];
    const derecho = tokens[i + 1];
    const clave = `${izquierdo},${derecho}`;
    const par = conteos.get(clave);

    if (par === undefined) {
      conteos.set(clave, {
        izquierdo,
        derecho,
        frecuencia: 1,
      });
    } else {
      par.frecuencia++;
    }
  }

  let mejorPar = null;

  for (const par of conteos.values()) {
    if (mejorPar === null || par.frecuencia > mejorPar.frecuencia) {
      mejorPar = par;
    }
  }

  return mejorPar;
}
```

La clave `"97,110"` permite usar un par de números como clave de un `Map`.

Si varios pares tienen la misma frecuencia máxima, se conserva el que apareció primero. Esta decisión modifica el vocabulario aprendido, pero no compromete la reversibilidad.

---

## 8. Segundo auxiliar: fusionar un par

Una vez elegido un par, debemos reemplazar sus apariciones de izquierda a derecha:

```js
fusionarPar(tokens, izquierdo, derecho, nuevoToken) {
  const resultado = [];

  for (let i = 0; i < tokens.length; ) {
    const coincide =
      i + 1 < tokens.length &&
      tokens[i] === izquierdo &&
      tokens[i + 1] === derecho;

    if (coincide) {
      resultado.push(nuevoToken);
      i += 2;
    } else {
      resultado.push(tokens[i]);
      i += 1;
    }
  }

  return resultado;
}
```

Cuando encuentra el par, agrega el token nuevo y avanza dos posiciones. De ese modo las fusiones no se superponen.

Por ejemplo:

```txt
[a, a, a, a]
```

al fusionar `a+a -> X` produce:

```txt
[X, X]
```

## 9. Método `aprender`

El entrenamiento comienza con los bytes UTF-8 del texto:

```js
let tokens = [...Buffer.from(textoBase, "utf8")];
```

En cada vuelta crea una nueva entrada del vocabulario:

```js
aprender(textoBase) {
  this.reiniciar();
  let tokens = [...Buffer.from(textoBase, "utf8")];

  while (this.vocabulario.size < this.tamanoVocabulario) {
    const mejorPar = this.buscarParMasFrecuente(tokens);

    if (mejorPar === null || mejorPar.frecuencia < 2) {
      break;
    }

    const nuevoToken = this.vocabulario.size;

    const bytesIzquierdos = this.vocabulario.get(mejorPar.izquierdo);
    const bytesDerechos = this.vocabulario.get(mejorPar.derecho);

    this.vocabulario.set(nuevoToken, [
      ...bytesIzquierdos,
      ...bytesDerechos,
    ]);

    this.fusiones.push({
      izquierdo: mejorPar.izquierdo,
      derecho: mejorPar.derecho,
      nuevo: nuevoToken,
    });

    tokens = this.fusionarPar(
      tokens,
      mejorPar.izquierdo,
      mejorPar.derecho,
      nuevoToken,
    );
  }

  return tokens;
}
```

Como el vocabulario inicial tiene 256 entradas, pedir un tamaño de `260` permite aprender como máximo cuatro tokens nuevos:

```txt
256 tokens básicos + 4 tokens aprendidos = 260
```

El método devuelve la tokenización final del propio texto de entrenamiento. Esto no es indispensable para entrenar, pero resulta útil para observar el resultado.

---

## 10. Método `codificar`

Para codificar un texto nuevo:

1. Lo convertimos en bytes.
2. Reproducimos las fusiones aprendidas en el mismo orden.

```js
codificar(texto) {
  let tokens = [...Buffer.from(texto, "utf8")];

  for (const fusion of this.fusiones) {
    tokens = this.fusionarPar(
      tokens,
      fusion.izquierdo,
      fusion.derecho,
      fusion.nuevo,
    );
  }

  return tokens;
}
```

El orden importa. Para crear el token `"ban"`, primero debe existir el token `"an"`.

Los fragmentos no aprendidos permanecen representados por sus bytes básicos. Por eso el modelo puede codificar incluso palabras, idiomas o símbolos que no aparecieron durante el entrenamiento.

---

## 11. Método `decodificar`

Cada token conoce exactamente qué bytes representa. Para decodificar:

1. Buscamos los bytes de cada token.
2. Los concatenamos.
3. Interpretamos el resultado como UTF-8.

```js
decodificar(tokens) {
  const bytes = [];

  for (const token of tokens) {
    const fragmento = this.vocabulario.get(token);

    if (fragmento === undefined) {
      throw new Error(`Token desconocido: ${token}`);
    }

    for (const byte of fragmento) {
      bytes.push(byte);
    }
  }

  return Buffer.from(bytes).toString("utf8");
}
```

No hace falta deshacer las fusiones una por una. El vocabulario ya almacena la secuencia completa de bytes correspondiente a cada token.

# 12. Implementación completa

Guarda el siguiente contenido en un archivo llamado `bpe.js`:

```js
class BPE {
  constructor(tamanoVocabulario = 300) {
    if (!Number.isInteger(tamanoVocabulario) || tamanoVocabulario < 256) {
      throw new Error(
        "El tamaño del vocabulario debe ser un entero mayor o igual que 256.",
      );
    }

    this.tamanoVocabulario = tamanoVocabulario;
    this.reiniciar();
  }

  reiniciar() {
    this.vocabulario = new Map();

    // Los tokens 0..255 representan los 256 bytes posibles.
    for (let byte = 0; byte < 256; byte++) {
      this.vocabulario.set(byte, [byte]);
    }

    // Cada elemento será: { izquierdo, derecho, nuevo }.
    this.fusiones = [];
  }

  aprender(textoBase) {
    if (typeof textoBase !== "string") {
      throw new TypeError("El texto base debe ser un string.");
    }

    this.reiniciar();
    let tokens = [...Buffer.from(textoBase, "utf8")];

    while (this.vocabulario.size < this.tamanoVocabulario) {
      const mejorPar = this.buscarParMasFrecuente(tokens);

      // Una aparición aislada no justifica crear un token nuevo.
      if (mejorPar === null || mejorPar.frecuencia < 2) {
        break;
      }

      const nuevoToken = this.vocabulario.size;
      const bytesIzquierdos = this.vocabulario.get(mejorPar.izquierdo);
      const bytesDerechos = this.vocabulario.get(mejorPar.derecho);

      // El token nuevo representa la concatenación de ambos fragmentos.
      this.vocabulario.set(nuevoToken, [
        ...bytesIzquierdos,
        ...bytesDerechos,
      ]);

      this.fusiones.push({
        izquierdo: mejorPar.izquierdo,
        derecho: mejorPar.derecho,
        nuevo: nuevoToken,
      });

      tokens = this.fusionarPar(
        tokens,
        mejorPar.izquierdo,
        mejorPar.derecho,
        nuevoToken,
      );
    }

    return tokens;
  }

  codificar(texto) {
    if (typeof texto !== "string") {
      throw new TypeError("El texto debe ser un string.");
    }

    let tokens = [...Buffer.from(texto, "utf8")];

    // Repetimos exactamente las fusiones aprendidas y en el mismo orden.
    for (const fusion of this.fusiones) {
      tokens = this.fusionarPar(
        tokens,
        fusion.izquierdo,
        fusion.derecho,
        fusion.nuevo,
      );
    }

    return tokens;
  }

  decodificar(tokens) {
    if (!Array.isArray(tokens)) {
      throw new TypeError("Los tokens deben estar contenidos en un array.");
    }

    const bytes = [];

    for (const token of tokens) {
      const fragmento = this.vocabulario.get(token);

      if (fragmento === undefined) {
        throw new Error(`Token desconocido: ${token}`);
      }

      for (const byte of fragmento) {
        bytes.push(byte);
      }
    }

    return Buffer.from(bytes).toString("utf8");
  }

  buscarParMasFrecuente(tokens) {
    const conteos = new Map();

    for (let i = 0; i < tokens.length - 1; i++) {
      const izquierdo = tokens[i];
      const derecho = tokens[i + 1];
      const clave = `${izquierdo},${derecho}`;
      const par = conteos.get(clave);

      if (par === undefined) {
        conteos.set(clave, {
          izquierdo,
          derecho,
          frecuencia: 1,
        });
      } else {
        par.frecuencia++;
      }
    }

    let mejorPar = null;

    for (const par of conteos.values()) {
      if (mejorPar === null || par.frecuencia > mejorPar.frecuencia) {
        mejorPar = par;
      }
    }

    return mejorPar;
  }

  fusionarPar(tokens, izquierdo, derecho, nuevoToken) {
    const resultado = [];

    for (let i = 0; i < tokens.length; ) {
      const coincide =
        i + 1 < tokens.length &&
        tokens[i] === izquierdo &&
        tokens[i + 1] === derecho;

      if (coincide) {
        resultado.push(nuevoToken);
        i += 2;
      } else {
        resultado.push(tokens[i]);
        i += 1;
      }
    }

    return resultado;
  }
}

// ------------------------------------------------------------
// Ejemplo de uso
// ------------------------------------------------------------

const bpe = new BPE(260);
const tokensEntrenamiento = bpe.aprender("banana banana");

console.log("Tokens del entrenamiento:", tokensEntrenamiento);
console.log("Fusiones aprendidas:");

for (const fusion of bpe.fusiones) {
  const textoDelToken = Buffer.from(
    bpe.vocabulario.get(fusion.nuevo),
  ).toString("utf8");

  console.log(`${fusion.nuevo} = ${JSON.stringify(textoDelToken)}`);
}

const original = "banana bananas";
const tokens = bpe.codificar(original);
const recuperado = bpe.decodificar(tokens);

console.log("Texto original:   ", original);
console.log("Tokens:           ", tokens);
console.log("Texto recuperado: ", recuperado);
console.log("¿Son iguales?:    ", original === recuperado);

const textoUnicode = "mañana ☕";
const tokensUnicode = bpe.codificar(textoUnicode);

console.log(
  "¿También conserva Unicode?:",
  bpe.decodificar(tokensUnicode) === textoUnicode,
);
```

## 14. ¿Por qué la decodificación recupera exactamente el texto?

La propiedad fundamental puede razonarse paso a paso:

1. Cada token inicial representa exactamente un byte.
2. Cada token nuevo representa la concatenación exacta de dos tokens anteriores.
3. Una fusión reemplaza una secuencia por otro token que representa los mismos bytes.
4. Por lo tanto, codificar modifica la agrupación, pero no la información.
5. Decodificar concatena nuevamente todos los bytes y los interpreta como UTF-8.

Para cualquier string correctamente codificado:

```js
bpe.decodificar(bpe.codificar(texto)) === texto
```

Debe usarse el mismo vocabulario para ambas operaciones. Una lista de tokens aprendidos por un modelo no tiene por qué ser interpretable por otro.

## 15. Qué simplificamos

Esta implementación contiene el núcleo del algoritmo, pero un tokenizador de producción suele agregar:

- Presegmentación del texto para controlar fusiones entre palabras.
- Tokens especiales, como inicio, fin o relleno.
- Reglas explícitas de normalización.
- Persistencia del vocabulario y de las fusiones.
- Algoritmos más eficientes para entrenar corpus grandes.
- Tratamiento específico de entradas inválidas o reservadas.

Nuestro entrenamiento vuelve a recorrer la secuencia en cada fusión. Es fácil de entender, aunque no está optimizado para millones de caracteres. Primero conviene dominar el mecanismo; la microoptimización puede esperar su turno sin hacer berrinche.

## 16. Modelo mental final

Todo el proceso puede resumirse así:

```txt
STRING
  ↓ UTF-8
BYTES
  ↓ aplicar fusiones aprendidas
TOKENS
  ↓ consultar el vocabulario
BYTES
  ↓ UTF-8
STRING
```

BPE comienza con una representación universal basada en bytes y aprende a agrupar las secuencias que más se repiten. Esa única idea permite obtener un vocabulario finito, evitar palabras desconocidas y representar fragmentos frecuentes con menos tokens.

## 17. Ver las fusiones paso a paso

Después de entrenar, `bpe.fusiones` conserva las reglas en el mismo orden en que fueron aprendidas. Podemos reproducirlas y mostrar cómo cambia la secuencia.

Agrega esta función después de la clase:

```js
function mostrarProceso(bpe, texto) {
  let tokens = [...Buffer.from(texto, "utf8")];

  function describir(token) {
    const bytes = bpe.vocabulario.get(token);
    const fragmento = Buffer.from(bytes).toString("utf8");
    return `${token}:${JSON.stringify(fragmento)}`;
  }

  function mostrar(etiqueta) {
    console.log(
      etiqueta,
      tokens.map(describir).join(" | "),
    );
  }

  mostrar("Inicio  ->");

  for (const fusion of bpe.fusiones) {
    tokens = bpe.fusionarPar(
      tokens,
      fusion.izquierdo,
      fusion.derecho,
      fusion.nuevo,
    );

    mostrar(`Regla ${fusion.nuevo} ->`);
  }
}
```

Luego ejecútala:

```js
const bpe = new BPE(260);
bpe.aprender("banana banana");

mostrarProceso(bpe, "banana banana");
```

La salida será semejante a esta:

```txt
Inicio    -> 98:"b" | 97:"a" | 110:"n" | 97:"a" | 110:"n" | 97:"a" | 32:" " | ...
Regla 256 -> 98:"b" | 256:"an" | 256:"an" | 97:"a" | 32:" " | ...
Regla 257 -> 257:"ban" | 256:"an" | 97:"a" | 32:" " | ...
Regla 258 -> 258:"banan" | 97:"a" | 32:" " | 258:"banan" | 97:"a"
Regla 259 -> 259:"banana" | 32:" " | 259:"banana"
```

Esta visualización deja a la vista una idea importante: un token nuevo no reemplaza letras arbitrariamente. Siempre reemplaza una pareja exacta de tokens ya existentes.

## 18. Probar la propiedad fundamental

La prueba más importante de un tokenizador reversible es esta:

```txt
decodificar(codificar(texto)) = texto
```

Node.js incluye el módulo `node:assert`, por lo que no necesitamos instalar nada. Agrega al final de `bpe.js`:

```js
const assert = require("node:assert/strict");

const modelo = new BPE(280);
modelo.aprender("banana mañana café banana mañana café");

const casos = [
  "",
  "banana",
  "una frase que no apareció durante el entrenamiento",
  "mañana tomaré café ☕",
  "中文",
  "👨‍👩‍👧‍👦",
];

for (const texto of casos) {
  const tokens = modelo.codificar(texto);
  const recuperado = modelo.decodificar(tokens);

  assert.equal(recuperado, texto);
}

console.log("Todas las pruebas pasaron.");
```

Ejecuta:

```bash
node bpe.js
```

Si alguna conversión pierde información, `assert.equal` detendrá el programa y mostrará el caso que falló. Si todo funciona, veremos:

```txt
Todas las pruebas pasaron.
```

El modelo puede reconstruir textos que nunca vio porque siempre conserva como respaldo los 256 tokens básicos, uno por cada byte posible.

## 19. Guardar y cargar el modelo aprendido

Entrenar y codificar son operaciones diferentes. Después del entrenamiento necesitamos conservar:

- El vocabulario: qué bytes representa cada token.
- Las fusiones: en qué orden deben aplicarse.

Un `Map` no se convierte directamente a JSON, pero sí podemos transformarlo en una lista de pares.

Agrega estos dos métodos dentro de la clase `BPE`:

```js
exportar() {
  return {
    tamanoVocabulario: this.tamanoVocabulario,
    vocabulario: [...this.vocabulario.entries()],
    fusiones: this.fusiones,
  };
}

static importar(datos) {
  const bpe = new BPE(datos.tamanoVocabulario);

  bpe.vocabulario = new Map(datos.vocabulario);
  bpe.fusiones = datos.fusiones;

  return bpe;
}
```

Ahora podemos guardarlo con las funciones de archivos de Node.js:

```js
const fs = require("node:fs");

const bpe = new BPE(260);
bpe.aprender("banana banana");

fs.writeFileSync(
  "modelo-bpe.json",
  JSON.stringify(bpe.exportar(), null, 2),
  "utf8",
);
```

Y cargarlo en otra ejecución:

```js
const fs = require("node:fs");

const datos = JSON.parse(
  fs.readFileSync("modelo-bpe.json", "utf8"),
);

const bpe = BPE.importar(datos);

const tokens = bpe.codificar("banana");
console.log(tokens);
console.log(bpe.decodificar(tokens));
```

Salida:

```txt
[259]
banana
```

No volvimos a entrenar. Cargamos exactamente el vocabulario y las reglas que ya habían sido aprendidas.

## 20. Qué conviene experimentar

Para terminar de apropiarse del algoritmo, resulta útil cambiar una sola cosa por vez:

1. Entrenar con `"abracadabra abracadabra"` y observar las fusiones.
2. Comparar vocabularios de tamaños `256`, `260` y `300`.
3. Codificar una palabra presente en el entrenamiento y otra completamente nueva.
4. Entrenar con textos que incluyan `ñ`, acentos, emojis o escrituras no latinas.
5. Medir cuántos bytes y cuántos tokens utiliza cada texto.

Esta pequeña función permite hacer la última comparación:

```js
function comparar(bpe, texto) {
  const bytes = Buffer.byteLength(texto, "utf8");
  const tokens = bpe.codificar(texto).length;

  console.log({ texto, bytes, tokens });
}

comparar(bpe, "banana");
comparar(bpe, "bananas");
comparar(bpe, "ornitorrinco");
```

BPE no garantiza que todo texto use menos tokens. Reduce especialmente las secuencias que se parecen al corpus de entrenamiento. El vocabulario aprendido refleja la frecuencia del texto que le dimos: no adivina; cuenta, fusiona y vuelve a contar.
