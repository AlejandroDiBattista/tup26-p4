# Byte Pair Encoding (BPE) en JavaScript con Node.js

## 1. El problema: ¿cómo convertir texto en números?

Una computadora no trabaja directamente con palabras como:

```text
hola
```

Trabaja con números.

Por eso, antes de enviar texto a un modelo, necesitamos una función que transforme un texto en una secuencia de números:

```text
"hola" -> [104, 111, 108, 97]
```

A esos números los llamaremos **tokens**.

Pero aparece inmediatamente una pregunta:

> ¿Qué debería representar cada token?

Podríamos usar:

- un token por carácter;
- un token por palabra;
- un token por byte;
- o tokens que representen fragmentos frecuentes de texto.

BPE, **Byte Pair Encoding**, parte de una idea muy simple:

> empezar con unidades pequeñas y unir repetidamente los pares que aparecen con mayor frecuencia.

En nuestro caso las unidades iniciales serán **bytes**.

---

# 2. Antes de BPE: texto, Unicode y UTF-8

JavaScript maneja strings Unicode:

```js
const texto = "hola";
```

Pero para trabajar con bytes necesitamos convertir ese string a una secuencia de bytes.

Node.js permite hacerlo fácilmente:

```js
const bytes = Buffer.from("hola", "utf8");

console.log([...bytes]);
```

Resultado:

```text
[104, 111, 108, 97]
```

Cada número está entre `0` y `255`, porque un byte tiene 8 bits:

```text
00000000 -> 0
11111111 -> 255
```

En ASCII muchos caracteres ocupan un solo byte.

Por ejemplo:

```text
h -> 104
o -> 111
l -> 108
a -> 97
```

Pero Unicode contiene muchos más caracteres.

Por ejemplo:

```js
console.log([...Buffer.from("ñ", "utf8")]);
```

produce:

```text
[195, 177]
```

La `ñ` necesita dos bytes en UTF-8.

Un emoji puede necesitar todavía más:

```js
console.log([...Buffer.from("😀", "utf8")]);
```

produce cuatro bytes.

Esto es importante porque nuestro tokenizer no necesita conocer letras, palabras ni idiomas.

Solo necesita conocer bytes.

---

# 3. ¿Por qué empezar por bytes?

Supongamos que hacemos un tokenizer basado únicamente en palabras.

Durante el entrenamiento encontramos:

```text
casa
perro
gato
```

Pero después aparece:

```text
ornitorrinco
```

Si esa palabra nunca fue aprendida, podríamos no saber cómo representarla.

Con bytes esto nunca ocurre.

Todo texto UTF-8 puede convertirse en bytes.

Por lo tanto, comenzamos con un vocabulario universal de 256 tokens:

```text
0
1
2
...
255
```

Cada token representa exactamente un byte.

Así nuestro tokenizer siempre puede representar cualquier texto.

---

# 4. El problema de usar solamente bytes

Funciona, pero produce demasiados tokens.

Por ejemplo:

```text
banana
```

en UTF-8 es:

```text
[98, 97, 110, 97, 110, 97]
```

Son seis tokens.

Pero observemos la estructura:

```text
b a n a n a
```

El par:

```text
a n
```

aparece dos veces.

Podríamos inventar un nuevo token que represente:

```text
a n
```

Entonces:

```text
b a n a n a
```

se convertiría aproximadamente en:

```text
b [an] [an] a
```

Ahora tenemos cuatro tokens.

BPE hace exactamente eso.

---

# 5. La idea fundamental de BPE

El algoritmo de aprendizaje puede resumirse así:

1. Convertir el texto de entrenamiento en bytes.
2. Buscar todos los pares de tokens consecutivos.
3. Encontrar el par más frecuente.
4. Crear un nuevo token para ese par.
5. Reemplazar todas sus apariciones.
6. Repetir.

Supongamos:

```text
banana
```

Inicialmente:

```text
98 97 110 97 110 97
```

Los pares son:

```text
98 97
97 110
110 97
97 110
110 97
```

Contamos:

```text
98 97   -> 1 vez
97 110  -> 2 veces
110 97  -> 2 veces
```

Hay un empate. Nuestro programa puede elegir simplemente el primero que encuentre.

Supongamos que selecciona:

```text
97 110
```

Creamos el token:

```text
256
```

con significado:

```text
256 = [97, 110]
```

Entonces:

```text
98 97 110 97 110 97
```

se transforma en:

```text
98 256 256 97
```

Ahora volvemos a contar pares.

BPE continúa aprendiendo estructuras cada vez mayores.

---

# 6. Los tokens nuevos son composiciones

Nuestro vocabulario comienza así:

```text
0..255 = bytes originales
```

Luego aprendemos tokens nuevos:

```text
256 = [97, 110]
257 = [98, 256]
258 = [256, 97]
...
```

Un token nuevo puede contener tokens que a su vez contienen otros tokens.

Por eso BPE construye una especie de vocabulario jerárquico.

Por ejemplo:

```text
256 = "an"
257 = "ban"
258 = "ana"
259 = "banana"
```

No necesariamente aprenderá exactamente esos tokens, pero conceptualmente puede hacerlo.

Construiremos una clase:


# 8. Primera pieza: convertir un string en bytes

Creamos una función pequeña:

```js
function toBytes(text) {
  return [...Buffer.from(text, "utf8")];
}
```

Ejemplo:

```js
console.log(toBytes("hola"));
```

Resultado:

```text
[104, 111, 108, 97]
```

Para reconstruir el texto:

```js
function fromBytes(bytes) {
  return Buffer.from(bytes).toString("utf8");
}
```

Entonces:

```js
const bytes = toBytes("hola");

console.log(fromBytes(bytes));
```

produce:

```text
hola
```

Esta ida y vuelta será la base de todo el tokenizer.

---

# 9. Contar pares

Supongamos que tenemos:

```js
const tokens = [98, 97, 110, 97, 110, 97];
```

Queremos contar:

```text
98,97
97,110
110,97
97,110
110,97
```

Podemos usar un `Map`.

```js
function countPairs(tokens) {
  const counts = new Map();

  for (let i = 0; i < tokens.length - 1; i++) {
    const key = `${tokens[i]},${tokens[i + 1]}`;

    counts.set(key, (counts.get(key) ?? 0) + 1);
  }

  return counts;
}
```

La clave:

```js
"97,110"
```

representa el par:

```js
[97, 110]
```

No es la representación más eficiente posible.

Es simplemente una representación muy fácil de entender.

---

# 10. Encontrar el par más frecuente

Ahora buscamos el máximo.

```js
function mostFrequentPair(tokens) {
  const counts = countPairs(tokens);

  let bestPair = null;
  let bestCount = 0;

  for (const [pair, count] of counts) {
    if (count > bestCount) {
      bestPair = pair;
      bestCount = count;
    }
  }

  if (bestPair === null) {
    return null;
  }

  return bestPair.split(",").map(Number);
}
```

Si:

```js
tokens = [98, 97, 110, 97, 110, 97];
```

podría devolver:

```js
[97, 110]
```

---

# 11. Fusionar un par

Ahora necesitamos transformar:

```text
98 97 110 97 110 97
```

usando:

```text
97 110 -> 256
```

para obtener:

```text
98 256 256 97
```

La función es:

```js
function mergePair(tokens, pair, newToken) {
  const result = [];

  for (let i = 0; i < tokens.length; i++) {
    if (
      i < tokens.length - 1 &&
      tokens[i] === pair[0] &&
      tokens[i + 1] === pair[1]
    ) {
      result.push(newToken);
      i++;
    } else {
      result.push(tokens[i]);
    }
  }

  return result;
}
```

El detalle importante es:

```js
i++;
```

Cuando encontramos el par consumimos dos tokens.

Por eso debemos saltar el segundo.

---

# 12. El aprendizaje completo

Ya tenemos las piezas fundamentales.

El entrenamiento será:

```text
texto
 ↓
bytes
 ↓
buscar par más frecuente
 ↓
crear token
 ↓
fusionar
 ↓
repetir
```

Nuestro primer token nuevo será:

```text
256
```

porque los valores:

```text
0..255
```

ya están reservados para bytes.

# 13. Nuestra clase BPE

Vamos ahora a reunir todo.

```js
class BPE {
  constructor() {
    this.merges = [];
  }

  train(text, mergeCount) {
    let tokens = [...Buffer.from(text, "utf8")];

    this.merges = [];

    for (let n = 0; n < mergeCount; n++) {
      const pair = this.findBestPair(tokens);

      if (!pair) {
        break;
      }

      const newToken = 256 + this.merges.length;

      this.merges.push({
        pair,
        token: newToken
      });

      tokens = this.merge(tokens, pair, newToken);
    }
  }

  encode(text) {
    let tokens = [...Buffer.from(text, "utf8")];

    for (const merge of this.merges) {
      tokens = this.merge(
        tokens,
        merge.pair,
        merge.token
      );
    }

    return tokens;
  }

  decode(tokens) {
    const bytes = [];

    for (const token of tokens) {
      this.expand(token, bytes);
    }

    return Buffer.from(bytes).toString("utf8");
  }

  findBestPair(tokens) {
    const counts = new Map();

    for (let i = 0; i < tokens.length - 1; i++) {
      const key = `${tokens[i]},${tokens[i + 1]}`;

      counts.set(
        key,
        (counts.get(key) ?? 0) + 1
      );
    }

    let bestPair = null;
    let bestCount = 0;

    for (const [key, count] of counts) {
      if (count > bestCount) {
        bestPair = key;
        bestCount = count;
      }
    }

    if (bestPair === null) {
      return null;
    }

    return bestPair.split(",").map(Number);
  }

  merge(tokens, pair, newToken) {
    const result = [];

    for (let i = 0; i < tokens.length; i++) {
      if (
        i < tokens.length - 1 &&
        tokens[i] === pair[0] &&
        tokens[i + 1] === pair[1]
      ) {
        result.push(newToken);
        i++;
      } else {
        result.push(tokens[i]);
      }
    }

    return result;
  }

  expand(token, bytes) {
    if (token < 256) {
      bytes.push(token);
      return;
    }

    const merge = this.merges[token - 256];

    this.expand(merge.pair[0], bytes);
    this.expand(merge.pair[1], bytes);
  }
}
```

Esta es prácticamente toda la implementación.

El resto consiste en entender por qué funciona.

---

# 14. Cómo aprende `train`

Consideremos:

```js
const bpe = new BPE();

bpe.train("banana banana banana", 5);
```

Primero ejecutamos:

```js
Buffer.from(text, "utf8")
```

y obtenemos bytes.

Luego repetimos:

```js
const pair = this.findBestPair(tokens);
```

Por ejemplo podría aparecer:

```js
[97, 110]
```

Creamos:

```js
const newToken = 256;
```

y guardamos:

```js
{
  pair: [97, 110],
  token: 256
}
```

Conceptualmente:

```text
256 = 97 + 110
```

o, interpretado como texto:

```text
256 = "an"
```

Después reemplazamos las apariciones.

Luego buscamos nuevamente el par más frecuente.

El segundo token nuevo será:

```text
257
```

el tercero:

```text
258
```

y así sucesivamente.

---

# 15. La tabla de fusiones es el modelo aprendido

Después de entrenar:

```js
console.log(bpe.merges);
```

podríamos obtener algo parecido a:

```js
[
  { pair: [97, 110], token: 256 },
  { pair: [98, 256], token: 257 },
  { pair: [256, 97], token: 258 }
]
```

Esto significa:

```text
256 = [97,110]
257 = [98,256]
258 = [256,97]
```

Es importante entender esto:

> BPE no aprende una red neuronal.

Aprende una **lista ordenada de fusiones**.

Ese es su modelo.

---

# 16. Cómo funciona `encode`

Supongamos que ya aprendimos:

```text
97 110 -> 256
98 256 -> 257
```

Codificamos:

```js
bpe.encode("banana");
```

Primero:

```text
banana
```

se convierte en:

```text
98 97 110 97 110 97
```

Aplicamos la primera regla:

```text
97 110 -> 256
```

y obtenemos:

```text
98 256 256 97
```

Después aplicamos:

```text
98 256 -> 257
```

obteniendo:

```text
257 256 97
```

Y esos son los tokens finales.

La parte crucial es esta:

```js
for (const merge of this.merges) {
  tokens = this.merge(tokens, merge.pair, merge.token);
}
```

Las reglas se aplican **en el mismo orden en que fueron aprendidas**.

---

# 17. ¿Por qué importa el orden?

Supongamos:

```text
256 = "an"
257 = "ban"
```

El token `257` depende del `256`.

Es decir:

```text
257 = [98,256]
```

No podríamos crear `257` antes de haber creado `256`.

Por eso las reglas BPE tienen un orden.

---

# 18. Cómo funciona `decode`

Decodificar parece más complicado, pero en realidad es muy simple.

Recordemos:

```text
257 = [98,256]
256 = [97,110]
```

Entonces:

```text
257
```

se expande como:

```text
98 256
```

y `256` se expande como:

```text
97 110
```

Resultado:

```text
98 97 110
```

que en UTF-8 representa:

```text
ban
```

Nuestra función:

```js
expand(token, bytes)
```

hace esto recursivamente.

---

# 19. El caso base de la recursión

La función empieza:

```js
if (token < 256) {
  bytes.push(token);
  return;
}
```

Si el token es menor que `256`, ya es un byte original.

No hay nada más que expandir.

Este es el **caso base**.

---

# 20. El caso recursivo

Si:

```js
token >= 256
```

entonces es un token aprendido.

Buscamos su regla:

```js
const merge = this.merges[token - 256];
```

Por ejemplo:

```text
token = 257
```

entonces:

```text
257 - 256 = 1
```

y buscamos:

```js
this.merges[1]
```

Luego expandimos las dos partes:

```js
this.expand(merge.pair[0], bytes);
this.expand(merge.pair[1], bytes);
```

Eventualmente todo termina convertido en bytes originales.

---

# 21. Ejemplo completo ejecutable

Guardemos:

```js
// bpe.js

class BPE {
  constructor() {
    this.merges = [];
  }

  train(text, mergeCount) {
    let tokens = [...Buffer.from(text, "utf8")];

    this.merges = [];

    for (let n = 0; n < mergeCount; n++) {
      const pair = this.findBestPair(tokens);

      if (!pair) break;

      const newToken = 256 + this.merges.length;

      this.merges.push({
        pair,
        token: newToken
      });

      tokens = this.merge(tokens, pair, newToken);
    }
  }

  encode(text) {
    let tokens = [...Buffer.from(text, "utf8")];

    for (const { pair, token } of this.merges) {
      tokens = this.merge(tokens, pair, token);
    }

    return tokens;
  }

  decode(tokens) {
    const bytes = [];

    for (const token of tokens) {
      this.expand(token, bytes);
    }

    return Buffer.from(bytes).toString("utf8");
  }

  findBestPair(tokens) {
    const counts = new Map();

    for (let i = 0; i < tokens.length - 1; i++) {
      const key = `${tokens[i]},${tokens[i + 1]}`;

      counts.set(
        key,
        (counts.get(key) ?? 0) + 1
      );
    }

    let bestPair = null;
    let bestCount = 0;

    for (const [key, count] of counts) {
      if (count > bestCount) {
        bestPair = key;
        bestCount = count;
      }
    }

    if (bestPair === null) {
      return null;
    }

    return bestPair.split(",").map(Number);
  }

  merge(tokens, pair, newToken) {
    const result = [];

    for (let i = 0; i < tokens.length; i++) {
      if (
        i < tokens.length - 1 &&
        tokens[i] === pair[0] &&
        tokens[i + 1] === pair[1]
      ) {
        result.push(newToken);
        i++;
      } else {
        result.push(tokens[i]);
      }
    }

    return result;
  }

  expand(token, bytes) {
    if (token < 256) {
      bytes.push(token);
      return;
    }

    const { pair } = this.merges[token - 256];

    this.expand(pair[0], bytes);
    this.expand(pair[1], bytes);
  }
}
```

Nuestro algoritmo trabaja con bytes UTF-8.

Por eso también funciona con:

```js
const text = "mañana 😀";
```

Podemos comprobar:

```js
const tokens = bpe.encode(text);

console.log(tokens);
```

```text
mañana 😀
```

# 23. Qué significa realmente un token

Al principio:

```text
token 97 = byte 97
```

y ese byte representa:

```text
"a"
```

Pero después:

```text
token 256
```

podría representar:

```text
"an"
```

y:

```text
token 257
```

podría representar:

```text
"ban"
```

y otro token podría representar:

```text
"banana"
```

Por lo tanto un token no es necesariamente:

- una letra;
- una sílaba;
- una palabra.

Es simplemente:

> una secuencia de bytes que el algoritmo decidió que era útil agrupar.

---

# 24. ¿Por qué esto reduce la cantidad de tokens?

Supongamos que usamos únicamente bytes:

```text
banana
```

requiere:

```text
6 tokens
```

Después de aprender ciertas fusiones podríamos obtener:

```text
[257, 258]
```

es decir:

```text
2 tokens
```

Cuanto más frecuente es una secuencia en el corpus de entrenamiento, mayor es la posibilidad de que BPE termine representándola con pocos tokens.

---

# 25. El compromiso fundamental

Si hacemos pocas fusiones:

```text
vocabulario pequeño
muchos tokens por texto
```

Si hacemos muchas fusiones:

```text
vocabulario grande
menos tokens por texto
```

Ese es uno de los compromisos fundamentales de un tokenizer.

En nuestro programa:

```js
bpe.train(text, 100);
```

aprende cien fusiones.

El vocabulario total tendría como máximo:

```text
256 + 100 = 356 tokens
```

---

# 26. Una pequeña mejora: no fusionar pares que aparecen una sola vez

Nuestra versión actual aprende el par más frecuente aunque aparezca una sola vez.

Para fines educativos esto simplifica el código.

Pero podemos detenernos cuando el mejor par tenga frecuencia menor que `2`.

Podríamos modificar:

```js
findBestPair()
```

para devolver también la frecuencia:

```js
return {
  pair: bestPair.split(",").map(Number),
  count: bestCount
};
```

y durante entrenamiento hacer:

```js
if (!best || best.count < 2) {
  break;
}
```

Así solo aprendemos patrones que realmente se repiten.

No es necesario para comprender el algoritmo básico.

---

# 27. Qué hemos simplificado

Esta implementación está diseñada para mostrar el algoritmo, no para competir con tokenizadores de producción.

Deliberadamente omitimos:

- optimizaciones de rendimiento;
- estructuras especiales para contar pares;
- pretokenización;
- reglas especiales para espacios;
- regex complejas;
- tokens reservados;
- almacenamiento del vocabulario en archivos;
- entrenamiento con corpus enormes;
- paralelización;
- codificación incremental.

La esencia de BPE permanece intacta:

```text
bytes
  ↓
contar pares
  ↓
fusionar el más frecuente
  ↓
guardar la regla
  ↓
repetir
```

---

# 28. La idea completa en pseudocódigo

El entrenamiento entero puede escribirse conceptualmente así:

```text
tokens = UTF8(texto)

repetir N veces:

    contar pares consecutivos

    elegir el más frecuente

    crear nuevo token

    guardar:
        par -> nuevo token

    reemplazar el par
```

Codificar:

```text
tokens = UTF8(texto)

para cada regla aprendida:

    aplicar la fusión

devolver tokens
```

Decodificar:

```text
para cada token:

    si es byte:
        devolver byte

    si es token aprendido:
        expandir sus dos componentes

convertir bytes UTF-8 a string
```

Eso es BPE en su forma esencial.

# 29. La clase mínima final

Si eliminamos explicaciones y dejamos solamente el núcleo del algoritmo:

```js
class BPE {
  constructor() {
    this.merges = [];
  }

  train(text, mergeCount) {
    let tokens = [...Buffer.from(text)];

    this.merges = [];

    for (let n = 0; n < mergeCount; n++) {
      const counts = new Map();

      for (let i = 0; i < tokens.length - 1; i++) {
        const key = `${tokens[i]},${tokens[i + 1]}`;
        counts.set(key, (counts.get(key) ?? 0) + 1);
      }

      let best = null;
      let max = 0;

      for (const [key, count] of counts) {
        if (count > max) {
          best = key;
          max = count;
        }
      }

      if (!best) break;

      const pair = best.split(",").map(Number);
      const token = 256 + this.merges.length;

      this.merges.push({ pair, token });

      tokens = this.merge(tokens, pair, token);
    }
  }

  encode(text) {
    let tokens = [...Buffer.from(text)];

    for (const { pair, token } of this.merges) {
      tokens = this.merge(tokens, pair, token);
    }

    return tokens;
  }

  decode(tokens) {
    const bytes = [];

    const expand = token => {
      if (token < 256) {
        bytes.push(token);
        return;
      }

      const { pair } = this.merges[token - 256];

      expand(pair[0]);
      expand(pair[1]);
    };

    for (const token of tokens) {
      expand(token);
    }

    return Buffer.from(bytes).toString("utf8");
  }

  merge(tokens, pair, newToken) {
    const result = [];

    for (let i = 0; i < tokens.length; i++) {
      if (
        tokens[i] === pair[0] &&
        tokens[i + 1] === pair[1]
      ) {
        result.push(newToken);
        i++;
      } else {
        result.push(tokens[i]);
      }
    }

    return result;
  }
}
```

Esta versión contiene prácticamente todo lo conceptualmente importante de BPE.

# 30. Qué conviene recordar

No memorices el código.

Recordá el proceso:

```text
texto
  ↓
UTF-8
  ↓
bytes
  ↓
pares frecuentes
  ↓
fusiones
  ↓
tokens cada vez mayores
```

El punto central es este:

> BPE construye un vocabulario descubriendo secuencias frecuentes a partir de unidades elementales.

Al trabajar sobre bytes obtenemos además una propiedad extremadamente útil:

> cualquier texto Unicode puede ser representado, incluso si contiene caracteres o palabras nunca vistos durante el entrenamiento.

Y finalmente, las tres operaciones de nuestro tokenizer son:

```js
bpe.train(textoBase, cantidadDeFusiones);

const tokens = bpe.encode(texto);

const textoOriginal = bpe.decode(tokens);
```

Ese pequeño ciclo contiene la esencia de un tokenizer BPE.
