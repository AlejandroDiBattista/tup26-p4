# Gestión de archivos con JavaScript y Node.js

Cuando un programa maneja archivos está haciendo algo conceptualmente muy simple:

> **guardar bytes en un dispositivo y recuperarlos posteriormente.**

Todo lo demás —archivos de texto, JSON, imágenes, carpetas, copiar, buscar, renombrar— se construye sobre esa idea.

En Node.js, la API fundamental para hacerlo es `fs` (**file system**). Node ofrece versiones síncronas, basadas en callbacks y basadas en `Promise`. Para programas modernos usaremos normalmente:

```js
import fs from "node:fs/promises";
```

Esto nos permite trabajar naturalmente con `async`/`await`.

---

# 1. ¿Qué es realmente un archivo?

Para el sistema operativo un archivo puede imaginarse como:

```text
nombre
   ↓
datos almacenados
   ↓
01001000 01101111 01101100 01100001
```

Esos datos son **bytes**.

Un archivo no sabe si contiene:

- texto;
- una imagen;
- audio;
- JSON;
- un programa;
- un PDF.

Sólo contiene bytes.

Por ejemplo:

```text
48 6F 6C 61
```

son cuatro bytes expresados en hexadecimal.

Si los interpretamos como UTF-8 obtenemos:

```text
Hola
```

La distinción importante es:

```text
archivo
    ↓
bytes
    ↓
interpretación
```

Por eso podemos leer un archivo de dos maneras fundamentales en Node:

```js
const datos = await fs.readFile("archivo.txt");
```

o:

```js
const texto = await fs.readFile("archivo.txt", "utf8");
```

En el primer caso obtenemos bytes.

En el segundo le estamos diciendo:

> Leé los bytes e interpretalos como texto UTF-8.

---

# 2. Nuestro primer archivo

Creemos un programa:

```text
proyecto/
└── index.js
```

Y escribamos:

```js
import fs from "node:fs/promises";

await fs.writeFile("saludo.txt", "Hola mundo");
```

Ejecutamos:

```bash
node index.js
```

Aparecerá:

```text
proyecto/
├── index.js
└── saludo.txt
```

con:

```text
Hola mundo
```

`writeFile()` crea el archivo si no existe.

Si ya existe, por defecto reemplaza su contenido.

---

# 3. Escribir texto

Podemos especificar explícitamente la codificación:

```js
await fs.writeFile(
    "saludo.txt",
    "Hola mundo",
    "utf8"
);
```

Aunque para strings UTF-8 es el valor predeterminado de `writeFile()`.

Podemos escribir cualquier string JavaScript:

```js
const contenido = `
Nombre: Ana
Edad: 25
Ciudad: Tucumán
`;

await fs.writeFile("persona.txt", contenido, "utf8");
```

El archivo resultante será:

```text
Nombre: Ana
Edad: 25
Ciudad: Tucumán
```

---

# 4. Leer un archivo de texto

Leerlo es exactamente la operación inversa:

```js
const contenido = await fs.readFile(
    "persona.txt",
    "utf8"
);

console.log(contenido);
```

Obtenemos un `string`.

Sin `"utf8"`:

```js
const contenido = await fs.readFile("persona.txt");

console.log(contenido);
```

obtendríamos aproximadamente:

```text
<Buffer 4e 6f 6d 62 72 65 ...>
```

Un `Buffer` representa bytes.

Podemos convertirlo después:

```js
const bytes = await fs.readFile("persona.txt");

const texto = bytes.toString("utf8");

console.log(texto);
```

Esto evidencia algo importante:

```text
archivo
   ↓
bytes
   ↓
Buffer
   ↓ UTF-8
string
```

---

# 5. ¿Qué es una codificación?

Supongamos que queremos guardar:

```text
A
```

Unicode identifica `A` mediante el código:

```text
U+0041
```

Pero un disco solamente guarda bytes.

UTF-8 establece cómo convertir ese código Unicode en bytes:

```text
A
↓
U+0041
↓ UTF-8
41
```

Otro ejemplo:

```text
ñ
↓
U+00F1
↓ UTF-8
C3 B1
```

Y un emoji puede necesitar todavía más bytes:

```text
😀
↓
U+1F600
↓ UTF-8
F0 9F 98 80
```

Por eso:

```js
Buffer.from("A").length
```

produce:

```text
1
```

pero:

```js
Buffer.from("ñ").length
```

produce:

```text
2
```

y:

```js
Buffer.from("😀").length
```

produce:

```text
4
```

UTF-8 es una codificación de longitud variable.

---

# 6. Texto JavaScript y texto almacenado

Aquí aparece una distinción fundamental.

Dentro de JavaScript tenemos:

```js
const texto = "Hola 😀";
```

Eso es un `string`.

Cuando queremos guardarlo:

```js
await fs.writeFile("texto.txt", texto, "utf8");
```

Node realiza aproximadamente:

```text
JavaScript string
        ↓
codificación UTF-8
        ↓
bytes
        ↓
archivo
```

Cuando lo leemos:

```js
const texto = await fs.readFile(
    "texto.txt",
    "utf8"
);
```

ocurre lo contrario:

```text
archivo
   ↓
bytes
   ↓
decodificación UTF-8
   ↓
JavaScript string
```

La codificación es, por tanto, **el convenio que permite pasar entre caracteres y bytes**.

---

# 7. Agregar información sin borrar lo anterior

Esto:

```js
await fs.writeFile("log.txt", "primero");
await fs.writeFile("log.txt", "segundo");
```

deja solamente:

```text
segundo
```

porque la segunda escritura reemplaza el archivo.

Para agregar información usamos:

```js
await fs.appendFile(
    "log.txt",
    "Nueva línea\n",
    "utf8"
);
```

Por ejemplo:

```js
await fs.appendFile("log.txt", "Inicio\n");
await fs.appendFile("log.txt", "Usuario conectado\n");
await fs.appendFile("log.txt", "Fin\n");
```

produce:

```text
Inicio
Usuario conectado
Fin
```

Esto es especialmente útil para:

- logs;
- historiales;
- registros;
- archivos CSV.

---

# 8. El problema de los saltos de línea

Históricamente los sistemas operativos no utilizaron exactamente la misma representación.

Unix, Linux y macOS modernos utilizan:

```text
LF
```

representado como:

```js
"\n"
```

Windows tradicionalmente utiliza:

```text
CR + LF
```

es decir:

```js
"\r\n"
```

Por eso un archivo puede contener:

```text
uno\n
dos\n
tres\n
```

o:

```text
uno\r\n
dos\r\n
tres\r\n
```

Una manera robusta de separar líneas es:

```js
const lineas = texto.split(/\r?\n/);
```

Acepta ambas variantes.

Node también expone:

```js
import os from "node:os";

console.log(os.EOL);
```

que devuelve el salto de línea convencional del sistema actual.

Sin embargo, para formatos interoperables suele ser perfectamente razonable utilizar simplemente:

```js
"\n"
```

en todas las plataformas.

---

# 9. Rutas de archivos

Un archivo se identifica mediante una **ruta**.

En Unix, Linux y macOS podemos encontrar:

```text
/home/ana/documentos/notas.txt
```

o:

```text
/Users/ana/documentos/notas.txt
```

En Windows:

```text
C:\Users\Ana\documentos\notas.txt
```

Aquí aparece uno de los principales problemas de portabilidad.

Windows suele utilizar:

```text
\
```

mientras que los sistemas POSIX utilizan:

```text
/
```

No deberíamos construir rutas así:

```js
const archivo = carpeta + "/" + nombre;
```

Node proporciona el módulo:

```js
import path from "node:path";
```

Entonces hacemos:

```js
const archivo = path.join(
    "datos",
    "usuarios",
    "ana.txt"
);
```

Node producirá la ruta apropiada para el sistema operativo.

Conceptualmente:

```text
path.join(...)
       ↓
ruta correcta para la plataforma
```

---

# 10. Rutas relativas y absolutas

Si escribimos:

```js
await fs.readFile("datos.txt", "utf8");
```

`datos.txt` es una **ruta relativa**.

Se interpreta respecto del directorio actual del proceso:

```js
console.log(process.cwd());
```

Por ejemplo:

```text
/Users/alejandro/proyecto
```

Entonces:

```text
datos.txt
```

significa:

```text
/Users/alejandro/proyecto/datos.txt
```

Podemos construir una ruta absoluta:

```js
const archivo = path.resolve("datos.txt");

console.log(archivo);
```

---

# 11. Analizar una ruta

Supongamos:

```js
const archivo = "/usuarios/ana/documentos/informe.pdf";
```

Podemos obtener distintas partes.

Nombre:

```js
path.basename(archivo);
```

Resultado:

```text
informe.pdf
```

Directorio:

```js
path.dirname(archivo);
```

Resultado:

```text
/usuarios/ana/documentos
```

Extensión:

```js
path.extname(archivo);
```

Resultado:

```text
.pdf
```

Esto es muy útil para clasificar archivos.

Por ejemplo:

```js
const extension = path.extname("foto.jpg");

if (extension === ".jpg") {
    console.log("Es una imagen JPEG");
}
```

# 12. Crear directorios

Podemos crear una carpeta:

```js
await fs.mkdir("datos");
```

Pero fallará si ya existe.

Normalmente hacemos:

```js
await fs.mkdir("datos", {
    recursive: true
});
```

Además permite crear varios niveles:

```js
await fs.mkdir(
    path.join("datos", "usuarios", "imagenes"),
    { recursive: true }
);
```

# 14. Saber si algo es archivo o directorio

Un directorio puede contener ambos:

```text
datos/
├── usuarios/
├── imagenes/
└── config.json
```

Podemos pedir información adicional:

```js
const elementos = await fs.readdir(
    "datos",
    { withFileTypes: true }
);
```

Entonces:

```js
for (const elemento of elementos) {

    if (elemento.isFile()) {
        console.log("Archivo:", elemento.name);
    }

    if (elemento.isDirectory()) {
        console.log("Directorio:", elemento.name);
    }
}
```

# 15. Obtener información sobre un archivo

Usamos:

```js
const info = await fs.stat("datos.txt");
```

Podemos consultar:

```js
console.log(info.size);
console.log(info.mtime);
console.log(info.birthtime);
```

y:

```js
console.log(info.isFile());
console.log(info.isDirectory());
```

Por ejemplo:

```js
const info = await fs.stat("datos.txt");

console.log(`Tamaño: ${info.size} bytes`);
console.log(`Modificado: ${info.mtime}`);
```

Hay que tener cuidado con algunos metadatos: su significado y disponibilidad exactos pueden variar entre sistemas de archivos y sistemas operativos.

# 16. Copiar un archivo

Node tiene una operación específica:

```js
await fs.copyFile(
    "original.txt",
    "copia.txt"
);
```

Para copiar estructuras completas existe:

```js
await fs.cp(
    "origen",
    "destino",
    { recursive: true }
);
```

# 17. Renombrar un archivo

```js
await fs.rename(
    "viejo.txt",
    "nuevo.txt"
);
```

Pero `rename()` también permite moverlo:

```js
await fs.rename(
    "datos.txt",
    path.join("backup", "datos.txt")
);
```

¿Por qué?

Porque para el sistema de archivos **renombrar y mover son esencialmente variaciones de modificar la ruta asociada a una entrada**.

---

# 18. Eliminar archivos

```js
await fs.unlink("datos.txt");
```

Otra API más general es:

```js
await fs.rm("datos.txt");
```

Para eliminar un directorio completo:

```js
await fs.rm(
    "datos",
    {
        recursive: true,
        force: true
    }
);
```

Hay que tratar esta operación con respeto: Node no manda mágicamente el contenido a una papelera portátil. Puede eliminarlo directamente.

---

# 19. Comprobar si existe un archivo

Es tentador hacer:

```js
if (archivoExiste) {
    // abrir
}
```

pero entre la comprobación y la apertura otro proceso podría eliminarlo.

En muchas situaciones es mejor **intentar directamente la operación**:

```js
try {

    const texto = await fs.readFile(
        "config.txt",
        "utf8"
    );

    console.log(texto);

} catch (error) {

    console.error("No pude leer el archivo");
}
```

Los sistemas de archivos pueden cambiar mientras nuestro programa se ejecuta.

Esto introduce una idea general importante:

> Las operaciones con archivos pueden fallar y ese fallo forma parte normal del problema.

---

# 20. Los códigos de error

Podemos inspeccionar:

```js
try {

    await fs.readFile("inexistente.txt");

} catch (error) {

    console.log(error.code);
}
```

Podríamos obtener:

```text
ENOENT
```

Entonces:

```js
try {

    const texto = await fs.readFile(
        "config.txt",
        "utf8"
    );

} catch (error) {

    if (error.code === "ENOENT") {
        console.log("El archivo no existe");
    } else {
        throw error;
    }
}
```

Es mejor discriminar el error que asumir que todo fallo significa "archivo inexistente".

También podríamos tener:

- falta de permisos;
- ruta inválida;
- disco lleno;
- dispositivo desconectado;
- archivo bloqueado;
- errores de entrada/salida.

# 21. Buscar archivos por nombre o extensión

Supongamos:

```text
documentos/
├── informe.txt
├── notas.md
├── foto.png
└── alumnos.txt
```

Podemos buscar todos los `.txt`:

```js
const archivos = await fs.readdir("documentos");

const textos = archivos.filter(
    nombre => path.extname(nombre) === ".txt"
);

console.log(textos);
```

Resultado:

```js
[
    "informe.txt",
    "alumnos.txt"
]
```

También podemos buscar por nombre:

```js
const encontrados = archivos.filter(
    nombre => nombre.includes("informe")
);
```

# 22. Búsqueda recursiva

Ahora tenemos:

```text
documentos/
├── informe.txt
├── universidad/
│   ├── alumnos.txt
│   └── notas/
│       └── parcial.txt
└── personal/
    └── compras.txt
```

Para recorrer todo el árbol podemos usar recursividad:

```js
async function buscar(directorio) {

    const elementos = await fs.readdir(
        directorio,
        { withFileTypes: true }
    );

    const archivos = [];

    for (const elemento of elementos) {

        const ruta = path.join(
            directorio,
            elemento.name
        );

        if (elemento.isDirectory()) {

            const encontrados = await buscar(ruta);

            archivos.push(...encontrados);

        } else {

            archivos.push(ruta);
        }
    }

    return archivos;
}
```

Uso:

```js
const archivos = await buscar("documentos");

console.log(archivos);
```

Conceptualmente estamos recorriendo un árbol:

```text
documentos
│
├── informe.txt
│
├── universidad
│   ├── alumnos.txt
│   └── notas
│       └── parcial.txt
│
└── personal
    └── compras.txt
```

Un directorio contiene otros nodos, algunos de los cuales contienen a su vez otros nodos.

Por eso la recursividad encaja naturalmente.

# 23. Buscar texto dentro de archivos

Ahora ya sabemos encontrar archivos.

Podemos además examinar su contenido.

```js
async function contieneTexto(
    archivo,
    buscado
) {

    const texto = await fs.readFile(
        archivo,
        "utf8"
    );

    return texto.includes(buscado);
}
```

Uso:

```js
if (await contieneTexto(
    "informe.txt",
    "JavaScript"
)) {
    console.log("Encontrado");
}
```

Podemos combinar ambos conceptos:

```text
recorrer directorios
        ↓
seleccionar .txt
        ↓
leer cada archivo
        ↓
buscar una expresión
```

Eso es esencialmente la base de herramientas como buscadores de código, indexadores y utilidades parecidas a `grep`.

# 24. Buscar línea por línea

Supongamos:

```text
Juan,25,Tucumán
Ana,31,Salta
Pedro,19,Córdoba
```

Podemos hacer:

```js
const texto = await fs.readFile(
    "personas.txt",
    "utf8"
);

const lineas = texto.split(/\r?\n/);

for (const linea of lineas) {

    if (linea.includes("Ana")) {
        console.log(linea);
    }
}
```

Resultado:

```text
Ana,31,Salta
```

# 25. Extraer información

Un archivo de texto suele contener **estructura**.

Por ejemplo:

```text
Ana,31,Tucumán
Juan,25,Salta
```

Primero obtenemos líneas:

```js
const lineas = texto.split(/\r?\n/);
```

Después campos:

```js
for (const linea of lineas) {

    const campos = linea.split(",");

    console.log(campos);
}
```

Resultado:

```js
["Ana", "31", "Tucumán"]
["Juan", "25", "Salta"]
```

Podemos convertirlos en objetos:

```js
const personas = lineas.map(linea => {

    const [nombre, edad, ciudad] =
        linea.split(",");

    return {
        nombre,
        edad: Number(edad),
        ciudad
    };
});
```

Ahora tenemos:

```js
[
    {
        nombre: "Ana",
        edad: 31,
        ciudad: "Tucumán"
    },
    {
        nombre: "Juan",
        edad: 25,
        ciudad: "Salta"
    }
]
```

Aquí ocurrió una transformación fundamental:

```text
archivo
   ↓
texto
   ↓
líneas
   ↓
campos
   ↓
objetos
```

Gran parte del procesamiento de información consiste exactamente en esto.

---

# 26. Un CSV real es más complicado

El ejemplo anterior:

```js
linea.split(",");
```

sirve para aprender el principio, pero no constituye un parser CSV completo.

Porque esto es perfectamente válido en CSV:

```text
Ana,"San Miguel de Tucumán, Tucumán",31
```

La coma dentro de las comillas **no separa columnas**.

Por eso, para archivos CSV reales conviene utilizar una biblioteca especializada.

La lección general es:

> No confundamos el formato conceptual que estamos aprendiendo con toda la complejidad de una especificación real.

# 27. JSON: texto que representa datos

JSON también es simplemente texto.

Archivo:

```json
{
    "nombre": "Ana",
    "edad": 31
}
```

Podemos leerlo:

```js
const texto = await fs.readFile(
    "persona.json",
    "utf8"
);
```

y convertirlo:

```js
const persona = JSON.parse(texto);

console.log(persona.nombre);
```

El proceso es:

```text
archivo JSON
     ↓
bytes
     ↓ UTF-8
string
     ↓ JSON.parse
objeto JavaScript
```

Para guardar:

```js
const persona = {
    nombre: "Ana",
    edad: 31
};

const texto = JSON.stringify(
    persona,
    null,
    2
);

await fs.writeFile(
    "persona.json",
    texto,
    "utf8"
);
```

Aquí hacemos exactamente el recorrido inverso:

```text
objeto JavaScript
       ↓
JSON.stringify
       ↓
string
       ↓ UTF-8
bytes
       ↓
archivo
```

# 28. Archivos pequeños y archivos grandes

`readFile()` hace conceptualmente:

```text
archivo completo
       ↓
memoria
```

Esto es fantástico para:

```text
10 KB
1 MB
10 MB
```

Pero imaginemos:

```text
clientes.csv
80 GB
```

No queremos cargar 80 GB en RAM.

Necesitamos procesar el archivo **por partes**.

Aquí aparecen los streams.

---

# 29. Streams

Podemos imaginar un archivo grande así:

```text
████████████████████████████████████
```

`readFile()` intenta:

```text
████████████████████████████████████
                 ↓
               memoria
```

Un stream hace:

```text
█████ → procesar
█████ → procesar
█████ → procesar
█████ → procesar
...
```

Importamos:

```js
import fs from "node:fs";
```

y hacemos:

```js
const stream = fs.createReadStream(
    "archivo-grande.txt",
    { encoding: "utf8" }
);
```

Podemos consumirlo:

```js
for await (const fragmento of stream) {
    console.log(fragmento);
}
```

Cada `fragmento` contiene una parte del archivo.

Esto permite procesar datos cuyo tamaño puede ser mucho mayor que la memoria disponible.

---

# 30. Pero un fragmento no es una línea

Un error conceptual frecuente es pensar:

```text
chunk = línea
```

No.

El sistema puede entregar:

```text
Ana,31,Tucu
```

y después:

```text
mán\nJuan,25,S
```

El corte depende del flujo de bytes, no de nuestra estructura lógica.

Para leer líneas existe:

```js
import readline from "node:readline";
import fs from "node:fs";

const archivo = fs.createReadStream(
    "personas.txt"
);

const lineas = readline.createInterface({
    input: archivo,
    crlfDelay: Infinity
});

for await (const linea of lineas) {
    console.log(linea);
}
```

Esto resulta mucho más apropiado para archivos de texto grandes.

---

# 31. Síncrono contra asíncrono

Node ofrece, por ejemplo:

```js
fs.readFile(...)
```

con callbacks,

```js
await fs.promises.readFile(...)
```

con Promises,

y:

```js
fs.readFileSync(...)
```

de forma síncrona.

Una operación síncrona:

```js
import fs from "node:fs";

const texto = fs.readFileSync(
    "datos.txt",
    "utf8"
);
```

detiene la ejecución hasta terminar.

Conceptualmente:

```text
programa
   ↓
leer archivo
   ↓
ESPERAR
   ↓
continuar
```

Mientras:

```js
import fs from "node:fs/promises";

const texto = await fs.readFile(
    "datos.txt",
    "utf8"
);
```

utiliza la infraestructura asíncrona de Node.

Para scripts muy pequeños las funciones síncronas pueden ser cómodas.

Para servidores y aplicaciones concurrentes normalmente preferimos las APIs asíncronas.

---

# 32. File handles

Hasta ahora utilizamos operaciones de alto nivel:

```js
readFile()
writeFile()
appendFile()
```

Pero conceptualmente un sistema operativo suele trabajar así:

```text
abrir archivo
     ↓
obtener descriptor
     ↓
leer/escribir
     ↓
cerrar archivo
```

Node representa esta idea mediante `FileHandle`.

```js
const archivo = await fs.open(
    "datos.txt",
    "r"
);

try {

    const contenido =
        await archivo.readFile("utf8");

    console.log(contenido);

} finally {

    await archivo.close();
}
```

El cierre es importante.

Aquí estamos un nivel más cerca del sistema operativo.

---

# 33. Modos de apertura

Cuando abrimos un archivo indicamos nuestra intención.

Por ejemplo:

```js
await fs.open("datos.txt", "r");
```

`r`:

```text
read
```

Lectura.

```js
await fs.open("datos.txt", "w");
```

`w`:

```text
write
```

Escritura.

Puede crear el archivo y truncar el existente.

```js
await fs.open("datos.txt", "a");
```

`a`:

```text
append
```

Agregar al final.

La idea es importante:

> abrir un archivo no significa solamente encontrarlo; también establece cómo pretendemos utilizarlo.

# 34. Diferencias entre Windows, macOS y Linux

Node abstrae gran parte de las diferencias, pero no puede eliminarlas todas.

## Separador de rutas

Windows:

```text
C:\datos\archivo.txt
```

POSIX:

```text
/datos/archivo.txt
```

Solución:

```js
path.join(...)
```

## Raíz

Windows puede tener varias unidades:

```text
C:\
D:\
E:\
```

Unix/macOS tienen una raíz lógica:

```text
/
```

## Mayúsculas y minúsculas

En muchos sistemas Linux:

```text
Archivo.txt
```

y:

```text
archivo.txt
```

son archivos diferentes.

En configuraciones habituales de Windows y macOS pueden referirse al mismo archivo.

Por eso conviene **no depender de diferencias solamente de mayúsculas y minúsculas**.

## Caracteres permitidos

Windows impone restricciones particulares sobre algunos caracteres y nombres.

Por ejemplo, nombres como:

```text
CON
NUL
PRN
```

tienen significados históricos especiales.

Si nuestro programa crea nombres a partir de datos introducidos por usuarios debemos sanitizarlos.

## Permisos

Linux y macOS siguen fuertemente el modelo POSIX:

```text
lectura
escritura
ejecución
```

para distintos propietarios/grupos.

Windows posee su propio modelo de permisos.

Node intenta ofrecer una API uniforme, pero las semánticas no siempre son idénticas entre plataformas.

# 35. No escribamos rutas específicas del sistema

Evitemos:

```js
const archivo =
    "C:\\Users\\Alejandro\\datos\\clientes.txt";
```

porque sólo tiene sentido en una determinada computadora Windows.

Y también:

```js
const archivo =
    "/Users/alejandro/datos/clientes.txt";
```

porque presupone una estructura específica.

Mejor:

```js
const archivo = path.join(
    "datos",
    "clientes.txt"
);
```

o construirla desde una ubicación conocida dinámicamente.

# 36. La carpeta del usuario

Node puede obtener ubicaciones del sistema:

```js
import os from "node:os";

console.log(os.homedir());
```

Podría producir:

macOS:

```text
/Users/ana
```

Linux:

```text
/home/ana
```

Windows:

```text
C:\Users\Ana
```

Entonces:

```js
const archivo = path.join(
    os.homedir(),
    "mi-programa",
    "datos.json"
```

# 37. Construyamos una pequeña utilidad

Supongamos que queremos encontrar todos los `.txt` dentro de un directorio que contengan determinada palabra.

```js
import fs from "node:fs/promises";
import path from "node:path";

async function buscar(directorio, palabra) {

    const encontrados = [];

    const elementos = await fs.readdir(
        directorio,
        { withFileTypes: true }
    );

    for (const elemento of elementos) {

        const ruta = path.join(
            directorio,
            elemento.name
        );

        if (elemento.isDirectory()) {

            const internos =
                await buscar(ruta, palabra);

            encontrados.push(...internos);

            continue;
        }

        if (path.extname(elemento.name) !== ".txt") {
            continue;
        }

        const texto = await fs.readFile(
            ruta,
            "utf8"
        );

        if (texto.includes(palabra)) {
            encontrados.push(ruta);
        }
    }

    return encontrados;
}
```

Uso:

```js
const archivos = await buscar(
    "documentos",
    "JavaScript"
);

console.log(archivos);
```

Esta pequeña función reúne casi todos los conceptos fundamentales:

```text
directorio
    ↓
readdir
    ↓
archivo o directorio
    ↓
recursión
    ↓
path.extname
    ↓
readFile
    ↓
decodificar UTF-8
    ↓
buscar información
```

# 38. Extraer estadísticas de muchos archivos

Ahora podemos hacer algo más interesante:

```js
async function informacion(archivo) {

    const stat = await fs.stat(archivo);

    return {
        archivo,
        bytes: stat.size,
        modificado: stat.mtime
    };
}
```

Uso:

```js
const info = await informacion("datos.txt");

console.log(info);
```

Podemos empezar a construir programas que:

- indexen documentos;
- calculen tamaños;
- encuentren duplicados;
- generen catálogos;
- extraigan estadísticas;
- realicen backups;
- transformen formatos.

Todas estas aplicaciones nacen de las mismas operaciones elementales.

# 39. El modelo mental completo

Podemos resumir la gestión de archivos en cuatro niveles.

## Nivel 1 — bytes

El disco guarda:

```text
01001000
01101111
01101100
01100001
```

Node los puede representar mediante:

```js
Buffer
```

## Nivel 2 — texto

Una codificación interpreta esos bytes:

```text
bytes
 ↓ UTF-8
Hola
```

En JavaScript obtenemos:

```js
string
```

## Nivel 3 — estructura

El texto puede representar estructuras:

```text
Ana,31,Tucumán
```

que interpretamos como:

```js
{
    nombre: "Ana",
    edad: 31,
    ciudad: "Tucumán"
}
```

## Nivel 4 — sistema de archivos

Los archivos están organizados mediante:

```text
directorios
    ↓
subdirectorios
    ↓
archivos
```

y los manipulamos mediante rutas.

En Node:

```text
Buffer       → bytes
string       → texto
fs           → archivos
path         → rutas
readline     → texto por líneas
streams      → datos grandes
```

# 40. Las operaciones fundamentales

Prácticamente toda la gestión cotidiana de archivos se reduce a estas operaciones:

```js
// crear / escribir
await fs.writeFile(archivo, datos);

// agregar
await fs.appendFile(archivo, datos);

// leer
await fs.readFile(archivo, "utf8");

// crear directorio
await fs.mkdir(directorio);

// listar
await fs.readdir(directorio);

// información
await fs.stat(archivo);

// copiar
await fs.copyFile(origen, destino);

// mover / renombrar
await fs.rename(origen, destino);

// eliminar
await fs.rm(archivo);

// construir rutas portables
path.join(...partes);
```

Node proporciona las tres variantes principales de acceso al sistema de archivos —síncrona, callback y `Promise`—; para código moderno general, `node:fs/promises` da una interfaz especialmente cómoda con `async/await`.

---

# 41. La idea más importante

No conviene aprender estas funciones como una colección de comandos independientes.

Hay un modelo mucho más simple:

```text
                    SISTEMA DE ARCHIVOS
                           │
                 ┌─────────┴─────────┐
                 │                   │
             directorios          archivos
                 │                   │
               rutas               bytes
                                     │
                                  encoding
                                     │
                                   texto
                                     │
                                  parsing
                                     │
                                    datos
```

De ahí salen casi todas las operaciones:

```text
crear
leer
escribir
agregar
copiar
mover
renombrar
eliminar
listar
buscar
clasificar
extraer
transformar
```

Cuando entendemos esa jerarquía, `fs` deja de parecer una API llena de funciones arbitrarias.

En realidad, todas responden a una misma pregunta:

> **¿Cómo transforma mi programa una estructura de bytes almacenada por el sistema operativo en información que JavaScript pueda manipular, y cómo realiza luego el camino inverso?**

Ese es el fundamento de la gestión de archivos.
