# Gestión de archivos con JavaScript y Node.js

Este tutorial parte de una idea central:

> **Un archivo no contiene texto, imágenes, objetos JSON ni registros. Un archivo contiene bytes.**

“Texto”, “imagen”, “PDF” o “JSON” son interpretaciones de esos bytes.

A lo largo del tutorial usaremos exclusivamente módulos nativos de Node.js:

```js
import * as path from 'node:path';
import {
  appendFile,
  copyFile,
  cp,
  mkdir,
  open,
  readFile,
  readdir,
  rename,
  rm,
  stat,
  writeFile,
} from 'node:fs/promises';

import {
  constants,
  createReadStream,
} from 'node:fs';

import { createInterface } from 'node:readline';
```

Los ejemplos utilizan módulos ES. Podés guardarlos en archivos con extensión `.mjs` y ejecutarlos así:

```bash
node programa.mjs
```

De esa forma no hace falta configurar `package.json`.

# 1. ¿Qué es realmente un archivo?

Conceptualmente, un archivo es:

```text
una secuencia finita de bytes
+
metadatos
```

Los metadatos incluyen, según el sistema de archivos:

- nombre;
- tamaño;
- fechas de acceso y modificación;
- permisos;
- propietario;
- ubicación dentro de un directorio;
- indicador de archivo, directorio o enlace simbólico.

Un directorio, por su parte, organiza nombres y referencias a otros archivos o directorios.

Podemos imaginar esta estructura:

```text
proyecto/
├── alumnos.json
├── notas.txt
└── imagenes/
    └── logo.png
```

Aquí:

- `proyecto` es un directorio;
- `notas.txt` es un archivo;
- `proyecto/notas.txt` es una ruta;
- `.txt` es una extensión.

La extensión es solamente una convención. Nada impide guardar una imagen con el nombre `foto.txt`. La extensión es una etiqueta, no un detector de mentiras.

## Las capas de interpretación

Tomemos este archivo:

```text
datos/clientes.json
```

Podemos verlo en distintos niveles:

```text
Ruta
  ↓
Archivo
  ↓
Bytes
  ↓ decodificación UTF-8
Texto
  ↓ análisis de JSON
Objetos y arrays
  ↓ interpretación del programa
Clientes, nombres y direcciones
```

Cada operación trabaja en una capa diferente:

| Operación | Capa principal |
|---|---|
| Renombrar | Ruta |
| Copiar | Bytes |
| Leer como texto | Codificación |
| Buscar una palabra | Texto |
| Interpretar JSON | Formato |
| Extraer clientes morosos | Información del dominio |

Esto explica por qué copiar un archivo no necesita conocer su codificación, pero buscar una palabra sí.

# 2. Abrir, operar y cerrar

En un nivel bajo, para trabajar con un archivo el sistema operativo realiza aproximadamente este proceso:

```text
1. Localizar la ruta.
2. Abrir el archivo.
3. Obtener un descriptor o manejador.
4. Leer o escribir bytes.
5. Cerrar el manejador.
```

Node.js ofrece funciones de alto nivel, como `readFile()` y `writeFile()`, que realizan automáticamente ese ciclo.

También permite trabajar explícitamente con un `FileHandle` mediante `open()`. En ese caso debemos cerrarlo nosotros.

Node proporciona tres familias de APIs:

| API | Ejemplo | Comportamiento |
|---|---|---|
| Sincrónica | `readFileSync()` | Detiene el hilo de JavaScript |
| Callbacks | `readFile(path, callback)` | Asincrónica |
| Promesas | `await readFile(path)` | Asincrónica y más cómoda |

Usaremos `node:fs/promises`. Las operaciones sincrónicas bloquean el event loop; las APIs de promesas realizan el trabajo de archivos fuera del hilo principal, aunque las modificaciones concurrentes sobre un mismo archivo no se sincronizan automáticamente. Los `FileHandle` deben cerrarse explícitamente. ([nodejs.org](https://nodejs.org/api/fs.html))

Ejemplo mínimo:

```js
import { readFile } from 'node:fs/promises';

const contenido = await readFile('notas.txt', 'utf8');

console.log(contenido);
```

# 3. Las rutas

Una ruta es una dirección dentro del sistema de archivos.

Puede ser relativa:

```text
datos/alumnos.json
```

O absoluta:

```text
/Users/alejandro/proyecto/datos/alumnos.json
```

En Windows podría ser:

```text
C:\Users\Alejandro\proyecto\datos\alumnos.json
```

## Nunca concatenar separadores manualmente

Esto es frágil:

```js
const archivo = directorio + '/' + nombre;
```

En su lugar:

```js
import * as path from 'node:path';

const archivo = path.join(directorio, nombre);
```

Node elegirá el separador correspondiente al sistema operativo.

```js
const archivo = path.join(
  'datos',
  'alumnos',
  'comision-c1.json',
);

console.log(archivo);
```

En sistemas POSIX puede producir:

```text
datos/alumnos/comision-c1.json
```

En Windows:

```text
datos\alumnos\comision-c1.json
```

El módulo `node:path` proporciona implementaciones adaptadas al sistema actual y, cuando hace falta interpretar deliberadamente rutas de otro sistema, también ofrece `path.win32` y `path.posix`. ([nodejs.org](https://nodejs.org/api/path.html))

## Operaciones frecuentes con rutas

```js
import * as path from 'node:path';

const archivo = path.join(
  'datos',
  'alumnos',
  'comision-c1.json',
);

console.log(path.basename(archivo));
// comision-c1.json

console.log(path.dirname(archivo));
// datos/alumnos

console.log(path.extname(archivo));
// .json

console.log(path.parse(archivo));
```

`path.parse()` devuelve algo semejante a:

```js
{
  root: '',
  dir: 'datos/alumnos',
  base: 'comision-c1.json',
  ext: '.json',
  name: 'comision-c1'
}
```

## `path.resolve()`

`path.resolve()` construye una ruta absoluta:

```js
const directorio = path.resolve('datos');

console.log(directorio);
```

Una ruta relativa se resuelve desde el directorio actual del proceso:

```js
console.log(process.cwd());
```

`process.cwd()` es el directorio desde el cual se inició Node, que no necesariamente coincide con el directorio donde está el programa. ([nodejs.org](https://nodejs.org/api/process.html))

Por ejemplo:

```bash
cd /Users/alejandro
node proyectos/archivos/programa.mjs
```

Dentro del programa:

```js
process.cwd();
```

devolverá:

```text
/Users/alejandro
```

No devolverá necesariamente:

```text
/Users/alejandro/proyectos/archivos
```

## Ruta relativa al propio programa

En módulos ES podemos obtener la ubicación del archivo ejecutado así:

```js
import * as path from 'node:path';
import { fileURLToPath } from 'node:url';

const nombreArchivoActual = fileURLToPath(import.meta.url);
const directorioActual = path.dirname(nombreArchivoActual);

const archivo = path.join(
  directorioActual,
  'datos',
  'alumnos.json',
);
```

Esto permite localizar recursos junto al programa independientemente del directorio desde el cual se lo ejecute.

# 4. Diferencias entre sistemas operativos

Para escribir código multiplataforma conviene no asumir detalles del sistema.

| Aspecto | Windows | Linux/macOS y otros POSIX |
|---|---|---|
| Separador habitual | `\` | `/` |
| Raíz | `C:\`, `D:\`, rutas UNC | `/` |
| Separador de `PATH` | `;` | `:` |
| Fin de línea tradicional | `\r\n` | `\n` |
| Permisos POSIX | Limitados o diferentes | `rwx`, propietario, grupo |
| Sensibilidad a mayúsculas | Frecuentemente insensible | Depende del sistema de archivos |

Reglas prácticas:

1. Usar siempre `path.join()` y `path.resolve()`.
2. No crear dos archivos que se distingan solamente por mayúsculas.
3. Usar nombres conservadores.
4. No depender de permisos POSIX para que el programa funcione en Windows.
5. No asumir que el orden devuelto por un directorio será siempre el mismo.
6. Ordenar explícitamente cuando el orden sea importante.

Para nombres realmente portables conviene evitar:

```text
< > : " / \ | ? *
```

También conviene evitar nombres que terminen en punto o espacio.

# 5. Crear directorios

Antes de escribir:

```text
datos/alumnos/c1.json
```

los directorios `datos` y `alumnos` deben existir.

```js
import { mkdir } from 'node:fs/promises';

await mkdir('datos', {
  recursive: true,
});
```

Con `recursive: true`, Node crea también los directorios intermedios que falten y no falla simplemente porque el directorio ya exista.

```js
import * as path from 'node:path';
import { mkdir } from 'node:fs/promises';

const archivo = path.join(
  'datos',
  'alumnos',
  'c1.json',
);

await mkdir(path.dirname(archivo), {
  recursive: true,
});
```

Una función reutilizable:

```js
import * as path from 'node:path';
import { mkdir } from 'node:fs/promises';

async function crearDirectorioContenedor(archivo) {
  await mkdir(path.dirname(archivo), {
    recursive: true,
  });
}
```

La opción `mode` representa permisos de creación al estilo POSIX y no tiene el mismo soporte en Windows. ([nodejs.org](https://nodejs.org/api/fs.html))

# 6. Bytes, texto y codificación

Supongamos que tenemos este texto:

```text
Año 😀
```

Dentro de JavaScript es un `string`.

Para guardarlo en un archivo hay que convertirlo en bytes:

```text
String de JavaScript
        ↓ codificación
Secuencia de bytes
        ↓ escritura
Archivo
```

Para leerlo sucede lo contrario:

```text
Archivo
   ↓ lectura
Secuencia de bytes
   ↓ decodificación
String de JavaScript
```

## Unicode no es lo mismo que UTF-8

Unicode asigna números abstractos a caracteres:

```text
A  → U+0041
ñ  → U+00F1
😀 → U+1F600
```

UTF-8 especifica cómo representar esos números mediante bytes.

Un mismo texto puede codificarse de diferentes maneras:

- UTF-8;
- UTF-16LE;
- ISO-8859-1;
- Windows-1252;
- otras codificaciones históricas.

Actualmente, para archivos de texto nuevos, UTF-8 suele ser la elección correcta.

## Los strings de JavaScript

Los strings de JavaScript están organizados como unidades de código UTF-16. Eso significa que `length` no siempre cuenta caracteres visibles. ([tc39.es](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html))

```js
const texto = 'Año 😀';

console.log(texto.length);
// 6 unidades de código UTF-16

console.log([...texto].length);
// 5 puntos de código
```

El emoji ocupa dos unidades UTF-16.

Pero en UTF-8 el texto ocupa nueve bytes:

```js
const texto = 'Año 😀';
const bytes = Buffer.from(texto, 'utf8');

console.log(bytes);
console.log(bytes.length);
// 9
```

La relación es:

```text
texto.length        → unidades UTF-16
[...texto].length   → puntos de código
Buffer.byteLength() → bytes codificados
```

```js
console.log(Buffer.byteLength('Año 😀', 'utf8'));
// 9
```

Un punto de código tampoco equivale siempre a un símbolo visual: algunas letras y emojis pueden estar formados por varios puntos de código. Unicode tiene más capas que una cebolla, pero por lo menos no hace llorar siempre.

## `Buffer`: los bytes de Node.js

Un `Buffer` representa una secuencia de bytes:

```js
const bytes = Buffer.from('Tucumán', 'utf8');

console.log(bytes);
```

Podemos volver a obtener el texto:

```js
const texto = bytes.toString('utf8');

console.log(texto);
// Tucumán
```

Node admite varias codificaciones en `Buffer`, y utiliza UTF-8 como codificación predeterminada para numerosas operaciones de texto. Al decodificar bytes UTF-8 inválidos con `Buffer`, los errores se representan normalmente mediante el carácter de reemplazo `�`. ([nodejs.org](https://nodejs.org/api/buffer.html))

## El problema de usar una codificación incorrecta

```js
const bytes = Buffer.from('canción', 'utf8');

console.log(bytes.toString('latin1'));
```

Resultado:

```text
canciÃ³n
```

Los bytes no cambiaron. Cambió la manera de interpretarlos.

```text
bytes UTF-8
   ↓ interpretados erróneamente como Latin-1
texto deformado
```

Ese fenómeno suele denominarse *mojibake*.

## Decodificación estricta

Cuando necesitamos rechazar un archivo que no sea UTF-8 válido:

```js
import { readFile } from 'node:fs/promises';

const bytes = await readFile('datos.txt');

const decoder = new TextDecoder('utf-8', {
  fatal: true,
});

try {
  const texto = decoder.decode(bytes);
  console.log(texto);
} catch {
  console.error('El archivo no contiene UTF-8 válido');
}
```

Con `fatal: true`, un error de decodificación produce una excepción en lugar de insertar silenciosamente `�`. `TextDecoder` también permite controlar el tratamiento del marcador BOM. ([nodejs.org](https://nodejs.org/api/util.html))

## El BOM

Algunos archivos comienzan con una marca denominada *Byte Order Mark*. Una vez decodificado, puede aparecer como `U+FEFF`.

Podemos retirarlo explícitamente:

```js
function quitarBom(texto) {
  return texto.charCodeAt(0) === 0xfeff
    ? texto.slice(1)
    : texto;
}
```

Esto resulta especialmente útil antes de interpretar JSON proveniente de herramientas externas:

```js
const texto = quitarBom(
  await readFile('datos.json', 'utf8'),
);

const datos = JSON.parse(texto);
```

## No existe una detección universal infalible

Si un archivo no declara su codificación, no siempre puede deducirse de manera segura.

UTF-8 puede validarse, pero ciertos conjuntos de bytes son válidos bajo varias codificaciones. Por eso, un programa serio debe establecer un contrato:

```text
Todos los archivos de entrada estarán codificados en UTF-8.
```

Mucho mejor que pedirle al programa que practique espiritismo con los bytes.

# 7. Fines de línea

Hay dos secuencias tradicionales:

```text
Linux/macOS: \n
Windows:     \r\n
```

Node expone el fin de línea nativo mediante:

```js
import { EOL } from 'node:os';

console.log(JSON.stringify(EOL));
```

`os.EOL` vale `\n` en POSIX y `\r\n` en Windows. ([nodejs.org](https://nodejs.org/api/os.html))

Para archivos de proyecto, JSON, Markdown y datos internos suele ser más simple generar siempre:

```js
'\n'
```

Los editores modernos lo entienden en todas las plataformas.

Cuando se lee texto proveniente de cualquier sistema, puede separarse así:

```js
const lineas = texto.split(/\r\n|\n|\r/);
```

Esto acepta:

- `\r\n`;
- `\n`;
- el antiguo `\r`.

# 8. Crear y escribir archivos de texto

## Escritura básica

```js
import * as path from 'node:path';
import {
  mkdir,
  writeFile,
} from 'node:fs/promises';

const archivo = path.join(
  'datos',
  'saludo.txt',
);

await mkdir(path.dirname(archivo), {
  recursive: true,
});

await writeFile(
  archivo,
  'Hola desde Node.js\n',
  {
    encoding: 'utf8',
  },
);
```

Si el archivo no existe, se crea.

Si ya existe, `writeFile()` lo reemplaza: su contenido anterior se trunca.

La función no crea automáticamente los directorios contenedores; por eso primero usamos `mkdir()`.

## Función reutilizable

```js
import * as path from 'node:path';
import {
  mkdir,
  writeFile,
} from 'node:fs/promises';

async function escribirTexto(archivo, texto) {
  await mkdir(path.dirname(archivo), {
    recursive: true,
  });

  await writeFile(archivo, texto, {
    encoding: 'utf8',
  });
}
```

Uso:

```js
await escribirTexto(
  path.join('datos', 'nota.txt'),
  'Primera línea\nSegunda línea\n',
);
```

## Crear sin sobrescribir

A veces queremos crear el archivo solamente si todavía no existe.

```js
await writeFile(
  'configuracion.json',
  '{}\n',
  {
    encoding: 'utf8',
    flag: 'wx',
  },
);
```

La bandera se interpreta así:

```text
w → escribir, creando o truncando
x → fallar si ya existe
```

Manejo del error:

```js
try {
  await writeFile(
    'configuracion.json',
    '{}\n',
    {
      encoding: 'utf8',
      flag: 'wx',
    },
  );

  console.log('Archivo creado');
} catch (error) {
  if (error.code === 'EEXIST') {
    console.log('El archivo ya existía');
  } else {
    throw error;
  }
}
```

Esta técnica es mejor que:

```js
// No recomendado
if (!(await existe(archivo))) {
  await writeFile(archivo, contenido);
}
```

Entre la comprobación y la escritura otro proceso podría crear el archivo. Es una condición de carrera.

## Crear un archivo vacío

```js
await writeFile(
  'vacio.txt',
  '',
  {
    flag: 'wx',
  },
);
```

# 9. Agregar contenido

`appendFile()` agrega bytes al final.

```js
import { appendFile } from 'node:fs/promises';

await appendFile(
  'registro.log',
  'Aplicación iniciada\n',
  {
    encoding: 'utf8',
  },
);
```

Si el archivo no existe, normalmente se crea.

```js
async function registrar(mensaje) {
  const linea =
    `${new Date().toISOString()} ${mensaje}\n`;

  await appendFile(
    'aplicacion.log',
    linea,
    {
      encoding: 'utf8',
    },
  );
}
```

Uso:

```js
await registrar('Servidor iniciado');
await registrar('Usuario autenticado');
```

Resultado:

```text
2026-08-24T06:00:00.000Z Servidor iniciado
2026-08-24T06:00:01.000Z Usuario autenticado
```

## Cuidado con escrituras simultáneas

Esto es conceptualmente problemático:

```js
await Promise.all([
  appendFile('datos.txt', 'A\n'),
  appendFile('datos.txt', 'B\n'),
  appendFile('datos.txt', 'C\n'),
]);
```

No debe asumirse un orden determinado.

Cuando el orden importa:

```js
await appendFile('datos.txt', 'A\n');
await appendFile('datos.txt', 'B\n');
await appendFile('datos.txt', 'C\n');
```

Las APIs de archivos basadas en promesas no sincronizan por sí solas múltiples modificaciones concurrentes sobre el mismo archivo. ([nodejs.org](https://nodejs.org/api/fs.html))

# 10. Leer archivos

## Leer todo el archivo como texto

```js
import { readFile } from 'node:fs/promises';

const texto = await readFile(
  'datos.txt',
  {
    encoding: 'utf8',
  },
);

console.log(texto);
```

También puede escribirse:

```js
const texto = await readFile(
  'datos.txt',
  'utf8',
);
```

Al indicar la codificación, Node:

1. lee los bytes;
2. los decodifica;
3. devuelve un `string`.

## Leer como bytes

```js
const bytes = await readFile('imagen.png');

console.log(Buffer.isBuffer(bytes));
// true

console.log(bytes.length);
// Cantidad de bytes
```

Al no indicar una codificación, `readFile()` devuelve un `Buffer`.

Esto es correcto para:

- imágenes;
- PDFs;
- archivos comprimidos;
- audio;
- ejecutables;
- datos binarios.

Nunca debe hacerse esto con un archivo binario:

```js
const imagen = await readFile(
  'imagen.png',
  'utf8',
);
```

Eso intenta interpretar los bytes de la imagen como texto UTF-8.

## Leer solamente si existe

En lugar de comprobar primero su existencia, intentamos leerlo:

```js
async function leerTextoONull(archivo) {
  try {
    return await readFile(archivo, 'utf8');
  } catch (error) {
    if (error.code === 'ENOENT') {
      return null;
    }

    throw error;
  }
}
```

Uso:

```js
const configuracion =
  await leerTextoONull('configuracion.json');

if (configuracion === null) {
  console.log('Todavía no existe');
}
```

Node desaconseja comprobar con `access()` antes de abrir, leer o escribir, porque el estado puede cambiar entre ambas operaciones. Es preferible ejecutar la operación y tratar `error.code`. ([nodejs.org](https://nodejs.org/api/fs.html))

# 11. Trabajar con un manejador explícito

Las funciones anteriores son operaciones completas:

```text
abrir → operar → cerrar
```

Cuando necesitamos realizar varias operaciones sobre el mismo archivo, podemos abrirlo explícitamente.

```js
import { open } from 'node:fs/promises';

const manejador = await open(
  'datos.txt',
  'r',
);

try {
  const contenido = await manejador.readFile({
    encoding: 'utf8',
  });

  console.log(contenido);
} finally {
  await manejador.close();
}
```

El `finally` garantiza el cierre incluso si ocurre un error.

Las banderas habituales son:

| Bandera | Significado |
|---|---|
| `r` | Leer |
| `r+` | Leer y escribir |
| `w` | Escribir, creando o truncando |
| `wx` | Crear sin reemplazar |
| `a` | Agregar al final |
| `ax` | Agregar, pero fallar si ya existe |

Para una lectura o escritura completa, `readFile()` y `writeFile()` son más sencillas. El `FileHandle` resulta útil cuando necesitamos:

- leer sectores concretos;
- mantener el archivo abierto;
- escribir varias veces;
- controlar posiciones;
- sincronizar explícitamente con el dispositivo.

# 12. Guardar y leer JSON

JSON es texto con una sintaxis determinada.

## Escribir

```js
import { writeFile } from 'node:fs/promises';

const alumnos = [
  {
    legajo: 63355,
    nombre: 'Jazmín Vargas',
  },
  {
    legajo: 61124,
    nombre: 'José Medina',
  },
];

const texto = JSON.stringify(
  alumnos,
  null,
  2,
);

await writeFile(
  'alumnos.json',
  `${texto}\n`,
  {
    encoding: 'utf8',
  },
);
```

`JSON.stringify()` convierte estructuras de JavaScript en texto JSON.

El archivo resultante:

```json
[
  {
    "legajo": 63355,
    "nombre": "Jazmín Vargas"
  },
  {
    "legajo": 61124,
    "nombre": "José Medina"
  }
]
```

## Leer

```js
import { readFile } from 'node:fs/promises';

const texto = await readFile(
  'alumnos.json',
  'utf8',
);

const alumnos = JSON.parse(
  quitarBom(texto),
);

console.log(alumnos[0].nombre);
```

`JSON.parse()` no lee archivos. Recibe texto.

El proceso completo es:

```text
readFile()
   ↓
string
   ↓ JSON.parse()
array u objeto
```

## Manejar JSON inválido

```js
async function leerJson(archivo) {
  const texto = quitarBom(
    await readFile(archivo, 'utf8'),
  );

  try {
    return JSON.parse(texto);
  } catch (error) {
    throw new Error(
      `El archivo ${archivo} no contiene JSON válido`,
      {
        cause: error,
      },
    );
  }
}
```

# 13. Obtener información y metadatos

`stat()` obtiene información del sistema de archivos.

```js
import { stat } from 'node:fs/promises';

const informacion = await stat('datos.txt');

console.log(informacion.size);
console.log(informacion.mtime);
console.log(informacion.isFile());
console.log(informacion.isDirectory());
```

Una función más clara:

```js
async function describirEntrada(ruta) {

  return {
    ruta,
    tipo: informacion.isFile()
      ? 'archivo'
      : informacion.isDirectory()
        ? 'directorio'
        : 'otro',
    tamañoEnBytes: informacion.size,
    modificacion: informacion.mtime,
    acceso: informacion.atime,
```

```js
console.log(
```

# 15. Recorrer directorios recursivamente

Un sistema de directorios forma un árbol:

```text
datos/
├── alumnos.json
├── cursos/
│   ├── c1.json
│   └── c3.json
└── textos/
    ├── introduccion.md
    └── unidad-1.md
```

Para recorrerlo:

1. listamos el directorio actual;
2. si encontramos un archivo, lo devolvemos;
3. si encontramos un directorio, repetimos el proceso dentro de él.

```js
import * as path from 'node:path';
import { readdir } from 'node:fs/promises';

async function* recorrerArchivos(directorio) {
  const entradas = await readdir(
    directorio,
    {
      withFileTypes: true,
    },
  );

  entradas.sort((a, b) =>
    a.name.localeCompare(b.name, 'es'),
  );

  for (const entrada of entradas) {
    const rutaCompleta = path.join(
      directorio,
      entrada.name,
    );

    if (entrada.isDirectory()) {
      yield* recorrerArchivos(rutaCompleta);
    } else if (entrada.isFile()) {
      yield rutaCompleta;
    }
  }
}
```

Uso:

```js
for await (
  const archivo of recorrerArchivos('datos')
) {
  console.log(archivo);
}
```

La función es un generador asíncrono:

```js
async function* ...
```

No devuelve todos los archivos de golpe. Los va produciendo uno por uno.

Eso permite procesar árboles grandes sin construir primero un array gigantesco.

Esta implementación no sigue enlaces simbólicos, lo cual evita accidentalmente entrar en ciclos como:

```text
A enlaza a B
B enlaza a A
```

# 16. Buscar archivos por nombre o extensión

## Por extensión

```js
import * as path from 'node:path';

async function buscarPorExtensiones(
  directorio,
  extensiones,
) {
  const aceptadas = new Set(
    extensiones.map(extension =>
      extension.startsWith('.')
        ? extension.toLowerCase()
        : `.${extension.toLowerCase()}`,
    ),
  );

  const encontrados = [];

  for await (
    const archivo of recorrerArchivos(directorio)
  ) {
    const extension =
      path.extname(archivo).toLowerCase();

    if (aceptadas.has(extension)) {
      encontrados.push(archivo);
    }
  }

  return encontrados;
}
```

Uso:

```js
const archivos = await buscarPorExtensiones(
  'datos',
  ['txt', 'md', '.json'],
);

console.log(archivos);
```

## Por parte del nombre

```js
async function buscarPorNombre(
  directorio,
  fragmento,

  const buscado = fragmento.toLocaleLowerCase('es');

    const archivo of recorrerArchivos(directorio)

      .toLocaleLowerCase('es');
```

## Búsqueda con patrones `glob`

En Node 22.17 o posterior, `fsPromises.glob()` es una API estable. Permite patrones como:

```text
**/*.txt
**/*.json
src/**/*.js
```

La versión estable admite opciones como `cwd`, exclusiones y resultados como iterador asíncrono. ([nodejs.org](https://nodejs.org/api/fs.html))

```js
import { glob } from 'node:fs/promises';

for await (
  const archivo of glob(
    [
      '**/*.txt',
      '**/*.md',
    ],
    {
      cwd: 'datos',
      exclude: [
        'node_modules/**',
        '.git/**',
      ],
    },
  )
) {
  console.log(archivo);
}
```

Los símbolos principales son:

| Patrón | Significado |
|---|---|
| `*` | Cualquier secuencia dentro de un nivel |
| `?` | Un carácter |
| `**` | Cero o más niveles de directorios |
| `*.txt` | Archivos TXT del directorio actual |
| `**/*.txt` | TXT en cualquier profundidad |

El recorrido manual enseña el algoritmo. `glob()` resuelve el caso cotidiano con menos código.

# 17. Buscar texto dentro de un archivo pequeño

Para un archivo pequeño podemos cargarlo completamente.

```js
function buscarEnTexto(
  texto,
  consulta,
  {
    distinguirMayusculas = false,
  } = {},
) {
  if (consulta.length === 0) {
    throw new Error(
      'La consulta no puede estar vacía',
    );
  }

  const transformar = valor =>
    distinguirMayusculas
      ? valor
      : valor.toLocaleLowerCase('es');

  const buscado = transformar(consulta);
  const lineas = texto.split(/\r\n|\n|\r/);
  const coincidencias = [];

  for (
    let indiceLinea = 0;
    indiceLinea < lineas.length;
    indiceLinea++
  ) {
    const lineaOriginal = lineas[indiceLinea];
    const lineaComparada =
      transformar(lineaOriginal);

    let desde = 0;

    while (desde < lineaComparada.length) {
      const indice = lineaComparada.indexOf(
        buscado,
        desde,
      );

      if (indice === -1) {
        break;
      }

      coincidencias.push({
        linea: indiceLinea + 1,
        columna: indice + 1,
        texto: lineaOriginal,
      });

      desde = indice + buscado.length;
    }
  }

  return coincidencias;
}
```

Uso:

```js
const texto = await readFile(
  'notas.txt',
  'utf8',
);

const coincidencias = buscarEnTexto(
  texto,
  'node',
);

console.log(coincidencias);
```

Resultado posible:

```js
[
  {
    linea: 3,
    columna: 12,
    texto: 'Trabajaremos con Node.js'
  }
]
```

La columna está medida en unidades de código de JavaScript. Para textos corrientes esto suele ser suficiente; una aplicación editorial que deba contar símbolos visuales necesitaría segmentación Unicode más precisa.

# 18. Buscar dentro de un archivo grande

`readFile()` carga el archivo completo en memoria.

Para un archivo de varios gigabytes eso sería una idea creativa, pero del tipo que termina con el sistema operativo golpeando la puerta.

En archivos grandes conviene leer por partes mediante un stream.

```js
import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

async function* buscarPorLineas(
  archivo,
  consulta,
  {
    distinguirMayusculas = false,
  } = {},
) {
  if (consulta.length === 0) {
    throw new Error(
      'La consulta no puede estar vacía',
    );
  }

  const transformar = valor =>
    distinguirMayusculas
      ? valor
      : valor.toLocaleLowerCase('es');

  const buscado = transformar(consulta);

  const entrada = createReadStream(
    archivo,
    {
      encoding: 'utf8',
    },
  );

  const lector = createInterface({
    input: entrada,
    crlfDelay: Infinity,
  });

  let numeroLinea = 0;

  for await (const linea of lector) {
    numeroLinea++;

    const comparada = transformar(linea);
    const columna = comparada.indexOf(buscado);

    if (columna !== -1) {
      yield {
        archivo,
        linea: numeroLinea,
        columna: columna + 1,
        texto: linea,
      };
    }
  }
}
```

Uso:

```js
for await (
  const coincidencia of buscarPorLineas(
    'servidor.log',
    'error',
  )
) {
  console.log(coincidencia);
}
```

`readline` permite consumir un stream línea por línea. Con `crlfDelay: Infinity`, las secuencias `\r\n` se interpretan correctamente como un único fin de línea. ([nodejs.org](https://nodejs.org/api/readline.html))

## Buscar en todos los archivos de un árbol

Primero determinamos cuáles extensiones trataremos como texto:

```js
import * as path from 'node:path';

const EXTENSIONES_DE_TEXTO = new Set([
  '.txt',
  '.md',
  '.json',
  '.csv',
  '.js',
  '.mjs',
  '.ts',
  '.html',
  '.css',
]);
```

Después recorremos los archivos uno por uno:

```js
async function buscarEnDirectorio(
  directorio,
  consulta,
) {
  const resultados = [];

  for await (
    const archivo of recorrerArchivos(directorio)
  ) {
    const extension =
      path.extname(archivo).toLowerCase();

    if (!EXTENSIONES_DE_TEXTO.has(extension)) {
      continue;
    }

    for await (
      const coincidencia of buscarPorLineas(
        archivo,
        consulta,
      )
    ) {
      resultados.push(coincidencia);
    }
  }

  return resultados;
}
```

Uso:

```js
const resultados = await buscarEnDirectorio(
  'proyecto',
  'TODO',
);

console.table(resultados);
```

Esta versión abre solamente un archivo por vez. Es más prudente que lanzar miles de lecturas simultáneas con `Promise.all()`.

# 19. Copiar archivos

## Copiar un archivo

```js
import { copyFile } from 'node:fs/promises';

await copyFile(
  'original.txt',
  'copia.txt',
);
```

Esto copia los bytes.

No importa si el archivo contiene:

- UTF-8;
- una imagen;
- un PDF;
- audio;
- datos comprimidos.

La copia no decodifica ni vuelve a codificar.

Por defecto, `copyFile()` puede reemplazar el archivo de destino.

## Evitar el reemplazo

```js
import { constants } from 'node:fs';
import { copyFile } from 'node:fs/promises';

await copyFile(
  'original.txt',
  'copia.txt',
  constants.COPYFILE_EXCL,
);
```

Si `copia.txt` ya existe, la operación falla con `EEXIST`. La constante `COPYFILE_EXCL` establece precisamente esa política. ([nodejs.org](https://nodejs.org/api/fs.html))

Una función completa:

```js
import * as path from 'node:path';
import { constants } from 'node:fs';
import {
  copyFile,
  mkdir,
} from 'node:fs/promises';

async function copiarSinReemplazar(
  origen,
  destino,
) {
  await mkdir(path.dirname(destino), {
    recursive: true,
  });

  await copyFile(
    origen,
    destino,
    constants.COPYFILE_EXCL,
  );
}
```

## Copiar directorios

```js
import { cp } from 'node:fs/promises';

await cp(
  'datos',
  'respaldo-datos',
  {
    recursive: true,
  },
);
```

Para evitar reemplazar entradas existentes:

```js
await cp(
  'datos',
  'respaldo-datos',
  {
    recursive: true,
    force: false,
    errorOnExist: true,
  },
);
```

`cp()` copia árboles de directorios y dispone de opciones para recursividad, reemplazo, filtros y preservación de fechas. La API dejó de ser experimental en Node 22.3. ([nodejs.org](https://nodejs.org/api/fs.html))

# 20. Renombrar y mover

Renombrar:

```js
import { rename } from 'node:fs/promises';

await rename(
  'notas.txt',
  'notas-programacion.txt',
);
```

Mover es la misma operación, pero cambiando el directorio:

```js
await rename(
  path.join('entrada', 'datos.txt'),
  path.join('procesados', 'datos.txt'),
);
```

Es recomendable crear antes el directorio de destino:

```js
import * as path from 'node:path';
import {
  mkdir,
  rename,
} from 'node:fs/promises';

async function mover(origen, destino) {
  await mkdir(path.dirname(destino), {
    recursive: true,
  });

  await rename(origen, destino);
}
```

`rename()` cambia `oldPath` por `newPath`; no interpreta el contenido. ([nodejs.org](https://nodejs.org/api/fs.html))

## Mover entre discos o volúmenes

Un renombrado suele funcionar dentro del mismo sistema de archivos. Si el origen y el destino están en volúmenes diferentes, puede producirse `EXDEV`.

En ese caso hay que:

1. copiar;
2. comprobar que la copia terminó;
3. eliminar el original.

```js
import * as path from 'node:path';
import { constants } from 'node:fs';
import {
  copyFile,
  cp,
  mkdir,
  rename,
  rm,
  stat,
} from 'node:fs/promises';

async function moverMultiplataforma(
  origen,
  destino,
) {
  await mkdir(path.dirname(destino), {
    recursive: true,
  });

  try {
    await rename(origen, destino);
    return;
  } catch (error) {
    if (error.code !== 'EXDEV') {
      throw error;
    }
  }

  const informacion = await stat(origen);

  if (informacion.isDirectory()) {
    await cp(origen, destino, {
      recursive: true,
      force: false,
      errorOnExist: true,
    });

    await rm(origen, {
      recursive: true,
    });

    return;
  }

  if (informacion.isFile()) {
    await copyFile(
      origen,
      destino,
      constants.COPYFILE_EXCL,
    );

    await rm(origen);
    return;
  }

  throw new Error(
    'El origen no es un archivo ni un directorio ordinario',
  );
}
```

El reemplazo por copia y eliminación no es atómico. Si la copia termina pero la eliminación falla, quedarán ambas versiones. Eso es preferible a perder las dos, pero debe contemplarse en el diseño.

# 22. Extraer información de un archivo

“Extraer información” puede significar varias cosas.

```js
const informacion = await stat(archivo);
```

## Extraer estadísticas de texto

```js
function analizarTexto(texto) {
  const lineas = texto === ''
    ? 0
    : texto.split(/\r\n|\n|\r/).length;

  const palabras = texto.trim() === ''
    ? 0
    : texto.trim().split(/\s+/u).length;

  const segmentador = new Intl.Segmenter(
    'es',
    {
      granularity: 'grapheme',
    },
  );

  return {
    bytesUtf8: Buffer.byteLength(
      texto,
      'utf8',
    ),
    unidadesUtf16: texto.length,
    puntosDeCodigo: [...texto].length,
    simbolosVisuales: [

    lineas,

}
```

## Extraer estructuras JSON

```js
const datos = JSON.parse(
```

## Extraer datos de un log

Supongamos este formato:

```text
2026-08-24T09:10:00Z INFO usuario=ana accion=login
2026-08-24T09:12:00Z ERROR usuario=juan accion=guardar
```

Podemos interpretarlo con una expresión regular:

```js
const PATRON_LOG =
  /^(?<fecha>\S+)\s+(?<nivel>INFO|WARN|ERROR)\s+usuario=(?<usuario>\S+)\s+accion=(?<accion>\S+)$/u;

function interpretarLog(texto) {
  const resultados = [];

  const lineas = texto.split(
    /\r\n|\n|\r/,
  );

  for (
    let indice = 0;
    indice < lineas.length;
    indice++
  ) {
    const coincidencia =
      PATRON_LOG.exec(lineas[indice]);

    if (!coincidencia) {
      continue;
    }

    resultados.push({
      linea: indice + 1,
      fecha: coincidencia.groups.fecha,
      nivel: coincidencia.groups.nivel,
      usuario:
        coincidencia.groups.usuario,
      accion:
        coincidencia.groups.accion,
    });
  }

  return resultados;
}
```

Uso:

```js
const texto = await readFile(
  'aplicacion.log',
  'utf8',
);

const registros = interpretarLog(texto);

const errores = registros.filter(
  registro => registro.nivel === 'ERROR',
);

console.table(errores);
```

El archivo no “contiene objetos”. Contiene texto que nuestro programa interpreta siguiendo un formato acordado.

## CSV

Esto:

```js
linea.split(',');
```

no es un analizador CSV general.

Un campo CSV puede contener:

```text
"Di Battista, Alejandro"
```

También puede contener:

- comillas escapadas;
- saltos de línea;
- separadores dentro del campo.

Solamente sería válido usar `split(',')` bajo un contrato muy limitado:

```text
Ningún campo contiene comas, comillas ni saltos de línea.
```

Para CSV real conviene utilizar un parser especializado.

## PDF, DOCX e imágenes

Node puede leer sus bytes:

```js
const bytes = await readFile('documento.pdf');
```

Pero no puede obtener automáticamente párrafos, tablas o imágenes simplemente porque haya leído el archivo.

Hace falta un parser que comprenda el formato:

```text
bytes
  ↓ parser de PDF, DOCX, PNG...
estructura interna
  ↓
información
```

Leer el archivo y comprender el archivo son operaciones distintas.

# 23. Seguridad: impedir que una ruta escape de un directorio

Supongamos que una aplicación guarda archivos dentro de:

```text
/uploads
```

Y recibe del usuario:

```text
../../configuracion-secreta.json
```

Si se concatena sin validar, el usuario puede escapar del directorio autorizado.

Una comprobación básica:

```js
import * as path from 'node:path';

function resolverDentroDe(
  directorioBase,
  rutaSolicitada,
) {
  const base = path.resolve(
    directorioBase,
  );

  const candidata = path.resolve(
    base,
    rutaSolicitada,
  );

  const relativa = path.relative(
    base,
    candidata,
  );

  const escapa =
    relativa === '..' ||
    relativa.startsWith(
      `..${path.sep}`,
    ) ||
    path.isAbsolute(relativa);

  if (escapa) {
    throw new Error(
      'La ruta está fuera del directorio permitido',
    );
  }

  return candidata;
}
```

Uso:

```js
const archivoSeguro = resolverDentroDe(
  'uploads',
  'usuarios/ana/foto.png',
);
```

Esto rechaza:

```js
resolverDentroDe(
  'uploads',
  '../../secreto.txt',
);
```

Para entornos hostiles también hay que definir una política sobre enlaces simbólicos, porque un enlace dentro del directorio puede apuntar fuera de él.

# 24. Manejo de errores

Las operaciones de archivos pueden fallar por razones normales:

| Código | Significado habitual |
|---|---|
| `ENOENT` | La ruta no existe |
| `EEXIST` | El destino ya existe |
| `EACCES` | Acceso denegado |
| `EPERM` | Operación no permitida |
| `EISDIR` | Se esperaba un archivo y apareció un directorio |
| `ENOTDIR` | Se esperaba un directorio |
| `ENOTEMPTY` | El directorio no está vacío |
| `EXDEV` | Operación entre dispositivos o volúmenes |

Ejemplo:

```js
try {
  const texto = await readFile(
    'datos.txt',
    'utf8',
  );

  console.log(texto);
} catch (error) {
  switch (error.code) {
    case 'ENOENT':
      console.error(
        'El archivo no existe',
      );
      break;

    case 'EACCES':
    case 'EPERM':
      console.error(
        'No hay permisos suficientes',
      );
      break;

    case 'EISDIR':
      console.error(
        'La ruta corresponde a un directorio',
      );
      break;

    default:
      throw error;
  }
}
```

Para tomar decisiones conviene utilizar `error.code`, no analizar el texto de `error.message`. Los errores de sistema de Node incluyen propiedades como `code`, `path`, `dest` y `syscall`. ([nodejs.org](https://nodejs.org/api/errors.html))

## No ocultar todos los errores

Esto es peligroso:

```js
try {
  await realizarOperacion();
} catch {
  // No hacer nada
}
```

Podría ocultar:

- corrupción de datos;
- falta de permisos;
- disco lleno;
- errores de programación;
- rutas equivocadas.

Debe tratarse solamente aquello que realmente se sabe resolver:

```js
try {
  await readFile(archivo, 'utf8');
} catch (error) {
  if (error.code === 'ENOENT') {
    return null;
  }

  throw error;
}
```

# 25. Archivos pequeños frente a archivos grandes

No existe un número universal que separe “pequeño” de “grande”. Depende de:

- memoria disponible;
- cantidad de solicitudes concurrentes;
- tamaño de los archivos;
- frecuencia de acceso;
- latencia aceptable.

La elección general es:

| Situación | Herramienta |
|---|---|
| Leer todo un archivo pequeño | `readFile()` |
| Escribir todo un archivo pequeño | `writeFile()` |
| Procesar muchas líneas | `createReadStream()` + `readline` |
| Transferir datos grandes | Streams |
| Leer posiciones concretas | `FileHandle` |
| Listar un directorio | `readdir()` |
| Recorrer un árbol | Generador recursivo o `glob()` |

`readFile()` tiene una ventaja enorme: simplicidad.

Los streams tienen otra: no necesitan almacenar simultáneamente todo el contenido.

# 26. Diferencias con otros lenguajes

Los conceptos no cambian:

```text
ruta → abrir → bytes → decodificar → interpretar → cerrar
```

Lo que cambia es la forma de expresarlos.

| Concepto | Node.js | Python | C# | Java |
|---|---|---|---|---|
| Rutas | Strings + `node:path` | Objetos `Path` | `Path`, `File`, `Directory`, `FileInfo` | Objetos `Path` + `Files` |
| Leer texto completo | `await readFile()` | `Path.read_text()` | `await File.ReadAllTextAsync()` | `Files.readString()` |
| Escribir texto | `await writeFile()` | `Path.write_text()` | `await File.WriteAllTextAsync()` | `Files.writeString()` |
| Bytes | `Buffer` | `bytes` | `byte[]` | `byte[]` |
| Operación asincrónica estándar | Promesas | `pathlib` es principalmente sincrónico | APIs `Async` | `Files` básico es sincrónico |
| Cierre explícito | `FileHandle.close()` | `with` | `using` / `await using` | `try-with-resources` |

Python concentra muchas operaciones directamente en objetos `Path`. C# ofrece métodos asincrónicos como `ReadAllTextAsync()` y `WriteAllTextAsync()`. Java separa objetos `Path` de la clase utilitaria `Files`; `Files.readString()` utiliza UTF-8 cuando no se especifica otro charset. ([docs.python.org](https://docs.python.org/3/library/pathlib.html))

## Una diferencia importante de Node.js

Node está diseñado alrededor de un event loop. Por eso es habitual escribir:

```js
const texto = await readFile(
  archivo,
  'utf8',
);
```

En lugar de:

```js
const texto = readFileSync(
  archivo,
  'utf8',
);
```

La segunda forma detiene la ejecución de JavaScript mientras termina la operación.

En un pequeño script de línea de comandos eso puede ser aceptable. En un servidor que atiende múltiples solicitudes puede bloquear a todos los usuarios.

# 27. Programa integrador completo

Este programa:

1. crea un directorio temporal;
2. crea un archivo;
3. agrega una línea;
4. lo lee;
5. guarda JSON;
6. lista el directorio;
7. busca texto;
8. copia;
9. renombra;
10. obtiene metadatos.

Guardarlo como `demo-archivos.mjs`:

```js
import * as path from 'node:path';

import {
  constants,
  createReadStream,
} from 'node:fs';

import {
  appendFile,
  copyFile,
  mkdir,
  mkdtemp,
  readFile,
  readdir,
  rename,
  stat,
  writeFile,
} from 'node:fs/promises';

import { tmpdir } from 'node:os';
import { createInterface } from 'node:readline';

async function* buscarPorLineas(
  archivo,
  consulta,
) {
  const buscado =
    consulta.toLocaleLowerCase('es');

  const entrada = createReadStream(
    archivo,
    {
      encoding: 'utf8',
    },
  );

  const lector = createInterface({
    input: entrada,
    crlfDelay: Infinity,
  });

  let numeroLinea = 0;

  for await (const linea of lector) {
    numeroLinea++;

    const columna = linea
      .toLocaleLowerCase('es')
      .indexOf(buscado);

    if (columna !== -1) {
      yield {
        linea: numeroLinea,
        columna: columna + 1,
        texto: linea,
      };
    }
  }
}

async function main() {
  const raiz = await mkdtemp(
    path.join(
      tmpdir(),
      'gestion-archivos-',
    ),
  );

  const originales = path.join(
    raiz,
    'originales',
  );

  const copias = path.join(
    raiz,
    'copias',
  );

  await mkdir(originales, {
    recursive: true,
  });

  await mkdir(copias, {
    recursive: true,
  });

  const notas = path.join(
    originales,
    'notas.txt',
  );

  // Crear y escribir.
  await writeFile(
    notas,
    'Primera línea\n',
    {
      encoding: 'utf8',
    },
  );

  // Agregar.
  await appendFile(
    notas,
    'Segunda línea con Tucumán\n',
    {
      encoding: 'utf8',
    },
  );

  // Leer.
  const contenido = await readFile(
    notas,
    'utf8',
  );

  console.log('Contenido:');
  console.log(contenido);

  // Guardar JSON.
  const alumnos = [
    {
      legajo: 1,
      nombre: 'Ana',
    },
    {
      legajo: 2,
      nombre: 'Juan',
    },
  ];

  const archivoJson = path.join(
    originales,
    'alumnos.json',
  );

  await writeFile(
    archivoJson,
    `${JSON.stringify(
      alumnos,
      null,
      2,
    )}\n`,
    {
      encoding: 'utf8',
    },
  );

  // Listar.
  const entradas = await readdir(
    originales,
    {
      withFileTypes: true,
    },
  );

  console.log('Entradas:');

  for (const entrada of entradas) {
    console.log({
      nombre: entrada.name,
      esArchivo: entrada.isFile(),
      esDirectorio: entrada.isDirectory(),
    });
  }

  // Buscar.
  console.log('Coincidencias:');

  for await (
    const coincidencia of buscarPorLineas(
      notas,
      'tucumán',
    )
  ) {
    console.log(coincidencia);
  }

  // Copiar sin reemplazar.
  const copia = path.join(
    copias,
    'notas.txt',
  );

  await copyFile(
    notas,
    copia,
    constants.COPYFILE_EXCL,
  );

  // Renombrar.
  const copiaRenombrada = path.join(
    copias,
    'notas-respaldo.txt',
  );

  await rename(
    copia,
    copiaRenombrada,
  );

  // Metadatos.
  const informacion = await stat(
    copiaRenombrada,
  );

  console.log('Metadatos:');

  console.log({
    ruta: copiaRenombrada,
    bytes: informacion.size,
    modificado: informacion.mtime,
    esArchivo: informacion.isFile(),
  });

  console.log(
    '\nDirectorio generado:',
    raiz,
  );
}

main().catch(error => {
  console.error(error);
  process.exitCode = 1;
});
```

Ejecutar:

```bash
node demo-archivos.mjs
```

El programa utiliza el directorio temporal correspondiente a Windows, macOS o Linux, por lo que no contiene rutas específicas de ninguna plataforma.

# 28. Mapa mental final

La gestión de archivos puede resumirse así:

```text
¿Dónde está?
    node:path

¿Existe el directorio contenedor?
    mkdir({ recursive: true })

¿Quiero escribir todo?
    writeFile()

¿Quiero agregar al final?
    appendFile()

¿Quiero leer todo como texto?
    readFile(ruta, 'utf8')

¿Quiero leer bytes?
    readFile(ruta)

¿Es demasiado grande?
    createReadStream()

¿Quiero listar?
    readdir({ withFileTypes: true })

¿Quiero recorrer subdirectorios?
    generador recursivo o glob()

¿Quiero copiar un archivo?
    copyFile()

¿Quiero copiar un directorio?
    cp({ recursive: true })

¿Quiero cambiar nombre o ubicación?
    rename()

¿Quiero conocer tamaño y fechas?
    stat()

¿Quiero eliminar?
    rm()

¿Quiero comprender el contenido?
    decodificar + interpretar el formato
```

La regla fundamental es mantener separadas estas capas:

```text
Ruta
≠
Archivo
≠
Bytes
≠
Texto
≠
Formato
≠
Información
```

Cuando esas diferencias están claras, la API deja de parecer una colección arbitraria de funciones. Cada operación cae naturalmente en el nivel que le corresponde.
