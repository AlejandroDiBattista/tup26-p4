# Objetos

Programación IV: Desarrollo Web — Etapa 1, fundamentos técnicos
Apunte de la tercera clase de JavaScript, 2 de 4

El [arreglo](031-arreglos.md) agrupa por posición y responde "cuál es el tercero". El objeto agrupa por nombre y responde "cuál es el email". Cuando los datos son partes distintas de una misma cosa, el objeto es la estructura correcta.

En desarrollo web el objeto es la moneda corriente. Todo lo que llega de una API llega como JSON, y JSON son objetos y arreglos anidados. Los otros apuntes de esta clase son [arreglos](031-arreglos.md), [Set](033-set.md) y [Map](034-map.md).

## Qué es un objeto

Un objeto agrupa valores y les pone nombre. Cada par de nombre y valor es una propiedad.

```javascript
const contacto = {
  nombre: "Ana Pérez",
  email: "ana@mail.com",
  edad: 30,
  activo: true,
};
```

El nombre de la propiedad, o clave, siempre es texto. El valor puede ser cualquier cosa, incluidos otros objetos, arreglos y funciones.

Que la clave sea siempre texto tiene una consecuencia que sorprende: si usás un número, se convierte.

```javascript
const puntajes = {};
puntajes[1] = "uno";
puntajes["1"];        // "uno", es la misma propiedad
Object.keys(puntajes); // ["1"], la clave quedó como texto
```

Cuando necesites claves que no sean texto, la estructura correcta es [Map](034-map.md).

Una aclaración para quien viene de C#: esto no es una instancia de una clase. Es un objeto suelto, creado en el momento, sin ninguna definición previa. JavaScript también tiene clases, pero la mayoría de los objetos que vas a manejar en desarrollo web nacen así, como literales o como resultado de leer un JSON.

Los objetos se anidan sin límite:

```javascript
const contacto = {
  nombre: "Ana",
  direccion: {
    calle: "Rivadavia 123",
    ciudad: "Tucumán",
  },
  telefonos: ["3814567890", "3811234567"],
};
```

## El punto y los corchetes

Hay dos formas de acceder a una propiedad.

La sintaxis de punto es la habitual:

```javascript
contacto.nombre;             // "Ana"
contacto.direccion.ciudad;   // "Tucumán"
contacto.telefonos[0];       // "3814567890"
```

La sintaxis de corchetes usa la clave como texto:

```javascript
contacto["nombre"];   // "Ana"
```

Con una clave fija son equivalentes y siempre se prefiere el punto. Pero hay tres casos en que los corchetes son obligatorios.

Cuando la clave no es un identificador válido:

```javascript
const config = {
  "api-key": "abc123",
  "max intentos": 3,
};

config["api-key"];  // única forma
config.api-key;     // error de sintaxis, lo lee como una resta
```

Cuando la clave está en una variable:

```javascript
const campo = "email";

contacto[campo];   // "ana@mail.com"
contacto.campo;    // undefined, busca una propiedad llamada "campo"
```

Y cuando la clave se calcula en el momento:

```javascript
for (const campo of ["nombre", "email"]) {
  console.log(`${campo}: ${contacto[campo]}`);
}
```

Esa diferencia entre `contacto[campo]` y `contacto.campo` es el error más común del tema. El punto toma lo que escribiste literalmente; los corchetes evalúan la expresión.

## Agregar, modificar y eliminar

Los objetos son abiertos: agregás propiedades cuando querés.

```javascript
const contacto = { nombre: "Ana" };

contacto.email = "ana@mail.com";  // agrega
contacto.nombre = "Ana María";    // modifica
delete contacto.email;            // elimina
```

Pedir una propiedad que no existe devuelve `undefined`, sin error:

```javascript
contacto.telefono; // undefined
```

Y pedir una propiedad de algo que es `undefined` sí falla:

```javascript
contacto.direccion.ciudad;  // TypeError si no hay direccion
contacto.direccion?.ciudad; // undefined, sin fallar
```

El encadenamiento opcional tiene tres formas, según qué venga después:

```javascript
contacto?.direccion;        // por si contacto no existe
contacto.telefonos?.[0];    // acceso por índice
contacto.saludar?.();       // llamada a un método que puede no estar
```

Para preguntar si una propiedad existe:

```javascript
"nombre" in contacto;              // true
Object.hasOwn(contacto, "nombre"); // true, solo propiedades propias
contacto.nombre !== undefined;     // sirve, salvo que valga undefined
```

La diferencia entre `in` y `Object.hasOwn` importa cuando usás el objeto como diccionario. `in` también encuentra las propiedades heredadas, y todo objeto hereda unas cuantas:

```javascript
const diccionario = {};
"toString" in diccionario;              // true, viene heredada
Object.hasOwn(diccionario, "toString"); // false, es lo que querías preguntar
```

Si vas a usar un objeto como diccionario de claves que vienen de afuera, usá `Object.hasOwn`, o directamente usá un [Map](034-map.md), que no tiene este problema.

## Las formas abreviadas

Hay tres atajos de sintaxis que aparecen en todo el código moderno.

El primero es la abreviatura de propiedad. Cuando la clave y la variable se llaman igual, escribís el nombre una sola vez:

```javascript
const nombre = "Ana";
const email = "ana@mail.com";

// Forma larga
const contacto = { nombre: nombre, email: email };

// Forma abreviada
const contacto = { nombre, email };
```

Es exactamente lo mismo. Lo vas a ver a la salida de casi toda función que arme un objeto.

El segundo es la abreviatura de método. Si el valor es una función, podés omitir `function` y los dos puntos:

```javascript
// Forma larga
const agenda = {
  contactos: [],
  agregar: function (c) { this.contactos.push(c); },
};

// Forma abreviada
const agenda = {
  contactos: [],
  agregar(c) { this.contactos.push(c); },
};
```

Adentro de un método, `this` es el objeto que está antes del punto en la llamada. Lo vemos en detalle cuando lleguemos a funciones; por ahora alcanza con saber que `agenda.agregar(c)` hace que `this` sea `agenda`.

El tercero son las claves calculadas. Con corchetes dentro del literal, la clave sale de una expresión:

```javascript
const campo = "email";
const valor = "ana@mail.com";

const objeto = { [campo]: valor };
// { email: "ana@mail.com" }

// Útil para construir objetos dinámicos
function crearFiltro(campo, valor) {
  return { [campo]: valor, [`${campo}Exacto`]: true };
}
```

## Propagación y combinación

El operador de propagación, que ya usamos con arreglos, también funciona con objetos:

```javascript
const base = { nombre: "Ana", activo: true };

const copia = { ...base };
const conEmail = { ...base, email: "ana@mail.com" };
const modificado = { ...base, nombre: "Ana María" };
```

El orden importa: lo que va después pisa lo que va antes.

```javascript
{ ...base, activo: false };  // activo queda en false
{ activo: false, ...base };  // activo vuelve a true
```

Combinando dos objetos:

```javascript
const porDefecto = { pagina: 1, orden: "nombre", limite: 10 };
const delUsuario = { limite: 50 };

const opciones = { ...porDefecto, ...delUsuario };
// { pagina: 1, orden: "nombre", limite: 50 }
```

Ese patrón de valores por defecto más valores del usuario lo vas a usar en cada función de configuración que escribas.

Ojo con una cosa: la combinación es superficial. Si una propiedad es un objeto, se pisa entera, no se mezcla:

```javascript
const base = { direccion: { calle: "Rivadavia 123", ciudad: "Tucumán" } };
const cambio = { direccion: { ciudad: "Salta" } };

{ ...base, ...cambio };
// { direccion: { ciudad: "Salta" } }, se perdió la calle
```

Para actualizar una propiedad anidada sin perder el resto, hay que propagar en cada nivel:

```javascript
const actualizado = {
  ...contacto,
  direccion: { ...contacto.direccion, ciudad: "Salta" },
};
```

Ese patrón es incómodo y por eso más adelante vamos a ver herramientas que lo simplifican. Por ahora, acordate de la regla: un nivel de propagación por cada nivel que quieras conservar.

## Desestructuración

Igual que con arreglos, pero por nombre en vez de por posición.

```javascript
const contacto = { nombre: "Ana", email: "ana@mail.com", edad: 30 };

const { nombre, email } = contacto;
// nombre = "Ana", email = "ana@mail.com"
```

El orden no importa y podés tomar solo lo que necesitás.

Para usar otro nombre de variable, con dos puntos:

```javascript
const { nombre: nombreContacto, email: correo } = contacto;
```

Valores por defecto para lo que falte:

```javascript
const { nombre, telefono = "sin teléfono" } = contacto;
```

El valor por defecto entra cuando la propiedad es `undefined`, no cuando es `null` ni cadena vacía.

Se puede combinar todo:

```javascript
const { nombre: n = "Anónimo", ciudad = "Tucumán" } = contacto;
```

Anidada, para llegar a propiedades internas:

```javascript
const contacto = {
  nombre: "Ana",
  direccion: { calle: "Rivadavia 123", ciudad: "Tucumán" },
};

const { direccion: { ciudad } } = contacto;
// ciudad = "Tucumán", y direccion no queda como variable
```

Cuidado con la desestructuración anidada: si `direccion` no existe, la línea falla. Poné un valor por defecto para el nivel intermedio:

```javascript
const { direccion: { ciudad } = {} } = contacto;
```

Y el resto, que junta lo que no nombraste:

```javascript
const { nombre, ...otrosDatos } = contacto;
// nombre = "Ana"
// otrosDatos = { email: ..., edad: ... }
```

Ese último uso sirve para sacar una propiedad de un objeto sin modificarlo, que es la versión inmutable de `delete`:

```javascript
const { password, ...contactoPublico } = usuario;
// contactoPublico tiene todo menos password, y usuario queda intacto
```

El lugar donde más se usa la desestructuración es en los parámetros de las funciones:

```javascript
// Sin desestructurar: hay que recordar el orden
function crearContacto(nombre, email, edad, activo) { /* ... */ }
crearContacto("Ana", "ana@mail.com", 30, true);

// Desestructurando: los argumentos se nombran
function crearContacto({ nombre, email, edad = 0, activo = true }) {
  return { nombre, email, edad, activo };
}

crearContacto({ email: "ana@mail.com", nombre: "Ana" });
```

La segunda versión no depende del orden, documenta qué recibe y permite valores por defecto. Es la forma habitual cuando una función tiene más de tres parámetros.

## Recorrer un objeto

Un objeto no es iterable, así que `for...of` no funciona directamente sobre él. Hay dos caminos.

El primero es `for...in`, que recorre las claves:

```javascript
for (const clave in contacto) {
  console.log(clave, contacto[clave]);
}
```

Tiene el mismo problema que `Object.hasOwn` resuelve: también recorre propiedades heredadas. Con objetos literales no pasa, pero con objetos que vienen de una clase o de una librería, sí.

El segundo camino, más recomendable, es convertir el objeto en un arreglo y recorrerlo con las herramientas que ya conocés:

```javascript
Object.keys(contacto);    // ["nombre", "email", "edad"]
Object.values(contacto);  // ["Ana", "ana@mail.com", 30]
Object.entries(contacto); // [["nombre","Ana"], ["email","ana@mail.com"], ...]
```

Con `entries` y desestructuración queda muy legible:

```javascript
for (const [clave, valor] of Object.entries(contacto)) {
  console.log(`${clave}: ${valor}`);
}
```

Y como son arreglos, podés encadenar métodos:

```javascript
// Quedarse con las propiedades que tienen valor
const limpio = Object.fromEntries(
  Object.entries(contacto).filter(([, valor]) => valor != null)
);

// Transformar todos los valores
const enMayusculas = Object.fromEntries(
  Object.entries(contacto).map(([k, v]) => [k, String(v).toUpperCase()])
);
```

`Object.fromEntries` es el camino inverso: de arreglo de pares a objeto.

Sobre el orden de las claves, hay una regla que conviene conocer. Las claves que parecen números enteros salen primero, ordenadas de menor a mayor. El resto sale en el orden en que las agregaste.

```javascript
const raro = { b: 1, 2: "dos", a: 3, 1: "uno" };
Object.keys(raro); // ["1", "2", "b", "a"]
```

Si el orden te importa, no uses un objeto: usá un arreglo o un [Map](034-map.md).

## Copiar y comparar

Vale lo mismo que para los arreglos, porque el mecanismo es el mismo: la variable guarda una referencia.

```javascript
const a = { nombre: "Ana" };
const b = a;

b.nombre = "Luis";
console.log(a.nombre); // "Luis", es el mismo objeto
```

Para copiar en forma superficial:

```javascript
const copia1 = { ...a };
const copia2 = Object.assign({}, a);   // forma anterior a la propagación
```

Las dos copian un solo nivel. Lo que esté anidado se sigue compartiendo:

```javascript
const original = { direccion: { ciudad: "Tucumán" } };
const copia = { ...original };

copia.direccion.ciudad = "Salta";
console.log(original.direccion.ciudad); // "Salta", el objeto interno es el mismo
```

Para una copia profunda, `structuredClone`:

```javascript
const copiaProfunda = structuredClone(original);
```

Copia objetos, arreglos, fechas, `Map` y `Set`. No copia funciones: si el objeto tiene métodos, falla.

Y la comparación funciona como con los arreglos: `===` compara referencias.

```javascript
{ a: 1 } === { a: 1 };  // false, son dos objetos distintos
```

Para comparar contenido hay que recorrer las claves, o comparar sus representaciones en texto si el caso es simple y el orden de las claves coincide.

## Congelar y proteger

```javascript
const config = Object.freeze({ pagina: 1, limite: 10 });

config.limite = 50;        // no hace nada, en modo estricto lanza error
Object.isFrozen(config);   // true
```

`Object.freeze` también es superficial: congela el objeto de afuera, no los objetos anidados.

## Objetos y JSON

Es la conversión que más vas a usar en toda la materia, porque es cómo viajan los datos por la red.

```javascript
JSON.stringify(contacto);  // objeto a texto
JSON.parse(texto);         // texto a objeto
```

`JSON.stringify` es también la forma de mostrar un objeto legible en consola, en vez del `[object Object]` que vimos la clase pasada:

```javascript
console.log(JSON.stringify(contacto, null, 2)); // con sangría de 2
```

Tiene pérdidas que conviene conocer desde ahora. Descarta las propiedades cuyo valor es `undefined` o una función. Convierte las fechas en texto, así que al volver con `parse` ya no son fechas. Y falla con referencias circulares.

```javascript
JSON.stringify({ a: undefined, b: () => 1, c: new Date() });
// {"c":"2026-08-15T..."}
```

## Errores frecuentes

Escribir `contacto.campo` cuando la clave está en la variable `campo`.

Creer que la propagación combina en profundidad. Pisa el nivel superior y listo.

Usar `for...in` sobre un arreglo. Para arreglos, `for...of`.

Preguntar `if (contacto.activo)` cuando la propiedad puede valer `0` o cadena vacía. Ahí conviene `if ("activo" in contacto)` o `!== undefined`.

Usar un objeto como diccionario con claves que vienen del usuario, sin `Object.hasOwn`. Una clave llamada `toString` o `constructor` da respuestas inesperadas.

Comparar dos objetos con `===` esperando comparar contenido.

## Para llevarte

- el objeto agrupa por nombre, y la clave siempre es texto
- el punto toma la clave literal; los corchetes evalúan la expresión
- pedir una propiedad inexistente devuelve `undefined`, pero pedirle una propiedad a `undefined` falla
- usá `?.` para atravesar estructuras que pueden estar incompletas
- `{ nombre }` es lo mismo que `{ nombre: nombre }`
- la propagación combina, respeta el orden y es superficial
- la desestructuración toma por nombre, admite renombrar, valores por defecto y resto
- `Object.keys`, `values` y `entries` convierten el objeto en arreglo para recorrerlo
- copiar es superficial salvo con `structuredClone`, y `===` compara referencias
- `JSON.stringify` pierde funciones, `undefined` y el tipo de las fechas
