# Map

Programación IV: Desarrollo Web — Etapa 1, fundamentos técnicos
Apunte de la tercera clase de JavaScript, 4 de 4

Un `Map` guarda pares de clave y valor, igual que un [objeto](032-objetos.md). La diferencia es para qué está pensado cada uno.

El objeto representa una entidad con propiedades conocidas de antemano: un contacto tiene nombre, email y edad. El `Map` representa un diccionario: claves que aparecen y desaparecen mientras el programa corre, y que no necesariamente son texto.

Los otros apuntes de esta clase son [arreglos](031-arreglos.md), [objetos](032-objetos.md) y [Set](033-set.md).

## Cómo se crea y se usa

```javascript
const contactosPorId = new Map();

contactosPorId.set(1, { nombre: "Ana" });
contactosPorId.set(2, { nombre: "Luis" });

contactosPorId.get(1);      // { nombre: "Ana" }
contactosPorId.get(99);     // undefined, no está
contactosPorId.has(2);      // true
contactosPorId.delete(2);   // true
contactosPorId.size;        // 1
contactosPorId.clear();
```

`set` devuelve el mismo `Map`, así que se puede encadenar:

```javascript
const config = new Map()
  .set("pagina", 1)
  .set("limite", 10);
```

Se puede crear desde un arreglo de pares, lo que lo conecta con `Object.entries`:

```javascript
const desdeArreglo = new Map([["a", 1], ["b", 2]]);
const desdeObjeto = new Map(Object.entries({ a: 1, b: 2 }));
const deVueltaAObjeto = Object.fromEntries(desdeObjeto);
```

## Las tres diferencias con el objeto

La primera es que la clave puede ser cualquier valor, no solo texto: números, booleanos, objetos, funciones.

```javascript
const m = new Map();
m.set(1, "número uno");
m.set("1", "texto uno");
m.get(1);    // "número uno", son claves distintas
```

En un objeto común, `obj[1]` y `obj["1"]` son la misma propiedad, porque las claves siempre se convierten a texto.

Usar un objeto como clave abre un uso que el objeto literal no permite: asociar datos a una entidad sin tocarla.

```javascript
const metadatos = new Map();
metadatos.set(contactoAna, { seleccionado: true });
metadatos.get(contactoAna);
```

La comparación de claves es la misma de `Set`, SameValueZero: como `===`, salvo que `NaN` funciona como clave y `0` y `-0` son la misma. Y los objetos se comparan por referencia, así que `m.get({id: 1})` nunca encuentra lo que guardaste con otro objeto de igual contenido.

La segunda diferencia es que `size` te da la cantidad directamente, sin tener que pedir `Object.keys().length`.

La tercera es que es iterable y conserva el orden de inserción, siempre, sin la regla rara de las claves numéricas del objeto.

## Cómo se recorre

```javascript
for (const [clave, valor] of contactosPorId) {
  console.log(clave, valor);
}

contactosPorId.forEach((valor, clave) => console.log(clave, valor));
```

Fijate que en `forEach` el valor viene primero y la clave después, al revés de lo que uno espera. Es una fuente clásica de confusión.

Tres métodos devuelven iteradores:

```javascript
contactosPorId.keys();     // iterador de claves
contactosPorId.values();   // iterador de valores
contactosPorId.entries();  // iterador de pares
```

Un iterador no es un arreglo: no tiene `map` ni `filter`. Para operar con las herramientas que ya conocés, convertilo:

```javascript
[...contactosPorId];            // [[1, {...}], [2, {...}]]
[...contactosPorId.keys()];     // [1, 2]
[...contactosPorId.values()];   // [{...}, {...}]

const activos = [...contactosPorId.values()].filter((c) => c.activo);
```

Y para transformar un `Map` en otro, el camino de ida y vuelta:

```javascript
const duplicados = new Map(
  [...precios].map(([clave, valor]) => [clave, valor * 2])
);
```

## Patrones habituales

Indexar una lista para poder buscar rápido. Es el uso más frecuente:

```javascript
const contactos = [
  { id: 1, nombre: "Ana" },
  { id: 2, nombre: "Luis" },
];

const indice = new Map(contactos.map((c) => [c.id, c]));

indice.get(2); // acceso directo, sin recorrer el arreglo
```

Si vas a buscar una sola vez, `find` alcanza. Si vas a buscar muchas veces, armar el índice una vez y consultarlo es mucho más rápido, por la misma razón que vimos con [Set](033-set.md).

Contar frecuencias:

```javascript
const conteo = new Map();

for (const palabra of palabras) {
  conteo.set(palabra, (conteo.get(palabra) ?? 0) + 1);
}
```

Ese `?? 0` cubre la primera vez, cuando `get` devuelve `undefined`. Es el patrón que hay que reconocer en todo acumulador con `Map`.

Agrupar por una propiedad:

```javascript
const porCiudad = new Map();

for (const c of contactos) {
  if (!porCiudad.has(c.ciudad)) porCiudad.set(c.ciudad, []);
  porCiudad.get(c.ciudad).push(c);
}
```

Desde 2024 hay una función que lo hace directamente:

```javascript
const porCiudad = Map.groupBy(contactos, (c) => c.ciudad);
```

Existe también `Object.groupBy`, que devuelve un objeto en vez de un `Map`. Usá la versión con `Map` cuando las claves puedan no ser texto o cuando te importe el orden.

Guardar resultados ya calculados, para no repetir el trabajo:

```javascript
const cache = new Map();

function traerContacto(id) {
  if (cache.has(id)) return cache.get(id);
  const contacto = buscarEnLaBase(id);
  cache.set(id, contacto);
  return contacto;
}
```

## Objeto o Map

| | Objeto | Map |
|---|---|---|
| Claves | texto y símbolos | cualquier valor |
| Cantidad | `Object.keys().length` | `.size` |
| Orden | números primero, después inserción | inserción siempre |
| Iterable | no, hay que convertirlo | sí |
| Se convierte a JSON | sí | no directamente |
| Altas y bajas frecuentes | más lento | más rápido |
| Claves heredadas | sí, cuidado con `toString` | no, está limpio |
| Sintaxis | `obj.clave`, breve | `map.get(clave)`, más larga |

La regla práctica: usá un objeto cuando represente una entidad con propiedades conocidas, como un contacto. Usá un `Map` cuando sea un diccionario con claves que cambian durante la ejecución.

Hay una razón más para preferir `Map` como diccionario. Un objeto hereda propiedades que pueden confundirse con datos:

```javascript
const dic = {};
dic["toString"];        // una función, aunque nunca la guardaste

const m = new Map();
m.get("toString");      // undefined, como corresponde
```

## Map y JSON

Un `Map` no se serializa solo:

```javascript
JSON.stringify(new Map([["a", 1]]));  // "{}", se pierde todo
```

Hay que convertirlo antes, y reconstruirlo al recibirlo:

```javascript
const texto = JSON.stringify([...miMapa]);       // arreglo de pares
const recuperado = new Map(JSON.parse(texto));
```

Si las claves son texto, la otra opción es pasar por objeto:

```javascript
JSON.stringify(Object.fromEntries(miMapa));
```

Esta es la razón principal por la que los datos que van y vienen de una API se manejan como objetos, y el `Map` queda para el trabajo interno del programa.

## Map y WeakMap

`WeakMap` es una variante donde las claves solo pueden ser objetos y no impiden que el recolector de basura los libere. No es iterable y no tiene `size`.

Sirve para asociar datos a un objeto mientras ese objeto viva, sin provocar pérdidas de memoria. Es lo que usan varias librerías para guardar estado privado de un componente. Alcanza con saber que existe.

## Errores frecuentes

Usar corchetes en vez de `get` y `set`:

```javascript
const m = new Map();
m["clave"] = 1;    // no da error, pero no usa el Map
m.get("clave");    // undefined
m.size;            // 0
```

Lo que hiciste fue agregarle una propiedad común al objeto `Map`. El `Map` sigue vacío.

Buscar con un objeto distinto del que guardaste. Las claves objeto se comparan por referencia.

Esperar que `JSON.stringify` conserve el contenido.

Invertir el orden de los parámetros en `forEach`: primero llega el valor.

Olvidar el valor por defecto al acumular: `conteo.get(x) + 1` da `NaN` la primera vez.

## Para llevarte

- `Map` es el diccionario: clave a valor, con claves de cualquier tipo
- la interfaz es `set`, `get`, `has`, `delete`, `clear` y `size`
- compara claves con SameValueZero, y los objetos por referencia
- es iterable y conserva el orden de inserción
- se crea desde un arreglo de pares, y `Object.entries` y `Object.fromEntries` son el puente con el objeto
- indexar una lista con `new Map(lista.map(x => [x.id, x]))` convierte cada búsqueda en un acceso directo
- para contar y agrupar, el patrón es `map.get(k) ?? valorInicial`
- `Map.groupBy` resuelve el agrupamiento en una línea
- no se serializa a JSON: convertilo a arreglo de pares o a objeto
- usá objeto para entidades, `Map` para diccionarios dinámicos
