Fundamento

Código y configuración son cosas distintas

El archivo .mjs indica que usamos módulos de JavaScript, con import y await en el nivel superior. .env contiene valores que pueden cambiar sin modificar la lógica. La clave queda fuera del código; si usás Git, agregá .env a .gitignore.

Los siguientes fragmentos se agregan a app.mjs en este orden. Al final tenés el archivo completo, listo para descargar.

01

Los módulos nativos

Usar lo que Node ya trae

Primero importamos las cuatro capacidades que necesitamos: cargar configuración, trabajar con archivos leer la terminal y dar estilo al texto.

node:process
Ofrece loadEnvFile para cargar .env en las variables de entorno del proceso.
node:fs/promises
Provee operaciones de archivos que devuelven promesas.
node:readline/promises
Permite preguntar por una línea de texto y esperar la respuesta.
node:util
Ofrece styleText para dar color y formato a los textos de la terminal.
Fundamento

Una promesa representa un resultado pendiente

Leer un archivo o pedir una respuesta al usuario lleva tiempo. async permite que una función use await; await suspende esa ejecución hasta obtener el resultado. El entorno puede seguir atendiendo otras tareas mientras espera.

02

Presentación con styleText

Dar color a la terminal

La interfaz usa color para distinguir quién está hablando y qué está haciendo el programa. Usamos styleText, una función nativa de node:util. Recibe primero el estilo y después el texto, y devuelve una cadena lista para mostrar.

styleText("yellow", texto) aplica amarillo. styleText(["bold", "cyan"], texto) combina negrita y cian. El estilo puede ser un nombre o un arreglo de nombres. La función genera las secuencias ANSI y restablece el formato al terminar el texto.

Referencia: Node.js · styleText. Es estable desde Node.js 22.13.

Cian
Identifica el encabezado del asistente.
Violeta
Destaca el prompt donde escribís tu mensaje.
Verde
Identifica la respuesta y confirma una herramienta completada.
Amarillo y gris
El amarillo marca las herramientas; el gris separa los estados de espera y la información secundaria.
Fundamento

El color cambia la presentación, no el contenido

styleText devuelve una cadena. Los mensajes enviados a OpenAI y los resultados de las herramientas conservan sus textos originales. styleText comprueba por defecto si la salida admite color y respeta variables como NO_COLOR. Así la función nativa también decide cuándo devolver texto plano; no necesitamos controles propios.

03

Funciones que hacen trabajo real

Implementar las dos herramientas

Antes de conectar el modelo, escribimos las operaciones locales. Cada función recibe un objeto con sus argumentos y devuelve un texto.

{ ruta } extrae la propiedad ruta del objeto recibido. Es la desestructuración de JavaScript. Escribir leerArchivo({ ruta: "saludo.js" }) entrega ese objeto a la función.

"utf8" indica que trabajamos con texto. readFile devuelve el contenido; writeFile crea el archivo o reemplaza todo lo que tenía. Esperamos a que termine antes de devolver "Archivo guardado.".

Fundamento

Las herramientas son funciones normales

Estas funciones funcionan por sí solas. Más adelante, nuestro programa decidirá cuál invocar usando el nombre que devuelva el modelo. Las rutas relativas se resuelven desde la carpeta donde ejecutás el comando, y la carpeta de destino debe existir.

Variante para HTML

La clave en el navegador

En los ejemplos HTML, usamos obtenerApiKey() en lugar de leer una variable de entorno. Primero busca OPENAI_API_KEY en localStorage; si falta, la solicita con prompt, quita los espacios de los extremos y la guarda. Si cancelás o dejás el campo vacío, detiene la consulta sin guardar nada.

La función se llama al enviar la consulta, no al abrir la página. Los ejemplos comparten la clave cuando se sirven desde el mismo origen (protocolo, host y puerto), según localStorage en MDN. Para cambiarla, ejecutá localStorage.removeItem("OPENAI_API_KEY") en la consola del navegador y volvé a consultar. El programa de terminal de este tutorial conserva su configuración con .env.

Traducir una solicitud en una llamada

El objeto funciones asocia nombres con referencias a funciones. funciones["leerArchivo"] devuelve la función leerArchivo; los paréntesis posteriores la invocan.

La petición a OpenAI devuelve datos. La lectura o escritura ocurre en el proceso de Node cuando llamamos a una función local. Así podemos señalar exactamente dónde se produce cada acción.

08

El estado de la conversación

Preparar la consola y el historial

Con las funciones definidas, comienza la ejecución del programa. Cargamos la configuración, abrimos la entrada de consola y creamos un arreglo de mensajes.

process.stdin recibe la entrada de la terminal y process.stdout muestra la salida. El objeto consola nos permitirá esperar una línea con question.

El historial es la memoria que enviamos

Cada petición lleva el arreglo mensajes completo. Agregamos elementos con push para que el modelo reciba el contexto anterior. const impide reasignar el arreglo, pero permite modificar su contenido. Esta memoria dura mientras corre el proceso.

09

El bucle exterior

Repetir la conversación

La aplicación sigue pidiendo mensajes hasta que la persona escribe salir. Esta es la estructura del bucle exterior; en el próximo paso completamos el procesamiento.

while (true) repite el cuerpo indefinidamente. question espera la entrada y devuelve el texto. break abandona el bucle cuando se cumple la condición de salida. Si seguimos, guardamos el mensaje con rol user.

Fundamento

Esperar entrada evita un bucle que consume CPU

Aunque la condición sea siempre verdadera, la ejecución se suspende en await consola.question(...) hasta recibir una línea. Cada vuelta representa un turno nuevo de la persona. El prompt usa styleText para mostrar la etiqueta en violeta y negrita.

10

El bucle interior

Procesar texto o herramientas

Un turno puede necesitar varias llamadas al modelo. Por ejemplo: leer un archivo, usar su contenido para decidir un cambio, escribirlo y confirmar el resultado. Por eso agregamos un segundo bucle dentro del anterior.

  1. Consultar y guardar. Llamamos a invocarOpenAI y agregamos el mensaje completo al historial, incluidas sus solicitudes de herramientas.
  2. Si terminó, mostrar. mensaje.tool_calls?.length consulta la cantidad de llamadas si la propiedad existe. Si no hay llamadas, mostramos content y salimos del bucle interior.
  3. Si pidió acciones, ejecutarlas. El for...of recorre cada llamada. Las ejecutamos una a una y guardamos cada resultado.
  4. Volver a consultar. Después del for, empieza otra vuelta: el modelo recibe los resultados y puede responder o solicitar más herramientas.
Fundamento

Cada resultado tiene que identificar su solicitud

El mensaje tool usa tool_call_id: llamada.id para asociar el resultado con la llamada original. content contiene el texto devuelto por nuestra función. Guardamos todas las solicitudes y sus resultados antes de la siguiente consulta.

El break interior vuelve a la pregunta de consola. El break exterior termina la conversación. Cada uno abandona el bucle más cercano.

Para discutir en clase

Comprobá lo que entendiste.

¿Por qué necesitamos dos bucles?

El exterior recibe nuevos mensajes de la persona. El interior resuelve un mensaje mediante las consultas y llamadas a herramientas que hagan falta. Una respuesta de texto termina el interior; escribir salir termina el exterior.

¿Quién escribe realmente el archivo?

La función escribirArchivo ejecutada por Node. El modelo devuelve una solicitud con un nombre y argumentos. ejecutarHerramienta transforma esa solicitud en una invocación local.

¿Qué pasa si no guardamos el resultado de una herramienta?

La siguiente consulta no incluye lo que devolvió la función. Además, el protocolo espera un resultado asociado a cada llamada. Conservamos la solicitud del asistente y cada mensaje tool con su tool_call_id.

¿Dónde está la memoria de la conversación?

En el arreglo mensajes del proceso de Node. Lo enviamos de nuevo en cada petición. Al cerrar el programa se pierde; esta implementación no guarda sesiones en disco.

¿Podría agregar una tercera herramienta?

Sí. Implementá una función que reciba un objeto y devuelva texto, agregá su descripción al arreglo herramientas y su referencia al objeto funciones. El bucle puede procesar su solicitud con el mismo mecanismo.
