La idea que hay detrás de React

pantalla = f(estado)

  • Escribimos funciones que describen la pantalla.
  • Cuando el estado cambia, React las vuelve a llamar.
  • Nunca tocamos el DOM a mano.

Vamos a construir cuatro piezas

PiezaPara qué sirve
createElementDescribir la interfaz sin JSX
renderDibujar la app en la página
useStateDarle memoria a un componente
useEffectHacer cosas después de dibujar

La regla del juego

Cada cambio: tirar la pantalla entera y construirla de nuevo.

  • Sin DOM virtual.
  • Sin comparar lo viejo con lo nuevo.
  • Así el mecanismo queda a la vista.

createElement, versión 1

function createElement(tipo, props, ...hijos) {
  props = props ?? {};
  const elemento = document.createElement(tipo);

  for (const [nombre, valor] of Object.entries(props)) {
    asignarPropiedad(elemento, nombre, valor);
  }

  for (const hijo of hijos.flat(Infinity)) {
    if (hijo === null || hijo === undefined
        || typeof hijo === "boolean") continue;
    elemento.append(hijo instanceof Node
      ? hijo
      : String(hijo));
  }
  return elemento;
}

Las props

function asignarPropiedad(elemento, nombre, valor) {
  if (nombre.startsWith("on")) {
    const evento = nombre.slice(2).toLowerCase();
    elemento.addEventListener(evento, valor);
  } else if (nombre === "className") {
    elemento.className = valor;
  } else if (nombre === "style") {
    Object.assign(elemento.style, valor);
  } else if (typeof valor === "boolean") {
    elemento.toggleAttribute(nombre, valor);
  } else if (valor !== null && valor !== undefined) {
    elemento.setAttribute(nombre, valor);
  }
}

Nivel 3

Dibujar y volver a dibujar

¿Cómo cambia la pantalla?

render

function render(componente, contenedor) {
  contenedor.replaceChildren(h(componente));
}
  • replaceChildren borra todo y pone el árbol nuevo.
  • Volver a dibujar es llamar a render otra vez.

Un contador con una variable global

let clics = 0;

function App() {
  return h("button", {
    onClick: () => {
      clics++;
      render(App, raiz);    // ¡hay que acordarse!
    },
  }, `Clics: ${clics}`);

Funciona, pero tiene dos problemas

  1. El dato vive afuera del componente: tres contadores necesitan tres variables globales.
  2. Hay que acordarse de redibujar después de cada cambio.

useState resuelve las dos cosas.

Nivel 4

useState

¿Dónde guarda un componente sus datos?

El problema

  • Un componente es una función.
  • Sus variables locales mueren cuando termina.
  • Los tres contadores son la misma función.

¿Cómo sabe el framework qué cuenta es de quién?

La respuesta: por la posición

  • En cada dibujo, los componentes se ejecutan siempre en el mismo orden.
  • Dentro de cada uno, los useState también.
  • El framework guarda los valores en un arreglo y los reparte en orden, como números en una fila.

useState → hooks[0], hooks[1]…

useState, versión 1

const hooks = [];   // la memoria: sobrevive entre dibujos
let indice = 0;     // la próxima ranura a entregar

function useState(valorInicial) {
  const i = indice++;
  if (hooks[i] === undefined) {
    hooks[i] = { valor: valorInicial };  // primera vez
  }
  const ranura = hooks[i];

  function setValor(nuevoValor) {
    ranura.valor = nuevoValor;
    renderizar();                        // se redibuja solo
  }
  return [ranura.valor, setValor];
}

renderizar, versión 1

function renderizar() {
  indice = 0;   // cada dibujo reparte desde cero
  contenedor.replaceChildren(h(componenteRaiz));
}

Si no volvemos indice a cero, el segundo dibujo pediría ranuras nuevas y todo arrancaría vacío.

Usarlo

function Contador({ nombre }) {
  const [cantidad, setCantidad] = useState(0);

  return h("section", null,
    h("h2", null, nombre),
    h("p", null, cantidad),
    h("button", {
      onClick: () => setCantidad(cantidad + 1),
    }, "+1"),
  );
}

Dos detalles

  • El valor inicial se usa una sola vez, cuando la ranura no existe. Después, useState(0) ignora el 0.
  • setValor es una clausura: recuerda su ranura. Por eso cada botón cambia la cuenta correcta.

La regla de los hooks

Siempre, en el mismo orden, en el nivel superior del componente.

  • Nunca dentro de un if.
  • Nunca dentro de un bucle.
  • Nunca después de un return temprano.

¿Qué pasa si la rompemos?

function Contador({ conHistorial }) {
  const [cantidad, setCantidad] = useState(0);  // 1.º
  if (conHistorial) {
    const [lista, setLista] = useState([]);     // 2.º… a veces
  }
  useEffect(/* … */);                           // ¿3.º o 2.º?
}

Si conHistorial cambia, todo lo que sigue queda corrido: cada hook lee la ranura de otro.

Nivel 6

useEffect

¿Dónde arrancamos el reloj?

Dibujar no es lo único

  • Un componente debería limitarse a calcular la pantalla.
  • Si arranca un reloj adentro, lo arranca en cada dibujo: uno por segundo.
  • Relojes, pedir datos, reaccionar a un cambio: son efectos secundarios.

Las tres partes de un efecto

useEffect(() => {
  // 1. el efecto: corre DESPUÉS de dibujar

  return () => {
    // 3. la limpieza: deshace el efecto
  };
}, [dependencias]);   // 2. cuándo volver a correrlo

Las dependencias

LlamadaCuándo corre
useEffect(f)Después de cada dibujo
useEffect(f, [])Solo después del primero
useEffect(f, [a, b])En el primero y cuando cambia a o b

Un efecto también ocupa una ranura

  • Guarda las dependencias del dibujo anterior, para saber si cambiaron.
  • Guarda la limpieza que devolvió, para ejecutarla antes de la próxima vez.
// la ranura del reloj, mientras se cuenta
{
  tipo: "efecto",
  dependencias: [true],
  limpieza: () => clearInterval(id),
}

useEffect por dentro

function useEffect(efecto, dependencias) {
  const i = indice++;
  const primeraVez = hooks[i] === undefined;
  if (primeraVez) hooks[i] = { tipo: "efecto" };
  const ranura = hooks[i];

  const cambiaron = primeraVez
    || dependencias === undefined
    || dependencias.some((d, k) =>
         !Object.is(d, ranura.dependencias[k]));

  if (cambiaron) {
    ranura.dependencias = dependencias;
    // se anota para después: ¡no se ejecuta acá!
    efectosPendientes.push({ ranura, efecto });
  }
}

renderizar, versión final

function renderizar() {
  renderPendiente = false;
  indice = 0;

  const arbol = h(componenteRaiz);       // 1. componentes
  contenedor.replaceChildren(arbol);     // 2. pantalla nueva

  for (const { ranura, efecto } of efectosPendientes) {
    if (typeof ranura.limpieza === "function") {
      ranura.limpieza();
    }
    ranura.limpieza = efecto();          // 3. efectos
  }
  efectosPendientes = [];
}

Ejemplo: el reloj

useEffect(() => {
  if (!corriendo) return;

  const id = setInterval(() => {
    setAhora(Date.now());
  }, 1000);

  return () => clearInterval(id);
}, [corriendo]);

El reloj, paso a paso

  1. corriendo es false: corre y sale sin hacer nada.
  2. ▶: pasa a true, cambió, arranca el intervalo.
  3. Cada segundo: setAhora, dibujo, corriendo sigue igual, el intervalo sigue.
  4. ⏹: vuelve a false, primero clearInterval, después el efecto.

Sin limpieza, cada inicio sumaría otro intervalo.

¿Hace falta guardar la hora actual?

  • Los segundos se podrían calcular con Date.now() al dibujar.
  • Pero el framework solo dibuja cuando cambia un estado.
  • Sin un estado que cambie, el reloj queda congelado.

ahora es el único dato que cambia solo. Y con el mismo estado, siempre la misma pantalla.

Ejemplo: volver a cero

useEffect(() => {
  if (habilitado) setCantidad(0);
}, [habilitado]);
  • El padre no puede tocar el estado del hijo.
  • El hijo reacciona a una prop: al pasar a habilitado, vuelve a cero.
  • Si ya estaba en cero, Object.is(0, 0) evita un dibujo inútil.

Hasta dónde llega reconstruir todo

¿Qué problema resuelve el DOM virtual?

El costo

  • Con el reloj andando, se crean unos cincuenta nodos por segundo.
  • Para cincuenta nodos, no se nota.
  • Para una tabla de cinco mil filas, sí.

Se pierde lo que el DOM recuerda

  • Un nodo recuerda cosas que no están en el estado: el foco, el cursor, el desplazamiento, una animación.
  • Un <input> perdería el foco con cada tecla… y con cada segundo del reloj.

React reconcilia: compara y cambia solo los nodos que cambiaron.

El estado atado a la posición

  • Si los contadores se reordenan, las cuentas quedan cruzadas.
  • React identifica cada componente por tipo, lugar y key.
  • Acá nunca se desmonta nada: si algo desapareciera, su limpieza no correría.

Otra forma: levantar el estado

function App() {
  const [conteos, setConteos] = useState({
    Motos: 0, Autos: 0, Camionetas: 0,
  });

  function registrarVehiculo(nombre) {
    setConteos((c) => ({ ...c, [nombre]: c[nombre] + 1 }));
  }

  // el total se calcula: no puede desincronizarse
  const total = Object.values(conteos)
    .reduce((a, b) => a + b, 0);
  // …
}

¿Qué cambia?

  • El total ya no se guarda dos veces: se calcula.
  • Reiniciar es asignar ceros: no hace falta el efecto en los hijos.
  • A cambio, los contadores pierden autonomía: reciben su cantidad por props.

¿Quién necesita el dato?

  • Si lo usa un solo componente, que lo guarde él.
  • Si lo usan varios, se guarda en el ancestro común más cercano y se reparte por props.

Acá duplicamos a propósito, para ver cómo un hijo le avisa al padre.

Funciones para mostrar el tiempo y el flujo

function formatearDuracion(segundos) {
  const horas = String(Math.floor(segundos / 3600)).padStart(2, "0");
  const minutos = String(Math.floor((segundos % 3600) / 60)).padStart(2, "0");
  const resto = String(segundos % 60).padStart(2, "0");
  return `${horas}:${minutos}:${resto}`;
}

function calcularFlujo(cantidad, segundos) {
  if (segundos === 0) return "—";
  return `${Math.round((cantidad * 3600) / segundos)} v/h`;
}

Cada contador guarda y cambia su número

function crearContador(elemento, alRegistrar) {
  const textoCantidad = elemento.querySelector(".cantidad");
  let cantidad = 0;

  elemento.addEventListener("click", () => {
    cantidad++;
    textoCantidad.textContent = cantidad;
    alRegistrar();
  });

  return {
    habilitar(habilitado) { elemento.disabled = !habilitado; },
    reiniciar() { cantidad = 0; textoCantidad.textContent = 0; },
  };
}

La aplicación actualiza los nodos directamente

const contadores = [...document.querySelectorAll(".contador")]
  .map((elemento) => crearContador(elemento, registrarVehiculo));

function segundosTranscurridos() {
  return inicio === null ? 0 : Math.floor((Date.now() - inicio) / 1000);
}

function actualizarTiempo() {
  const segundos = segundosTranscurridos();
  cronometro.textContent = formatearDuracion(segundos);
  textoFlujo.textContent = calcularFlujo(total, segundos);
}

function registrarVehiculo() {
  total++;
  textoTotal.textContent = total;
  textoFlujo.textContent = calcularFlujo(total, segundosTranscurridos());
}

Iniciar reinicia y habilita los contadores

function iniciar() {
  inicio = Date.now();
  total = 0;
  textoTotal.textContent = 0;

  for (const contador of contadores) {
    contador.reiniciar();
    contador.habilitar(true);
  }

  boton.textContent = "⏹";
  boton.title = "Detener";
  reloj = setInterval(actualizarTiempo, 1000);
  actualizarTiempo();
}

Detener limpia el reloj y escucha el clic

function detener() {
  clearInterval(reloj);
  inicio = null;

  for (const contador of contadores) contador.habilitar(false);

  boton.textContent = "▶";
  boton.title = "Iniciar";
  actualizarTiempo();
}

boton.addEventListener("click", () =>
  (inicio === null ? iniciar() : detener())

El contador declara su estado con useState

function Contador({ nombre, habilitado, alRegistrar }) {
  const [cantidad, setCantidad] = useState(0);

  useEffect(() => {
    if (habilitado) setCantidad(0);
  }, [habilitado]);

  function registrar() {
    setCantidad((c) => c + 1);
    alRegistrar();
  }

  return (
    <button disabled={!habilitado} onClick={registrar}>
      <span>{nombre}</span>
      <span>{cantidad}</span>
    </button>
  );
}

App (1/3): estado y efecto

function App() {
  const [inicio, setInicio] = useState(null);
  const [ahora, setAhora] = useState(Date.now());
  const [total, setTotal] = useState(0);

  const corriendo = inicio !== null;
  const segundos = corriendo
    ? Math.floor((ahora - inicio) / 1000)
    : 0;

  useEffect(() => {
    if (!corriendo) return;
    const id = setInterval(() => setAhora(Date.now()), 1000);
    return () => clearInterval(id);
  }, [corriendo]);
